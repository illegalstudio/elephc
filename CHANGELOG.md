# Changelog

All notable changes to elephc, a PHP-to-native compiler written in Rust.
Releases are listed newest first.

## [Unreleased]
- Fixed `array_merge()` refusing to compile for STRING arrays, empty-literal mixes included; unlike the set operations there is no key divergence, because php reindexes list keys on merge.
- Fixed `array_diff()` and `array_intersect()` refusing to compile for STRING arrays — `array_diff(scandir($d), [".", ".."])`, the most ordinary directory idiom in PHP, now works. One parameterised string helper serves both operations through `__rt_str_eq`; values are php-identical, keys stay reindexed where php preserves them (the set-operation family's pre-existing divergence, tracked).
- Fixed `array_reverse()` refusing to compile for STRING arrays — plain literals included: string slots are 16-byte (ptr, len) descriptors and the shared 8-byte element gate refused them since it existed. A dedicated string variant re-persists each element into the new array. The rest of the same family (array_unique, array_diff, array_merge, array_flip, array_slice, shuffle, natsort on string arrays) remains refused and tracked; the gate stays authoritative there because their 8-byte helpers would read a descriptor as two unrelated words.
- Fixed a NESTED literal `php://filter` URL being refused where php recurses — the inner level's chain applies first, measured through double and triple nesting. Conflicting explicit directions across levels stay loudly refused, and the assembled spelling's non-recursion stays a pinned, tracked divergence.
- Fixed a resourceless `php://filter` URL answering false where php throws `Error: No URL resource specified` — a throw `@` does not soften, uncaught fatal, on `fopen()` and every filter-routed reader and writer, literal and assembled spellings alike. The run-time parse gains a third verdict for "filter URL naming no resource" and the call sites throw; a NESTED filter resource still pins the known divergence (php recurses, elephc refuses loudly).
- Fixed `file()` answering an empty array where php answers `false` for a file it cannot read (an EMPTY file still answers `[]`), and widened `glob()` to its real `array|false` signature. Both ride the scandir machinery: the same union, the same argument unbox-or-throw in the consumers, the same sole-owner boxing — factored into one shared helper — and the eval interpreter's `file()` agrees on both of its failure branches.
- Fixed `scandir()` answering an empty listing where php answers `false`, never sorting where php sorts, and the array-taking family refusing to compile against its real signature. The declaration flips to `array|false` with the four-authority alignment the `fgetcsv` flip established; `scandir($d) === false` finally fires and `count()` on the failure raises php's TypeError. The listing is sorted ascending by default, descending for `SCANDIR_SORT_DESCENDING`, readdir order for `SCANDIR_SORT_NONE` — the `$sorting_order` parameter and the three constants are new. Twenty array-taking builtins (in_array, sort, array_map, array_filter, array_search, array_values…) accept the union through one choke point: the argument lowering unboxes it — throwing php's exact TypeError for a runtime `false` — so the consumers' own lowerings are untouched. Two ownership defects found by probing are fixed and pinned: the unbox must be borrowed (an owned unbox let a consumer's argument-release free the listing under the box) and the box must be its listing's sole owner (a retained-twice listing made `sort($d)`'s copy-on-write split sort a copy while the box kept the original).
- Added `php://filter` support to `readfile()` and `file()`, both spellings. `readfile()` answered false and `file()` an empty array where php streams the filtered bytes. The run-time route `file_get_contents` ships is now parameterised by the caller's warning prefix, so one implementation serves all three readers; `file()` gains a split-only second runtime entry (`__rt_file_from_bytes`) because its ordinary entry performs its own read, and `$flags` applies to filtered bytes exactly as to plain ones.
- Added `php://filter/write=...` support to `file_put_contents()`. The URL reached the one-shot writer as a filename; the route now opens the RESOURCE, attaches the write chain, writes through it and closes, answering the input byte count as php does. One run-time probe serves the literal and the assembled spelling alike; `rot13|toupper` chain order, FILE_APPEND appending THROUGH the filter, and the failure warning naming `file_put_contents` and the whole URL with `operation failed` are all measured byte-identical against `php -n` 8.5.6.
- Fixed `file_put_contents()` writing the payload through a garbage descriptor when the path cannot be opened. The open result was never checked, on either architecture; on macOS a failed open answers the ERRNO with the carry set, so `file_put_contents("/no/such/dir/x.txt", $secret)` wrote the secret through descriptor 2 — the caller's own stderr — and returned the byte count as a success. php warns and answers false, and elephc now does both, through the platform's own error convention on each half. The declaration flips from `Int` to `int|false` with the same four-authority alignment the `fgetcsv` flip established (`returns:`, check hook, lowering boxing, eval interpreter — the last already answered false), because with `Int` the manual's own `=== false` failure test could never fire.
- Fixed `file_get_contents()` never consulting the run-time `php://filter` parser. A URL assembled at run time was treated as a filename: the plain byte reader never creates a stream, so a filter chain had nowhere to attach, and the read failed loudly naming the whole URL as a path — while `fopen()` on the same URL worked. The route now mirrors the dynamic `fopen()` shape: the parse publishes the filter list and swaps the path to the RESOURCE, the resource is opened read-only through the same runtime openers `fopen()` dispatches to (php://, data://, http://, plain file), the parked chain is attached once the stream is boxed, and the bytes come back through the shared open-read-close tail. Six behaviors measured byte-identical against `php -n` 8.5.6, including the failure wording: php names `file_get_contents` and the WHOLE URL with the wrapper's generic `operation failed`, so the inner opener's warning is suppressed through the same depth counter `@` uses and the php-worded line is composed once the outcome is known — on the literal spelling too, which the new test caught leaking `fopen(<resource>)` because a concat of two literals is folded at compile time and takes the literal path.
- Added the two warnings PHP prints for a directory `scandir()` cannot open. `scandir("/no/such")` answered an empty listing in complete silence, so a typo'd path produced a `foreach` that did nothing and no clue why; php-src writes `scandir(/no/such): Failed to open directory: No such file or directory` and then `scandir(): (errno 2): No such file or directory`. Neither line needed a composer of its own — `__rt_errno_warning` already appends `strerror` and the newline, so it serves as the tail of both and only the beginning differs, which is what made this small. The error number goes through `__rt_itoa`, which formats into the shared 64 KiB concat arena and advances its cursor, so the diagnostic hands its scratch back; a loop over unreadable paths would otherwise eat the buffer a few bytes at a time. `@` suppresses both lines. The return value is unchanged and still diverges: PHP answers `false` where elephc answers an empty array, which is the `array|false` family blocked on the twenty-odd array builtins whose check hooks refuse a union — the warnings are an independent divergence and fixing them turns a mute failure into a diagnosed one.
- Fixed `fputcsv()` segfaulting on x86_64 for every field array that is not already strings — an int row, a float row, a bool row, a boxed row and a `foreach` row all crashed, while the same programs were correct on aarch64. The runtime's helpers do not share one calling convention on x86_64: `__rt_fd_write` takes rdi/rsi/rdx like any SysV function, but `__rt_mixed_cast_string` reads `rax`, because it opens by falling into `__rt_mixed_unbox`, whose input register that is — `__rt_heap_free` is the same. The CSV writer staged its cell pointer in `rdi`, which assembled, linked and ran, and handed the unboxer whatever the previous `__rt_fd_write` had returned: a byte count, dereferenced as a pointer. A row of strings never reaches the cast, which is why the string layout passed and every other one did not. AArch64 uses one convention for both helpers, so the identical code was correct there. `implode()` had always staged this cast in `rax` and is the reference caller.
- Fixed `fseek()` and `rewind()` on a userspace-wrapper stream leaving `ftell()` reporting where the reads had stopped. php-src reconciles the position it keeps for such a stream after every seek — that is the one place `main/streams/userspace.c` calls `stream_tell` — and elephc did too, on exactly one of the three code paths that need it. `fseek()` had the reconciliation on aarch64 and not on x86_64, so the same program answered `3` on one architecture and `7` on the other; `rewind()` had it on NEITHER, and `php -n` answers `wrapped|7|0|wrap|4` where elephc answered `wrapped|7|7|wrap|11`. In every case the wrapper's own position was set correctly, so the bytes a following read returned were right and only the number `ftell()` reported was wrong — which is how the `rewind()` half sat undetected behind the `fseek()` test. Both halves of both builtins now reconcile. Still narrower than php: the reconciliation uses the requested offset rather than asking the wrapper where it landed, so a `SEEK_CUR` or `SEEK_END` seek reports the offset rather than the resulting position.
- Fixed `__rt_heap_free` on x86_64 reading a candidate's header before bounding it. Callers are invited by contract to hand the helper a pointer that is not a heap block — `__rt_fputcsv` does it for every non-string field, because `__rt_mixed_cast_string` renders an int, a float or a bool into the shared concat arena and returns a pointer into that. aarch64 implements the contract by bounding the pointer against the heap first; x86_64 implemented it by reading the kind word at `[rax - 8]` and comparing the marker, so a foreign pointer was dereferenced outside the heap in order to decide it was foreign, and it takes only those eight neighbouring bytes carrying the marker for arena storage to be threaded onto the free list. The range check did exist on x86_64, but only inside the heap-debug block, which is off in every ordinary run.
- Fixed a `php://filter` URL built at RUN TIME applying only its first filter. `fopen($p, "r")` where `$p` names `read=string.toupper|string.rot13` returned the uppercased bytes and said nothing — plausible output, no diagnostic, and wrong. The literal spelling of the same URL was always right, which is why every existing test stayed green: it resolves the whole `|` chain during lowering, and only a URL assembled at run time reaches the parser that stopped at the first separator. That parser handed the attach a single filter id through one word of BSS, so the shape of the hand-off, not the scan, was the limit. It now publishes a LIST and the attach walks it, creating and linking each filter in the order the URL spelled them — `__rt_stream_filter_link` appends at the tail, so list order is chain order. An unrecognised name is skipped and its neighbours still apply, and a chain of nothing but unknown names opens the resource unfiltered; both readings are measured against `php -n` 8.5.6 rather than reasoned about, because the opposite reading is just as plausible. Elephc bounds a run-time chain at 32 filters, which php-src does not; the literal path, which is what real code takes, has no bound. Still open and tracked: `file_get_contents()` on a run-time filter URL never consults the parser at all and reports `Failed to open stream` — wrong, but loudly so.
- Fixed an `eval()`'d open failure naming neither the file nor the reason. The compiled path already reported both; the eval interpreter has a warning emitter of its own and was left behind printing `fopen(): Failed to open stream` with nothing after it — the same family-left-behind shape as the stat readers. `file()` was worse: it announced itself as `file_get_contents()`, so the warning named a function the program had not called. The reason is read from the OS rather than assumed, because "No such file or directory" is wrong for a file that exists and cannot be read: a locked file now reports `Permission denied`, as PHP does. The opener records the reason beside the result instead of changing its signature, so every caller that only needs to know whether the open succeeded is untouched.
- Fixed two x86_64-only defects in this release's own new code, both the same shape: correct when addressed from `sp` with rising offsets, wrong from `rbp` with falling ones. `__rt_fputcsv` builds a Mixed cell in its frame so one formatter serves every scalar layout; a cell is read at ASCENDING addresses, and an rbp frame grows DOWNWARD, so writing tag/payload/high in frame order put the last two BELOW the base and the reader took the two slots above it instead. `__rt_unknown_wrapper_warning` cleared its copy counter only on the clamped path, so the ordinary case entered the loop with the previous fragment's counter — already past the length — and the scheme came out empty as `Unable to find the wrapper ""`. Both were green on aarch64, where the same code cannot express either mistake.
- Fixed an UNTYPED `public $context;` on a stream wrapper never receiving its context — the spelling the manual shows, while `public mixed $context;` worked. The class was read as declaring no context, so it also collected the PHP 8.2 dynamic-property deprecation meant for classes that really declare none: elephc told the author to declare the property they had already declared. Widening which declarations count is only half of it and on its own it SEGFAULTS, which is what an earlier attempt measured. The two spellings are the same PHP null and differ only in elephc's representation: an untyped property is initialised by its class prologue to the in-band tagged null, not to a cell pointer, and the context injection released the previous cell before storing the new one — dereferencing `PHP_INT_MAX - 1` as an address. The release now recognises the sentinel for what it is. A wrapper that declares no `$context` still gets the deprecation.
- Fixed `fputcsv()` refusing to compile for every field array that was not already strings. `fputcsv($out, [1, 2, 3])` did not write a wrong row, it failed to build — and so did a float row, a bool row, a heterogeneous row, and `foreach ($rows as $row) fputcsv($out, $row)`, which is the shape most real CSV writing takes. php-src has no such requirement: `php_fputcsv` calls `zval_get_tmp_string` on each field, so the question a writer must answer is not "is this a string array?" but "how are these elements stored?" — 16-byte (pointer, length) slots for strings, 8-byte payloads for int/float/bool, 8-byte cell pointers for a gradual array. The lowering now stamps the element `value_type` into the free bits of the packed `csv_opts` word and the runtime reads it, delegating every non-string layout to `__rt_mixed_cast_string`, the formatter that already handles int, float, bool, resource and null; a bare scalar is wrapped in a frame-local Mixed cell first, so one formatter serves every layout and nothing is allocated to do it. Two things this had to get right were not the cast. A gradual row arrives BOXED, and writing the box is worse than a wrong field — the cell's tag word reads as a length, so a two-field row came out as four fields of raw header bytes; the row is unwrapped through the same guard that already turns a `false` from `fgetcsv()` into PHP's TypeError. And `__rt_itoa` formats into the shared 64 KiB concat arena and advances its cursor, so a numeric row that never handed its scratch back would overrun the arena silently, and only in a long loop; the writer now saves and restores the cursor, reclaiming the whole row.
- Fixed an unknown stream wrapper reporting the path and never the missing wrapper. `fopen("bogus://x", "r")` warned only `Failed to open stream: No such file or directory` — true of the path, and silent about the cause, sending a reader to the filesystem instead of to their wrapper registration. php-src warns twice, naming the scheme first. The check cannot live at compile time, which is why the obvious placement is the wrong one: `stream_wrapper_register()` is a runtime call, so a scheme the compiler has never heard of may be perfectly valid by the time the open happens. The warning is composed at the failure site and only when neither the userspace table nor the built-in list claims the scheme; a path with no `://` is an ordinary filesystem path and stays quiet. Unrelated to this change and still open: PHP ends every warning with " in <file> on line <N>", which elephc omits across its whole diagnostic surface.
- Removed `set_socket_blocking()`, which elephc declared as an alias of `stream_set_blocking()`. PHP removed it in 7.0 and `function_exists("set_socket_blocking")` answers false on 8.5.6, so declaring it made elephc accept a call PHP rejects.
- Fixed a stream wrapper that declares `$context` as its FIRST property never receiving one. The vtable slot carrying the property's byte offset used no sentinel, and zero is the legitimate offset of a first property, so such a wrapper was indistinguishable from one that declared nothing. The slot now holds offset + 1 and both openers subtract it. A separate defect in the same slot remains and is tracked: the offset is recorded only for a property the emitter can see as `mixed`, so `public $context;` — the spelling the manual shows — still reads as undeclared, while `public mixed $context;` works.
- Added PHP 8.2's `Deprecated: Creation of dynamic property <Class>::$context is deprecated` for a stream wrapper that declares no `$context`. PHP assigns the stream context onto the wrapper object whether or not the class declared a property for it, and deprecates the invented assignment; elephc skipped the injection and said nothing, so a program PHP would tell to declare its property heard nothing here. The class name comes from the same class-id table `var_dump()` reads. A separate defect is now visible and tracked: a wrapper that declares `$context` as its FIRST property is indistinguishable from one that declares none, because the vtable stores the property's offset with no sentinel and zero is a valid offset — such a wrapper never receives its context, and now also collects this deprecation.
- Fixed `file_get_contents()` refusing to read through a registered stream wrapper, where `fopen()` on the very same URI worked. php-src has no separate reader here — `file_get_contents` is `php_stream_open_wrapper` followed by `_php_stream_copy_to_mem`, so every scheme the opener knows is readable by definition. elephc had a hand-rolled scheme ladder that recognised `http`, `https` and `ftp` and then fell back to opening a filename, which is how a wrapper URI ended up reported as `Failed to open stream: No such file or directory`. A literal URI whose scheme belongs to no built-in wrapper now goes through the opener, which already scans the wrapper registry and reports a scheme nobody registered the way PHP does. A URI built at run time still takes the ladder.
- Fixed `$_SERVER` and its siblings being `null` in a CLI build, where PHP has them as arrays. Nothing noticed for as long as `count()` answered `0` for a null; the moment it started raising PHP's `TypeError`, `count($_SERVER)` became a fatal. Which superglobals exist is measured rather than assumed, and two readings of `php -n` look contradictory until the mechanism is clear: walking `$GLOBALS` reports `$_ENV` and `$_REQUEST` absent, yet `isset($_ENV)` answers true. Both are right. PHP compiles a reference to an auto-global into a marker and materializes the variable at run time, so NAMING it is what brings it into existence — which makes seven, not five: `$_SERVER`, `$_GET`, `$_POST`, `$_COOKIE`, `$_FILES`, `$_ENV` and `$_REQUEST`. `$_SESSION` appears only once `session_start()` has run, so seeding it would make `isset($_SESSION)` answer the opposite of PHP. elephc follows the same rule: a superglobal is seeded only where the program names it, which is not an optimisation but the semantics — seeding unconditionally left five live heap blocks before a program's first instruction and exhausted the deliberately tiny arenas the allocator's own tests run under. They are empty arrays, not populated ones — PHP fills `$_SERVER` with 68 entries in CLI, and that is separate work.
- Fixed `ftell()` on a userspace-wrapper stream answering uninitialised memory — a different number every run. php-src has no tell op for these streams: `main/streams/userspace.c` calls `stream_tell` only from inside `php_userstreamop_seek`, to reconcile after a seek. The position itself is PHP's own, advanced by whatever each read moved, which is why `ftell()` answers 7 after seven bytes even when the wrapper's `stream_tell()` is written to return something else entirely. elephc called the method on every `ftell()`, and an undeclared return hands back a boxed cell, so it printed a pointer. Fixing only the boxing would have been worse than the crash-shaped answer: it would have reported what the wrapper CLAIMS rather than where the stream is. The position now lives on the stream state, reads advance it, and a seek sets it. Two tests pinned the old belief, one of them by name — `php -n` answers `0|0` where it asserted `42|-1`.
- Fixed a stream wrapper's untyped contract parameters carrying the wrong type. `stream_write($data) { return strlen($data); }` — the signature the manual shows — failed to compile with `strlen() argument must be string`, and so did any wrapper that used `$path`, `$mode` or `$count` as what PHP passes. The parameter was not untyped by accident: a wrapper's methods are reached through a runtime vtable with raw fixed-ABI arguments, so they are deliberately excluded from the pass that widens untyped parameters to boxed Mixed, which would desynchronize the dispatcher from the body — and they were left with the `Int` an untyped parameter is seeded with. The dispatcher's argument types are not unknown, only undeclared, so they are now seeded from PHP's own contract instead of widened: the fixed ABI is untouched and the body can use its arguments. Only parameters without a type hint are affected, and only in a class that really is a wrapper — a lone `stream_write()` on an unrelated class keeps its own inference, because a method name is not a contract.
- Fixed `count()` answering `0` for a value that is not a collection, where PHP raises a `TypeError`. `count($x) === 0` read a non-empty string, a `null`, an integer, a float, a boolean and a resource as empty collections — six silent wrong answers, and the one case a memory note recorded was only the first of them. PHP's message names the type with the VALUE's own spelling, so a boolean reports `true` or `false` rather than `bool`; all seven wordings are read off `php -n` 8.5.6 rather than derived from the tag names, which is what separates the boolean pair. The uncaught form matches too, down to the exit code. The rejection is probed ahead of the count rather than reported by it, because the counting helper tail-calls the SPL counters and anything it returned beside the count would be whatever the tail call left behind; and the seven texts live in one runtime table rather than seven static throws, which would have inlined seven throwable constructions at every `count()` call site. A non-`Countable` object still counts as `0`: PHP names the class there, which needs a lookup and a composed message. With the runtime raising, `count()` now also accepts an `array|false` argument — the union every `array|false` builtin produces — where it used to refuse to compile; that refusal was the only thing standing between the union and a wrong answer.
- Fixed `ftell()` on a stream opened for appending reporting where the descriptor sits rather than the position PHP keeps. `fopen($f, 'a')` on a four-byte file answers `1` in PHP after one byte is written; elephc answered `5`, because `O_APPEND` puts every write at the end of the file. Only the reported number diverged — PHP's own reads use the descriptor's offset too, so a read after an append write hits EOF on both sides and the bytes on disk were always identical — but a program that recorded `ftell()` as a resume point wrote down a number PHP never produces. What is tracked is the distance `O_APPEND` jumps, not the position itself: a read moves the descriptor and PHP's position by the same amount, so it needs no accounting of its own and `ftell()` stays right through an `a+` read. A seek puts the two back in agreement and clears the running total, which is what keeps the write after `fseek($h, 0)` answering `1` instead of a negative number.
- Fixed `disk_free_space()` and `disk_total_space()` failing silently. Answering `false` was only half of PHP's behaviour: it also prints `disk_free_space(): No such file or directory`, so a script that watched the warning to notice a bad path saw nothing at all. The helper had the reason in hand at the failing `statfs` and discarded it; it now carries it out beside the success flag. PHP names neither the path nor a fixed middle here, so this could not reuse the failed-open composer, which is built around a path — and the reason comes from a `strerror` of its own rather than the socket one, which answers a pending resolver message ahead of any `errno` and would have let a failed DNS lookup earlier in the program supply the reason for a later filesystem error. `@` suppresses it, as it does every elephc diagnostic.
- Fixed `stream_socket_server("udp://…")` and `("udg://…")` handing back a working socket where PHP answers `false`. `$flags` defaults to `STREAM_SERVER_BIND|STREAM_SERVER_LISTEN`, and `listen()` is meaningless on a datagram socket, so PHP fails every datagram server not opened with `STREAM_SERVER_BIND` alone — a program written against PHP took a branch PHP never takes. The two examples shipped in `examples/udp-socket` and `examples/udg-socket` were themselves programs `php -n` refuses to run, and six tests pinned the over-acceptance. The runtime knew the transport and deliberately skipped `listen()` for it; what was missing is that the lowering never read the `$flags` operand at all, so the caller's intent never reached the helper. The refusal sits ahead of the dispatch, so the IPv4, IPv6 and Unix-domain paths all obey it, and a bind-only datagram server still opens.
- Fixed a failing IPv6 server not saying why. `stream_socket_server("tcp://[::1]:<port already bound>")` answered `false` with `&$error_message` empty and a warning reading `()`, where PHP says `Address already in use` — the difference between a program that can log why it did not start and one that logs nothing. The IPv6 helper is tail-called from a dispatcher that clears the error stash before jumping, and the helper then failed its `socket()`, `bind()` or `listen()` without recording anything; each of the three now stashes the error number before the cleanup `close()` overwrites it, as the IPv4 helper already did. `unix://` and `udg://` still report a reason PHP leaves empty: php-src's Unix-domain path composes no message, and dropping a correct diagnostic on the strength of a single platform's observation buys parity at too high a price.
- Fixed a socket failure with no reason printing an empty pair of parentheses. php-src warns `Unable to connect to <address> (Unknown error)` when nothing described the failure; elephc wrote `()`. The substitution belongs to the warning alone — the caller's `&$error_message` stays the empty string PHP leaves there — so it cannot come from the shared `strerror` helper that feeds both.
- Fixed `disk_free_space()` and `disk_total_space()` answering `float(0)` for a path they cannot stat, where PHP answers `false`. Zero is a legitimate reading for a full filesystem, so `disk_free_space($d) === false` never fired and arithmetic silently used zero. Both now follow the `float|false` convention the stat family already uses for `int|false`.
- Fixed `substr()` and `substr_replace()` reading a negative `$length` as "nothing" instead of "bytes omitted from the end". `substr("hello", 1, -1)` answered `"ello"` and `substr("hello", 0, -2)` answered `""`, where PHP answers `"ell"` and `"hel"`; `substr_replace("hello", "X", 1, -1)` answered `"hX"` instead of `"hXo"`. Two faults compounded: `-1` doubled as the in-band sentinel for "no length argument", so an explicit `-1` was indistinguishable from a two-argument call, and every other negative length was clamped to zero. `substr()` knows its argument count at compile time and no longer encodes anything in the value; `substr_replace()` consumes the sentinel in the runtime, so it became `i64::MAX`, which the existing clamp against the available bytes reduces on its own.
- Fixed `sys_get_temp_dir()` always answering `/tmp`, ignoring `TMPDIR`. On macOS PHP hands out a private per-user directory, so every program that fell back to the shared `/tmp` changed behaviour, not just its output. PHP's rule, measured: `TMPDIR` when set and non-empty, with exactly ONE trailing slash removed — `/tmp///` becomes `/tmp//`, not `/tmp` — and otherwise `P_tmpdir`, which keeps its trailing slash and is `/var/tmp/` on macOS and `/tmp` on Linux.
- Fixed a stream opened read-only accepting writes. `fopen("php://memory", "r")` took a `fwrite()` and the bytes were really there to read back, because those streams are backed by a temporary file elephc opens read-write whatever the caller asked. The mode was recorded correctly and simply never consulted; it now decides, so the answer can never disagree with the `mode` that `stream_get_meta_data()` reports. Every writable mode — including `a`, `c`, `x` and `r+` — still writes.
- Fixed `file_get_contents("php://filter/read=…/resource=…")` answering `false`. `fopen()` on the same URI already worked, parsing the URL, opening the wrapped resource and linking the filter chain; `file_get_contents()` could not reuse that because the shared opener read the open mode off the call's second argument, which for `file_get_contents()` is `$use_include_path`. The mode is now an explicit parameter, so a caller with no `$mode` argument says "read-only" instead of pointing at an operand that means something else. Filter chains (`a|b`) apply in order, as they do through `fopen()`. A URI built at run time still applies only its first filter.
- Fixed `file_get_contents("data://text/plain,hello")` answering `false` with `Failed to open stream: No such file or directory`, naming a "path" that was never one. `fopen()` already decoded these URIs at compile time; `file_get_contents()` went through the filesystem helper instead. Base64 payloads, percent-decoding and the `$offset`/`$length` window all apply to the decoded bytes, and a malformed URI still answers `false`. `file_get_contents("php://filter/…")` remains unsupported and is tracked separately.
- Fixed `feof()` answering `true` after a read that FAILED. Only a genuine zero-byte read exhausts a stream; elephc marked end-of-file for an error too, so a read loop guarded by `feof()` stopped as though the file had been consumed when in fact nothing had been read. PHP keeps it `false`.
- Fixed `stream_is_local()` and `stream_supports_lock()` answering `true` for a `data://` stream, where PHP answers `false` to both. The URL-identity test covered the remote wrappers and `data://` is not one of them, while the lock test only knew the `php://` family. A file, `php://stdout`, `php://memory` and `php://temp` keep their own answers.
- Fixed `filesize()` and `filemtime()` answering an integer for a path they cannot stat, where PHP answers `false`. `filesize()` gave `0` — a legitimate size for an empty file, so `filesize($f) === false` never fired and arithmetic silently used zero. `filemtime()` was worse on AArch64: the helper read the stat buffer without checking whether the syscall had filled it, so a missing path returned uninitialised stack, a different large integer each run. Seven of the nine stat readers already reported `int|false` through the shared boxing; these two were the ones left behind.

- Resource scope-cleanup: an `fopen()` stream, `popen()` pipe, `opendir()` directory handle, or `hash_init()` hashing context that leaves scope without an explicit `fclose()`/`pclose()`/`closedir()`/`hash_final()` is now released automatically at scope exit (closing the fd, reaping the `popen` child, freeing the context) instead of leaking until the process exits. Aliasing (`$b = $a`) is reference-counted so the handle is freed exactly once; finalizing a hash context and then dropping it is a single safe free; and an explicit close is never doubled even if the descriptor number is later reused.
- `zval` bridge builtins `zval_pack`/`zval_unpack`/`zval_type`/`zval_free`: convert elephc values to and from PHP-shaped `zval` structs (scalars, strings, packed and hash arrays, nested), the foundation for linking against a PHP extension shared library. Works on every supported target.

## [0.25.2] - 2026-06-26
- `--web`: compile a PHP program into a standalone prefork HTTP server binary with per-request top-level execution, `echo`/`print` response bodies, `$_SERVER`/`$_GET`/`$_POST` and `php://input` request input, PHP-compatible `http_response_code()`/`header()` handling, configurable listen address/workers/body limit, clean signal shutdown, worker respawn, bounded keep-alive handling, fixed-heap request cleanup, and full sharded CI coverage across macOS ARM64, Linux x86_64, and Linux ARM64.
- Fixed a heap leak when releasing string-keyed associative arrays (issue #408): promoting an indexed array to hash storage (`array_to_hash`) built the result hash from a copy of the source array but never freed that source array, leaking one allocation per conversion. Reassigning an assoc array in a loop — or, under `--web`, rebuilding the request superglobals each request — slowly exhausted the heap. The conversion now releases the temporary source array, so the heap stays flat.
- EIR small-function inliner: splices small (≤24-instruction), non-recursive user functions into their callers — covering scalar, string, and array/value helpers — with copy-on-write and reference-counting semantics preserved, gated by `--ir-opt`. Recursive (direct or mutual), generator/fiber, exception-handling, object/closure/resource/by-reference, and argument-coercing call sites are left as ordinary calls.
- EIR optimization pipeline now runs to a module-level fixed point: the small-function inliner and the per-function passes are interleaved and repeated until neither changes anything, so optimization and inlining feed each other (e.g. a function inlined once its callees fold below the size threshold). Behavior is unchanged with `--ir-opt` on vs off; only the generated code gets tighter.
- EIR common-subexpression elimination now unifies constant operands by value, so repeated computations built on constants are deduplicated too — `($n + 1) * ($n + 1)` computes `$n + 1` once. Gated by `--ir-opt`; output is unchanged, only the generated code is tighter.
- Fixed an EIR optimizer miscompile: `$x / 1` (PHP's float-producing division) was folded to its integer operand, so the result's bits were misread as a float — `var_dump($x / 1)` and float arithmetic on it produced wrong values with the optimizer on. Identity folding now only folds genuine integer division.

Runtime args: `--listen host:port`, `--workers N`, `--max-body-size N` (413 on overflow). The prefork master shuts down cleanly on `SIGINT`/`SIGTERM`, respawns workers that die, and bounds slow/idle keep-alive connections with a header-read timeout.
