# Zero-arg builtin call results (arrays/boxed Mixed) leak on local reassignment/scope-exit

> Zero argument builtin calls whose result is a fresh heap backed value a real PhpType::Array via rt array new, or a bo…

Zero-argument builtin calls whose result is a fresh heap-backed value (a real PhpType::Array via __rt_array_new, or a boxed Mixed cell via __rt_mixed_from_value/__rt_incref) are not reliably released when stored in a local variable — neither on reassignment in a loop nor at end-of-program/main-scope teardown. Confirmed reproducible with three independent, otherwise-unrelated builtins: get_declared_classes() (pre-existing, already shipped — 470 live blocks after 5 loop calls), spl_autoload_functions() (pre-existing — 5 live blocks after 5 calls), and the newly-added libxml_get_errors()/error_get_last() (5 live blocks each after 5 calls, or 2 live blocks for a single non-loop call of libxml_get_errors()+error_get_last() together). By contrast, one-or-more-argument array-returning builtins (explode(), array_keys(), even array_keys([]) which also returns a length-0 result) release correctly on reassignment (heap-debug clean). This rules out result length/emptiness as the cause and implicates argument count (or absence of any operand) in whatever mechanism ir_lower/codegen_ir uses to decide a local slot's assigned call-result needs a release-on-reassignment / end-of-scope decref. Root cause not yet isolated (likely in ir_lower's local-slot ownership bookkeeping or the codegen_ir end-of-function/reassignment cleanup pass, not the free/decref runtime routines themselves — __rt_decref_array has no length-based special case). Workaround used in tests/codegen/callables/constants_and_system.rs (both the pre-existing test_ini_table_heap_clean_with_teardown and the new gc/libxml/error_get_last heap tests): store results into an array element instead of a bare local; the array is deep-freed at epilogue and this reliably produces a clean heap-debug run.
Evidence: Reproduced with --heap-debug on macOS-aarch64: (1) loop of 5x get_declared_classes() reassigned to same local -> allocs=470 frees=0; (2) loop of 5x spl_autoload_functions() -> allocs=5 frees=0; (3) loop of 5x libxml_get_errors() -> allocs=5 frees=0; (4) single-shot script calling libxml_get_errors()+error_get_last() once each (no loop) -> allocs=2 frees=0 live_blocks=2; (5) control: loop of 5x explode(",","a,b") reassigned -> allocs=15 frees=15 clean; (6) control: loop of 5x array_keys($assocArrayWithElements) -> allocs=28 frees=28 clean; (7) control: loop of 5x array_keys([]) (zero-arg empty INPUT, but array_keys itself takes 1 arg) -> allocs=6 frees=6 clean, ruling out result-length as the cause.

## Verification

Reproduced with --heap-debug on macOS-aarch64: (1) loop of 5x get_declared_classes() reassigned to same local -> allocs=470 frees=0; (2) loop of 5x spl_autoload_functions() -> allocs=5 frees=0; (3) loop of 5x libxml_get_errors() -> allocs=5 frees=0; (4) single-shot script calling libxml_get_errors()+error_get_last() once each (no loop) -> allocs=2 frees=0 live_blocks=2; (5) control: loop of 5x explode(",","a,b") reassigned -> allocs=15 frees=15 clean; (6) control: loop of 5x array_keys($assocArrayWithElements) -> allocs=28 frees=28 clean; (7) control: loop of 5x array_keys([]) (zero-arg empty INPUT, but array_keys itself takes 1 arg) -> allocs=6 frees=6 clean, ruling out result-length as the cause.
