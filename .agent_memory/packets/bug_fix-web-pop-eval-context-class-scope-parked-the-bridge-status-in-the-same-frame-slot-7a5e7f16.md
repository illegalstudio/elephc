# --web: pop_eval_context_class_scope parked the bridge status in the same frame slot as the boxed receiver of a bridged property read, so the release decref'd 0 and leaked one object reference per read inside a class method

> Commit bacfbc1a7c — the root cause of the Symfony ServiceNotFoundException "secrets.local vault" the configurators of…

Commit bacfbc1a7c — the root cause of the Symfony `ServiceNotFoundException "secrets.local_vault"` (the configurators of `secrets.php` were never destructed, so `ServiceConfigurator::__destruct()` never called `setDefinition`). Under `--web`, `promote_eval_bridge_method_argument_locals` declares an eval context in any function with a Mixed-fallback receiver (e.g. `$this->definition->setClass()` on a `?Definition`), and `has_eval_context()` then routes that function's own `$this->definition` READ through `__elephc_eval_property_get`, which boxes the typed receiver into the frame scratch slot `EVAL_TEMP_CELL_OFFSET` (40) and owes it a release after the status check. Inside a CLASS METHOD, `pop_eval_context_class_scope()` (`src/codegen/lower_inst/builtins/eval/scope_context.rs`) parked the bridge STATUS in that same slot 40, destroying the box's only pointer; the release path then loaded the status (always 0 on that path), compared it against the result cell and called `__rt_decref_mixed` on 0 — a no-op — so the box leaked: one object reference per bridged property read, deterministic and silent, never a crash. Emitted asm (verbatim): `bl ___elephc_eval_property_get; str x0, [sp, #40]; … bl ___elephc_eval_context_pop_class_scope; … L_eval_status_ok: ldr x0, [sp, #40]; cmp x0, x9; b.eq keep; bl __rt_decref_mixed`. Fix: `src/codegen/lower_inst/builtins/eval.rs` gains `EVAL_STATUS_SAVE_OFFSET = 88` (the frame's unused last slot) and `scope_context.rs` parks the status there; two call sites were affected, `lower_eval_property_get` and `lower_eval_method_call` (the two that box a receiver into slot 40). Test: `tests/web_tests.rs::web_bridged_property_read_still_destructs_its_receiver`, a `--web` test pinning destructor ORDER against php -n (`d(a)|d(b)|d(c)|a,b,c` vs the buggy `|d(b)||b`), red on the pre-fix binary, green after on two consecutive requests. The existing non-web test `test_property_read_under_an_eval_context_releases_its_boxed_receiver` stayed green throughout because it is not inside a class method (no class scope pushed, nothing pops). Why five earlier lots (11 real bridge-ownership leaks fixed) never moved the configurator refcount ladder: every probe ran in a small build, and the breadth of the eval context comes from the `--web` FLAG, not from an `eval()` in the code — the tiny reproducer `w28/index.php` (exact mirror of ServicesConfigurator/ServiceConfigurator/traits/`return static`/explicit `__destruct()`/runtime-required closure) compiled WITH `--web --keep-symbols` reproduced in one bisection step (`set('id')` alone destructs, `set('id', Class::class)` → `->class()` does not), then the pure-AOT chain failed too (interpreter = red herring), then an asm diff plain vs --web named it. Ladder on the reproducer after: every ServiceConfigurator reaches object_refs=1, `has('secrets.local_vault')=true`, all three builds byte-identical to php -n. Filters: destructors 44/0, eval_bridge 11/0, spread 11 / references 2 / objects:: 17 / callable 24 at baseline; eval_closures 4 and runtime_gc 35 proved pre-existing by targeted revert. Harness gotcha: `tests/web_tests.rs` writes a ~29 MB binary per test into `$TMPDIR` and never cleans up (79 tests ≈ 2.3 GB) — purge `$TMPDIR/elephc*` older than a few hours when no suite runs.
Evidence: Tiny --web reproducer: php -n / plain AOT / --web outputs (secrets.local_vault missing only under --web before, has=true after); asm diff plain vs --web of ServiceConfigurator::class showing the shared slot 40; ELEPHC_EVAL_RELEASE_TRACE ladder on the reproducer before (object_refs 2..5, never 1) and after (all 1); the new web test red then green; filter name sets.
Verified by: commit bacfbc1a7c; php -n; --web reproducer build; emitted assembly; tests/web_tests.rs
