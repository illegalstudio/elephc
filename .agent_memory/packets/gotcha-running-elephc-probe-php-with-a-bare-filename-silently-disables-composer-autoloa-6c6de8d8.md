# Running `elephc probe.php` with a bare filename silently disables Composer autoload: every vendor class becomes "Undefined class". Always pass `./probe.php`

> Compile a probe with a BARE filename and the whole Composer autoload index goes empty, with no warning: ../../target/…

Compile a probe with a BARE filename and the whole Composer autoload index goes empty, with no warning: `../../target/debug/elephc freshprobe.php` reports "Undefined class" for every Symfony class, while `../../target/debug/elephc ./freshprobe.php` resolves all of them. The mechanism is one line: src/pipeline.rs derives the entry directory with `Path::new(filename).parent().unwrap_or(Path::new("."))`, and for a bare filename `parent()` returns `Some("")` — an EMPTY path, not None — so the `unwrap_or(".")` never fires. That empty path is handed to Registry::build (src/autoload/registry.rs) and on to AutoloadIndex::from_project_root (src/autoload/index.rs), whose nearest_autoload_manifest_root walks `ancestors()` of the empty path, finds no readable directory and therefore no composer.json, and returns an EMPTY index. So the rule for anyone writing probes: a probe that depends on Composer autoload is always launched with a directory component (`./x.php`), and an "Undefined class" on a vendor class is suspected to be THIS trap first, before it is reported as a compiler defect. Probes that `require_once` everything explicitly never see it, which is exactly why it went unnoticed for a whole session. The underlying defect — an empty parent should collapse to `.` — is still open at HEAD.
Evidence: Measured on 2026-09-02 while probing `new App\Kernel(...)` from examples/symfony-app/: the bare-filename invocation reported Undefined class for every Symfony class, the `./`-prefixed invocation resolved them all (session note dated 2026-09-02). The mechanism was re-derived by reading the code at HEAD f7a17151de on 2026-09-04: src/pipeline.rs:89 (`.parent().unwrap_or(Path::new("."))`), src/autoload/registry.rs:40 (Registry::build hands the root to AutoloadIndex::from_project_root), src/autoload/index.rs:30 and :75-80 (from_project_root returns an empty index when nearest_autoload_manifest_root finds no manifest).
