# OPEN: the Symfony --web ServiceClosureArgument string fatal is a `?string` PROPERTY read back wrong, at ResolveBindingsPass.php:99/101 — reduced to 60 lines

> Échelon 35, branch reconcile/dirname symfony, HEAD 99f98db775. The web Symfony cold request dies with Uncaught Error:…

Échelon 35, branch reconcile/dirname-symfony, HEAD 99f98db775. The `--web` Symfony cold request dies with `Uncaught Error: Object of class Symfony\Component\DependencyInjection\Argument\ServiceClosureArgument could not be converted to string`. The site is now NAMED and the mechanism MEASURED; it is neither instanceof (already refuted) nor the object-to-string ladder (which is correct php).

SITE. Built the binary with `--keep-symbols` (668 s, 168,956,632 bytes), served with `--workers 1` (the failure then reproduces in ~200 s instead of 652 s — use --workers 1, it is the cheapest iteration lever), attached lldb to the single worker and broke on the runtime thrower. Note the macOS naming: `breakpoint set -n __rt_sprintf_throw_string_error` does NOT resolve; `breakpoint set -r rt_sprintf_throw_string_error` does. Backtrace:
  frame #0 _rt_sprintf_throw_string_error
  frame #1 eir_shared_mixed_to_string + 10880
  frame #2 method___Symfony_..._Compiler_..._ResolveBindingsPass___processvalue + 16352
`eir_shared_mixed_to_string` is reached ONLY from an EIR `Op::Cast` to `Str` on a Mixed/Union value (src/codegen/shared_mixed_string.rs::instruction_is_mixed_string_site), so the operand is a boxed Mixed.

THE EXPRESSION. Whole-function disassembly (lldb `disassemble --force -n <symbol>` on the file works; it refuses without --force) shows at the throw: load local fp-0x2330, `eir_shared_mixed_to_string` (succeeds), the 2-byte literal " $", `_rt_concat`, `_rt_heap_free_safe`, then load local fp-0x2378 and `eir_shared_mixed_to_string` — which throws. That is `ResolveBindingsPass.php:101`, `$name = $value.' $'.$name`, and the failing operand is `$name`, not `$value`. `$name` comes from line 99, `$name = $value->getName()`; the call site is confirmed by the `__elephc_eval_trace_aot_null_method_receiver` diagnostic in the same block, which passes method "getName" and line=99.

WHY PHP NEVER GETS THERE. Line 101 is `isset($name, $bindings[$name = $value.' $'.$name])`. The short-circuit IS emitted correctly (the disassembly branches on `mixed_unbox($name) == tag 8` and skips the second operand when null). php's `$name` is null so php never evaluates the concat. elephc's `$name` is not null, so it does.

WHAT `$name` ACTUALLY HOLDS. At the breakpoint: `$value` = tag 6, class id 445 = TypedReference (its `id` and `type` are both the 75-char "Symfony\Component\Security\Core\Authorization\AuthorizationCheckerInterface", so `$type === $id` and php would assign `$this->name = $name`). `$name` = a boxed cell, tag 6, payload class id 317 = ServiceClosureArgument — and that object is RECYCLED memory: its `values` word is 0 and the next property word holds ASCII string bytes ("ializer"). So the `?string` property came back as a boxed pointer into reused heap.

DISPATCH AND VTABLE ARE INNOCENT. The Mixed-receiver call is a class-id ladder (src/codegen/lower_inst/method_dispatch.rs::mixed_method_candidates, 53 candidate ids, 43 arms boxing tag 1, 6 arms storing x0 as an already-Mixed return, 5 eval-bridge fallbacks). Class 445 IS a candidate; its arm virtual-calls `class_vtable_ptrs[445]` slot 0x28, and that slot really is `TypedReference::getname` (verified live). `TypedReference::getName()` reads offset 0x28 with its uninit sentinel at 0x30, matching `getType()` at 0x38/0x40 and `getAttributes()` at 0x48/0x50 and `Reference::__toString`'s `id` at 0x08/0x10. So the read offset is right and the property slot itself is wrong.

REDUCER (examples/symfony-app/p35r.php, 60 lines, untracked, plain build — no --web needed, no eval context, no ServiceClosureArgument). A class with a non-promoted `private ?string $name` plus promoted `private string $type` / `private array $attributes`, constructor `$this->name = $type === $id ? $name : null;`, objects built in a foreach and COLLECTED INTO AN ARRAY that the function returns, read back afterwards. Mirrors AutowireLocator::__construct() lines 84-95, which is what builds this exact TypedReference (invalidBehavior 3 = IGNORE_ON_INVALID_REFERENCE, id === type).

  elephc:       key=aliasA -> (empty) / key=TypeB -> (empty) / key=aliasC -> (empty)
A second, even smaller face is in p35s.php case m3: `$name = 'aliasA'; if ($flag) { $name = null; } return ['k' => new TR('T','T',1,$name)];` then `->getName()` gives php NULL vs elephc `9223372036854775806` = 0x7FFFFFFFFFFFFFFE, the inline NULL SENTINEL leaking into a value context undecoded (src/codegen_support/sentinels.rs:11 already documents that this sentinel collides with the real integer 9223372036854775806).
Reading it back IMMEDIATELY (no array, no return) is CORRECT — p35q's m1/m2/m4 and the `match`-wrapped variants all match php. Collecting into an array and reading after the function returns is what breaks it.

WHAT IS EXCLUDED, do not reopen: `&&`/`||`/ternary/`??`/multi-argument `isset()` short-circuit all behave (p35d); `'' !== $obj` and other literal-vs-object comparisons do not stringify (p35e); the `instanceof Reference` guard in PhpDumper's ServiceLocatorArgument arm is fine (p35c); `serialize()`/`hash()`/`ksort()`/`json_encode()` on arrays of objects are fine (p35b); a property store from a narrowed Mixed local survives heap churn (p35k); the ladder with many `getName` declarers and mixed return types is fine (p35j); `--web` alone changes nothing (p35g/p35iw).

SIDE FINDINGS, both real and both separate: after a short-circuited `isset($name, ...)` elephc leaves `$name` as `""` where php leaves NULL (p35d); and `'zz' == $stringableObject` is false in elephc, true in php (p35e). Also three compile-time refusals met while probing: `in_array` with an object needle, `array_unique` over object values, and an object as a hash key (`hash_isset`).

NOT FIXED. The fix is a representation question — the `?string` property's write and read disagree — in an area the codebase itself flags as structurally unsound, so it was not attempted without budget to run the codegen filters and a 700 s rebuild.
