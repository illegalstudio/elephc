# __rt_incref reads its argument in RAX on x86_64, and __rt_closure_bind passes it in RDI again

> rt incref has exactly two emitters, src/codegen support/runtime/arrays/incref.rs:26 AArch64 and :70 x86 64 , and the …

__rt_incref has exactly two emitters, src/codegen_support/runtime/arrays/incref.rs:26 (AArch64) and :70 (x86_64), and the x86_64 body starts with "test rax, rax" at line 74 - so its argument register is RAX, NOT the SysV first-argument register RDI. The file contains no rdi at all. A hand-written x86_64 caller that sets rdi before "call __rt_incref" therefore increfs whatever happens to be in rax. The July-2026 packet recorded this ABI trap and said the closure_bind rewrite had fixed it by using rax. On the merged tree it is back: __rt_closure_bind's x86_64 object-capture arm, src/codegen_support/runtime/callables/closure_bind.rs:172-177, does "mov rax, [rsp+16]" (rax = the NEW descriptor), "mov rdx, [rsp+8]" (rdx = the new $this receiver), "mov [rax+64], rdx", then "mov rdi, rdx" and "call __rt_incref" - so the refcount lands on the descriptor block, not on the receiver, and $this is never retained. The comment on that line still claims the descriptor now owns a reference to $this. The Mixed-capture arm just below (label __rt_closure_bind_box_this) goes through __rt_mixed_from_value instead and is unaffected. This is AArch64-invisible: the AArch64 arm at line 93 calls __rt_incref with the receiver already in x0, which is that emitter's input register, so the native macOS dev target cannot see it - only the linux-x86_64 CI shard or a cross-assembled run can. Two other observations from the same closure_bind generalization still need re-measurement and were NOT re-grounded here: calling a closure that returns a captured local more than once returned an empty string on the second call, and a local holding a Closure::bind result appeared to leak at scope exit even when never invoked. Also still true and useful: Closure::bind's literal-null $newThis lowers through Op::ConstNull at PhpType::Void, which materializes NULL_SENTINEL = 0x7fff_ffff_ffff_fffe (src/codegen_support/sentinels.rs:66, emitted at :106), so a runtime helper testing for "no new $this" must compare against that constant, never cbz or test reg,reg.
Evidence: Read src/codegen_support/runtime/arrays/incref.rs:26-90 - the two label_global("__rt_incref") sites are the only ones in src, and the x86_64 one begins "test rax, rax" (line 74) with no rdi in the file. Read src/codegen_support/runtime/callables/closure_bind.rs:160-195 - line 176 is "mov rdi, rdx" immediately before "call __rt_incref" on line 177, with rax holding the descriptor pointer loaded on line 172.
Verified by: grep + file reading on the merged worktree during the a7bb4cd92c merge, 2026-09-02; NOT executed and NOT confirmed on the linux-x86_64 shard
