# A local retyped inside a branch printed the pre-branch type's value; the if/while joins now go through the frame slot the stores already widened, and the checker widens at any depth

> PHP lets a local be reassigned to a value of another type inside a branch. $i = \strlen 'ab' ; if $argc 0 { $i = 'si'…

PHP lets a local be reassigned to a value of another type inside a branch. `$i = \strlen('ab'); if ($argc > 0) { $i = 'si'; } echo $i;` printed `0` where php -n prints `si`, but only when something below the branch stopped the tail from being duplicated into the arms — which made it look order-dependent (probe w6 wrong, its order-swapped twin w9 right). Mechanism: the store inside the arm widens the local's FRAME slot (`store_local` → `Builder::widen_local_storage_type`, int against string widens to boxed Mixed), but the merge's LOGICAL type did not follow: `join_arm_types` in src/ir_lower/stmt/conditionals.rs recorded a joined fact only for arms that agree, an arm already Mixed, or all-indexed-array arms it could convert; every other disagreement fell through with no entry, and `finish_if_type_join` restored the snapshot it happened to hold (the last arm's environment — for a bodyless else, the pre-branch int), so the echo below the merge was lowered as an int load of a boxed slot holding a string and `__rt_mixed_cast_int("si")` is 0. The same stale fact leaked out of every construct with no type join: while (its exit restored the condition's types, undoing the body's widening), zero-trip for/foreach, ternary and && arms, and a try whose callee threw before the store. Fix (commits 0751e72438 and a61b5de243): `join_arm_types` falls back to the slot's frame storage type — the contract `join_switch_type_envs` has always used for a switch's edges; `store_local_impl` in src/ir_lower/context.rs records a store that widens an already-declared slot into a boxed representation, and from that store on the name's logical type is the slot's storage type (the whole-frame boxed contract `mixed_storage_scan` and `string_incdec_locals` already used); the while exit re-asserts widened storage types after its snapshot restore (`reassert_widened_local_storage_types` in src/ir_lower/stmt/loops.rs). `Array(int)→Array(string)` is deliberately excluded from that path (the ArrayToMixed/ArrayToHash machinery's job) — this is what still blocks several array-element retypes. With the lowering correct, the checker's `local_conditional_depth == 0` condition was removed from `Checker::local_binding_is_widenable` (src/types/checker/mod.rs); every other guard stays (superglobals, $argv, global, static, =&, by-ref params, and the full --strict-locals hard error at every depth). ATTRIBUTION: this was NOT a merge regression — the pre-merge tip 8da22fe141 compiled w6 with no diagnostic and printed the same wrong 0, and was wrong on w2 (five values), w3 and wb and refused wd; the merge of origin/main only made the checker REFUSE the shapes that expose it, so the wrong output stopped being reachable rather than stopping being wrong. Known residual: 48 bytes per widened local leak at frame teardown (the boxed occupant is not released by the frame epilogue — a different code path), and PHP's "Deprecated: Increment on non-numeric string" is not emitted.
Evidence: Probes w2..wd, we/wf under the session scratchpad p0/: php -n vs pre-merge 8da22fe141 (built in a throwaway detached worktree) vs current — pre-merge printed I:0 on w3/w6/wb and A:0 B:∅ C:0 D:∅ F:0 on w2; current is byte-identical to php on all. --emit-ir on w6 vs wc showed the tail sunk into both arms in wc (each copy carrying its arm's fact) and landing in if.merge in w6 with `v10: I64 = load_local slot[0]`. 14 end-to-end fixtures in tests/codegen/locals_retype.rs (if, else, nested if, foreach, while, three zero-trip loops, try, catch, switch, ternary, &&, the w6/w9 pair both orders, the Path.php:320 shape, a store after unset inside try, a widening whose RHS throws, ++ on a widened local) each byte-verified against php -n.
