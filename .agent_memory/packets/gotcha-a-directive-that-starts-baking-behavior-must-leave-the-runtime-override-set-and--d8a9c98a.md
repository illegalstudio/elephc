# A directive that starts baking behavior must leave the runtime-override set, and the null arm must follow too

> directive runtime overridable in src/opcache/directives.rs encodes a rule the codebase states explicitly: ELEPHC INI …

`directive_runtime_overridable` in src/opcache/directives.rs encodes a rule the codebase states explicitly: `ELEPHC_INI_*` re-points only directives elephc MERELY REPORTS, because honoring a directive on the reporting surface while its compiled behavior ignores it produces a binary that contradicts itself. THE RULE IS NOT SELF-ENFORCING — nothing fails when a new feature starts consuming a directive that is still in the overridable set.

That had already silently happened: when the runtime script cache landed it began baking `opcache.validate_timestamps` and `opcache.max_file_size` into the `__elephc_eval_configure_opcache` bridge call, but both were left runtime-overridable, so `ELEPHC_INI_opcache__max_file_size=8K` moved the REPORT while the cache kept applying the compiled value. Its siblings `revalidate_freq`/`memory_consumption`/`max_accelerated_files` had been excluded from the start, which is what made the omission easy to miss.

Adding the `opcache.file_cache` startup validation required excluding four more (`file_cache`, `file_cache_read_only`, `log_verbosity_level`, `error_log`), and the two above were fixed at the same time — 16 excluded, 38 overridable on 8.5 (older tables: 15 of 53, also 38).

TWO NON-OBVIOUS CONSEQUENCES:

1. THE NULL ARM IS A SECOND, SEPARATE SURFACE. src/opcache_prelude/env_ini.rs renders `ini_get_all()`'s PHP-`null` decision for `opcache.file_cache` (the only null-defaulting directive) independently of the value arm. Excluding the directive silenced the value arm but left the null arm consulting the environment, so `ELEPHC_INI_opcache__file_cache=/x` reported `''` — "assigned the empty string" — a THIRD state reference PHP never shows, for a directive nothing assigned. Both arms must test `directive_runtime_overridable`.

2. THE TEST SUITES PICK EXEMPLAR DIRECTIVES. tests/opcache_env_override_tests.rs and tests/opcache_ini_tests.rs pin the generic scanner/normalizer machinery through one directive per type code, and had chosen `opcache.max_file_size` ('i') and `opcache.error_log` ('s') — both now excluded, which broke 6 tests that were not about those directives at all. Replaced with `opcache.jit_debug` and `opcache.blacklist_filename`; VERIFIED on 8.5.10 that jit_debug normalizes identically (1M->1048576, 12abc->12, 8K->8192, nope->0, 0x10->16) so no expected value moved. When excluding a directive, grep the test suites for it before assuming the change is local.
Evidence: The null-arm defect was observed as `fc=''` where `fc=NULL` was required (tests/opcache_ini_tests.rs::assigning_file_cache_replaces_the_null_with_the_string). The exemplar breakage was 4 failures in opcache_env_override_tests and 2 in opcache_ini_tests, none of which concerned the swapped directives' own semantics. All green after the fix.
Verified by: cargo test --lib (all pass) plus the eight opcache integration suites
