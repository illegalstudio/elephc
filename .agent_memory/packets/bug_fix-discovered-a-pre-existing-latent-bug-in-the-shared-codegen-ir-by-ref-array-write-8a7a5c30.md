# Discovered a pre-existing, latent bug in the shared codegen_ir by-ref array write-back pri

> Discovered a pre existing, latent bug in the shared codegen ir by ref array write back primitive: FunctionContext::st…

Discovered a pre-existing, latent bug in the shared codegen_ir by-ref array write-back primitive: FunctionContext::store_value_to_local()'s ref-cell branch (src/codegen_ir/context.rs, store_value_to_ref_cell_local) corrupts an ALIASED array (`$b =& $a`) down to a zeroed/empty state when store_result_value()+store_value_to_local() is called MORE THAN ONCE against the same array local within either (a) a single array_unshift() call with 2+ variadic values, or (b) any array_unshift() call that triggers __rt_array_grow() reallocation. Verified the array/shift/insert/capacity logic itself is byte-for-byte correct (php-verified) without an alias present, and that calling this same write-back exactly ONCE per statement (e.g. two separate `array_unshift($a, $v)` statements) works fine — so the trigger is specifically "2+ ref-cell write-backs of an Array-typed value reachable from ONE alias, close together". The identical source_load_local_slot()+store_result_value()+store_value_to_local() sequence is also used verbatim by array_push()'s own codegen_ir fallback (src/codegen_ir/lower_inst/arrays.rs:346 lower_array_push), but that fallback is normally UNREACHABLE for a simple local variable since array_push($simpleLocal,...) is intercepted earlier by lower_static_array_push in src/ir_lower/expr/mod.rs (a completely different Op::ArrayPush-based mechanism that never touches store_value_to_local). So this bug was very likely never exercised by any by-ref array builtin before H5's array_unshift capacity-growth work. Repro (crashes/zeroes to empty): `$a=[3,4]; $b=&$a; array_unshift($a,1,2);` (multi-value single call) OR `$a=[-1]; $b=&$a;` then several sequential single-value array_unshift($a,$i) calls until __rt_array_grow fires. Workaround shipped in H5: array_unshift's EIR lowering (src/codegen_ir/lower_inst/builtins/arrays/unshift.rs) still emits the standard per-value write-back loop (matches array_push's established pattern), and the test suite (tests/codegen/arrays/indexed/slice_stack_range.rs) deliberately avoids the two broken combinations, documenting them as a residual instead of asserting broken behavior.
Evidence: Manual repro via cargo run on /tmp/h5test/unshift_alias*.php variants; php -n cross-checked expected correct output; confirmed non-aliased equivalent cases produce byte-for-byte correct output.
