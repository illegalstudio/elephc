# clone must re-persist a string property: strings are the one owned payload without a refcount

> A string property slot owns an independent rt str persist block that carries NO refcount word: every store into one p…

A `string` property slot owns an independent `__rt_str_persist` block that carries NO refcount word: every store into one persists, every release frees outright. `clone` called `__rt_incref` on the copied pointer, which retained NOTHING (and under `--heap-debug` wrote a refcount word a string block does not have, reported as "bad refcount"), so clone and source shared one block that the source's next assignment freed: `foreach ($chunks as $c) { $s->string = $c; $out[] = clone $s; }` printed the LAST chunk for every element, then 2-byte garbage once the freed block was reused. An `array` property in the same class survived because arrays ARE refcounted, which made the defect look string-specific. Fix (commit d6b512514d, `src/codegen/lower_inst/objects/clone_and_spl.rs` `emit_persist_cloned_property_string`, `allocation_clone.rs`): the clone re-runs `__rt_str_persist` on the copied pointer/length pair (exactly what a store into a `string` property does) and drops `Str` from the retain list so no slot gets both. GOTCHA: a declared-but-unassigned typed property carries the UNINITIALIZED sentinel in the slot's high word where an initialized string keeps its length; persisting that pair would read 0x7fff_ffff_ffff_fffd bytes, so the marker is left as the shallow copy placed it, which is what `isset($this->path)` reads afterwards. `Symfony\Component\String\ByteString::split()` is that loop shape. `--test codegen_tests clon` has 2 pre-existing failures (`test_eval_clone_aot_object_expression`, `test_reflection_class_is_cloneable`) identical with and without the change.
Evidence: Loop fixture printed the last chunk for every element and garbage before the fix, byte-identical to php -n after; --heap-debug "bad refcount" gone; uninitialized-property clone fixture keeps isset() false as php does; `clon` filter 2 failures identical before/after.
Verified by: commit d6b512514d; value tests in tests/codegen/objects/cloning.rs; php -n oracle; --heap-debug

## Verification

Loop fixture printed the last chunk for every element and garbage before the fix, byte-identical to php -n after; --heap-debug "bad refcount" gone; uninitialized-property clone fixture keeps isset() false as php does; `clon` filter 2 failures identical before/after.
