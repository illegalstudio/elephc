# A typed static property never takes ownership of a heap string: the store emits no acquire, so the next allocation silently replaces the value (S::$a = str_repeat("x",3) then reads "zzz")

> OPEN, found 2026 09 04 while probing the web static property reset which turned out NOT to be needed: a three request…

OPEN, found 2026-09-04 while probing the --web static-property reset (which turned out NOT to be needed: a three-request --web probe is byte-identical to php -S, so the Laravel branch's Gate 65 failure does not reproduce on this tree). Reducer: `class S { public static string $a; } S::$a = str_repeat("x", 3); $other = str_repeat("z", 3); echo S::$a;` — php prints `xxx`, elephc prints `zzz`: one typed static property, one later unrelated allocation, the value is silently gone. A typed static WITH a default is equally broken; an untyped (Mixed-boxed) static, an instance property and a local are all correct; it reproduces in a plain CLI build and with `--ir-opt=off`, so it is neither web-specific, nor aliasing (symbols distinct and correctly sized), nor the optimizer. The IR pins it: `store_static_property v3` gets NO `acquire`, while the local assignment two lines later emits `acquire`/`release` — the block is simply unowned and the allocator reissues it. The two sides disagree about who adopts the value: `lower_static_property_assign` in `src/ir_lower/stmt/static_property_writes.rs` (~:64-77, the moving-store branch) and `static_property_store_retains_independent_value` (~:86) versus the codegen store in `src/codegen/lower_inst/static_properties.rs` (~:103). Fix shape: make the store adopt (acquire) a heap payload exactly like a local/instance store does, on one side only. Frozen reducers with .expected under the session scratchpad laravel/transfer/static/.
Evidence: php -n vs ./target/debug/elephc at bacfbc1a7c on the 3-line reducer (xxx vs zzz), typed-with-default variant identical, untyped/instance/local controls correct; --emit-ir showing store_static_property without acquire; --ir-opt=off same result.
Verified by: read-only agent probes 2026-09-04 (php -n oracle, elephc binary, --emit-ir)

## Verification

php -n vs ./target/debug/elephc at bacfbc1a7c on the 3-line reducer (xxx vs zzz), typed-with-default variant identical, untyped/instance/local controls correct; --emit-ir showing store_static_property without acquire; --ir-opt=off same result.
