# The return-by-reference marker must be recorded, not skipped, or a by-value method passes a by-ref contract

> PHP's return by reference marker sits between the function keyword and the name or parameter list. Every eval declara…

PHP's return-by-reference marker sits between the function keyword and the name or parameter list. Every eval declaration parser advanced past the keyword and then demanded an identifier or an opening paren, so five spellings all died on the ampersand: the named function in parser/statements/functions_namespaces.rs, the class method and the interface signature, the anonymous function and the arrow function in parser/expressions/callables_arrays.rs. The property-hook parser in class_members.rs was the ONLY one that had ever consumed it -- worth knowing, because a grep for the consume finds one hit and makes the gap look already handled.

The important part is that the marker has to be RECORDED, not consumed and dropped. PHP's rule is one-directional and measurable with php -n 8.5.6: an implementation may ADD the ampersand where its interface does not ask for one, but dropping one the interface requires is a fatal reading Declaration of Bad::get() must be compatible with & Ref::get(). A parser that swallowed the marker would let a by-value method stand in for a by-reference contract silently, which is a worse state than the refusal it replaced. So EvalFunction, EvalClassMethod, EvalInterfaceMethod and EvalStmt::FunctionDecl each carry a returns_by_ref flag and class_method_satisfies_interface_signature_with_return_mode enforces the single direction php enforces.

SCOPE that matters for whoever picks this up next: the DECLARATION is not the BINDING. Called by value -- how nearly all PHP code calls them -- a by-reference function is indistinguishable from a by-value one, so accepting the declaration alone is a real gain with no wrong answers. Binding to the result, a dollar-r equals ampersand call, is a different construct: it needs the callee to hand a writable reference target back to the caller, and nothing in the interpreter does that yet. It stays refused on purpose and the refusal is pinned in a parser test, because binding by value would silently make a later write to the bound name a no-op on the original.

ALSO MISSING, pre-existing and wider than references: elephc has no parent-CLASS method override compatibility check at all. A subclass dropping an ampersand its parent declares is accepted where php refuses it. Only the interface direction had machinery to extend.
Evidence: php -n 8.5.6 prints 5;1;1;7;2;1 for the five declaration spellings called by value and 3 for an implementation adding the marker; it fails with Declaration of Bad::get() must be compatible with & Ref::get() when an implementation drops one the interface requires, and elephc now matches all three. Sentinels: disabling the marker consumption fails all three interpreter tests plus the parser one and three property-hook tests that share the same line; disabling the interface rule fails exactly the test that drops a required marker. Symfony measurement: LazyDecoratorTrait.php moves from line 86 to line 94 onto list destructuring with skipped slots; the reducer corpus goes from 21 refusals of 37 to 20.
Verified by: cargo test -p elephc-magician --lib with no skips: 1395 passed, 0 failed, 0 filtered (commit 7405c9d7a0)
