# instanceof on an `iterable` operand answered a hardcoded false; the slot holds the UNBOXED payload so it belongs on the object matcher, not the Mixed one

> FIXED, and it is a general correctness bug, not a Symfony one: every instanceof whose operand was declared iterable a…

FIXED, and it is a general correctness bug, not a Symfony one: every `instanceof` whose operand was declared `iterable` answered a hardcoded false, for any object.

THE SITE. `src/codegen/lower_inst/objects/instanceof_entry.rs`, top of `lower_instanceof`, guards on the operand's type:
    if !matches!(value_ty, PhpType::Callable | PhpType::Object(_) | PhpType::Mixed | PhpType::Union(_))
        { emit_false(ctx); return ...; }
`PhpType::Iterable` was missing, so the operand took `emit_false` with no runtime call emitted at all (`--emit-asm` showed zero `__rt_class_implements_interface` / `__rt_mixed_instanceof`). The dynamic sibling `emit_normalized_dynamic_instanceof_value` (instanceof_helpers.rs) had the same omission, dropping `Iterable` into the `_` arm that loads 0, so `$v instanceof $name` was equally affected. PHP spells `iterable` as `array|Traversable`, so the value IS an object whenever it is the Traversable half.

THE SUBTLETY THAT MAKES OR BREAKS THE FIX. Adding `Iterable` to the guard and routing it alongside `Mixed | Union(_)` to `__rt_mixed_instanceof` does NOT work -- measured: the emitted code changes (a real `bl __rt_mixed_instanceof` appears) and the answer is still false. An `iterable` slot does not hold a boxed Mixed cell; it holds the UNBOXED payload. The proof is `src/ir_lower/gradual_coercions.rs:104`, where coercing a gradual value TO `Iterable` emits `Op::MixedUnbox`, and `src/types/model.rs:120` describes it as a "type-erased pointer (array|Traversable)". Routing it to the Mixed matcher therefore unboxes a second time and reads garbage. `Iterable` belongs on the `PhpType::Object(_)` arm, where the raw pointer is already what `__rt_exception_matches` wants.

THE ARRAY HALF IS SAFE, and this is why the object matcher may be used for a type that is only sometimes an object: `__rt_exception_matches` / `__rt_class_implements_interface` range-check the class id against the emitted class table and answer false for anything outside it (see the `cmp x0, x9 / b.hs ..._no` guard in src/codegen_support/runtime/exceptions/class_implements.rs). Verified against php -n 8.5.10 for an empty array, a list, an assoc array and a nested array -- all answer false, an object answers true, and a second pass over the same values is unchanged, so nothing is corrupted.

SCOPE OF THE FIX, measured. Before: `obj:yy iter:nn mixed:yy` against php's `obj:yy iter:yy mixed:yy`, for a Generator, an `ArrayIterator` and a user class implementing `Iterator` alike. After: identical to php in every case. It is NOT sufficient for the Symfony `--web` request, which still segfaults at the same address in the same frame -- that crash depends on something else (see the companion packet on `__rt_mixed_unbox` inside `ResourceCheckerConfigCache::isFresh`, where the object is constructed through the EVAL bridge; the AOT-constructed twin of the same reducer now matches php exactly while the eval-constructed one still dies in `iterator_to_array`).
Evidence: scratchpad/red7/builtin.php, pure AOT, three parameter declarations over one `MyIter implements \Iterator`: before `obj:yy iter:nn mixed:yy`, after `obj:yy iter:yy mixed:yy`, php `obj:yy iter:yy mixed:yy`. scratchpad/red7/arrays.php, the safety check: php and elephc both print `empty:nn list:nn assoc:nn nested:nn obj:yy again:nnyy`, exit 0. scratchpad/red6 (Symfony-shaped `Checker` with promoted `private iterable` + Generator): the AOT-constructed case goes from `[trav=n][iter=n]` + TypeError to `[type=Generator][trav=y][iter=y][converted]false`, matching php exactly. The intermediate attempt routing `Iterable` to `__rt_mixed_instanceof` emitted `bl __rt_mixed_instanceof` inside `_fn_as_u_iterable` and still printed `iter:nn`, which is what identified the unboxed representation. Regression slices with the fix: `RUST_MIN_STACK=33554432 cargo test --test codegen_tests exception -- --test-threads=4` = 145 passed / 2 failed and `... instanceof ...` = 59 passed / 2 failed; all four failures reproduce identically on a pristine tree (test_builtin_exception_message_api, test_regression_escaped_caught_exception_retained_once, test_eval_declared_class_native_instanceof_after_barrier, test_instanceof_self_parent_and_late_static). The Symfony binary still crashes at KERN_INVALID_ADDRESS 0x100000020 in the same frame, so the fix is necessary but not sufficient there.
Verified by: php -n 8.5.10 as oracle on four pure-AOT reducers including an array-safety matrix, --emit-asm before and after, and the exception + instanceof codegen slices compared against a pristine tree
