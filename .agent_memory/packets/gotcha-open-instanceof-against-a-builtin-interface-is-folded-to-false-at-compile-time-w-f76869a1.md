# OPEN: instanceof against a builtin interface is folded to FALSE at compile time when the operand is declared `iterable`, and that is what sends Symfony's isFresh down the wrong branch

> OPEN, measured and NOT fixed, with a 25 line PURE AOT reducer no eval, no include, no web. This is the upstream cause…

OPEN, measured and NOT fixed, with a 25-line PURE AOT reducer -- no eval, no include, no --web. This is the upstream cause of the SIGSEGV the Symfony `--web` request dies on.

THE DEFECT, in one table. Same object (`class MyIter implements \Iterator`), same interface targets, three parameter declarations, identical bodies:
  php -n 8.5.10 : obj:yy  iter:yy  mixed:yy
  elephc        : obj:yy  iter:nn  mixed:yy
ONLY the `iterable` declaration is wrong, and it is wrong for every object tried: a Generator, an `ArrayIterator`, and a user class implementing `Iterator`. A user-defined interface under an `object` parameter answers correctly both as `MyMarker` and `\MyMarker`, so this is about the OPERAND's declared type, not the target name and not the leading backslash.

THE SITE. `src/codegen/lower_inst/objects/instanceof_entry.rs`, top of `lower_instanceof`:
    if !matches!(value_ty,
        PhpType::Callable | PhpType::Object(_) | PhpType::Mixed | PhpType::Union(_)
    ) { emit_false(ctx); return store_if_result(ctx, inst); }
`PhpType::Iterable` is absent from that allow-list, so an `iterable` operand takes a hardcoded `emit_false`. `elephc --emit-asm` confirms it: ZERO `__rt_class_implements_interface` / `__rt_mixed_instanceof` calls are emitted for those probes. The dynamic sibling has the same omission -- `emit_normalized_dynamic_instanceof_value` (instanceof_helpers.rs:60-81) handles `Mixed | Union(_)` and drops `Iterable` into the `_` arm that loads 0 -- so `$v instanceof $name` is equally affected. PHP spells `iterable` as `array|Traversable`, so the value IS an object whenever it is the Traversable half; answering a constant false is simply wrong.

ADDING `Iterable` TO THE ALLOW-LIST IS NECESSARY BUT NOT SUFFICIENT -- this was tried and measured. With `PhpType::Iterable` added to the guard, to the eval-fallback condition, and to the `Mixed | Union(_)` arm (routing it to `__rt_mixed_instanceof`), the emitted code DOES change -- `as_iterable` then contains a real `bl __rt_mixed_instanceof` -- but the answer is still `nn`. Copying the parameter into a local first (`$m = $v;`) does not help either. So the runtime helper cannot read the cell: an `iterable` slot is NOT the boxed Mixed cell that `__rt_mixed_instanceof` expects. `src/types/model.rs:120` describes it as `Iterable => 8, // type-erased pointer (array|Traversable)`. The change was REVERTED rather than shipped, because it swapped a wrong-but-harmless constant for a runtime call that feeds a possibly-unboxed pointer into a Mixed helper -- same wrong answer, new crash risk.

SO THE REAL FIX NEEDS THE REPRESENTATION ANSWERED FIRST: what exactly lives in an `iterable` slot at run time, and either normalize it to a boxed Mixed before the matcher (the way `emit_mixed_instanceof_value_normalization` does for the dynamic path) or give it its own matcher that discriminates the array half from the Traversable half. Worth noting the Symfony crash lands in `__rt_mixed_unbox` reading that very property, so some other path already treats an `iterable` as boxed -- the representation may simply be inconsistent between producers and consumers, which would make this a storage bug rather than an instanceof bug.

WHY IT MATTERS BEYOND THE REDUCER. `ResourceCheckerConfigCache` declares `private iterable $resourceCheckers = []` and `isFresh()` opens with
    if ($this->resourceCheckers instanceof \Traversable && !$this->resourceCheckers instanceof \Countable) {
        $this->resourceCheckers = iterator_to_array($this->resourceCheckers);
    }
    if (!\count($this->resourceCheckers)) { return true; }
The false answer skips the conversion and hands the Traversable to `count()`. In the small reducer that is a clean `TypeError: count(): Argument #1 ($value) must be of type Countable|array, Traversable given` -- the message itself calls the value Traversable, so `count`'s own check contradicts `instanceof`. In the real Symfony binary the same wrong branch ends in SIGSEGV inside `__rt_mixed_unbox` in the AOT `isFresh` body. An older packet caught this same property lying (`is_array()` false while `get_debug_type()` said `array`), so both findings are about one member.
Evidence: scratchpad/red7/builtin.php, pure AOT: php `obj:yy iter:yy mixed:yy` vs elephc `obj:yy iter:nn mixed:yy`. scratchpad/red7/main.php with all three probes typed `iterable`: php `gen:yy arrayiter:yy userclass:yy` vs elephc `gen:nn arrayiter:nn userclass:nn`, and `--emit-asm` yields 0 occurrences of `__rt_class_implements_interface`. scratchpad/red7/fq.php: user-defined interface under `object`, `bare:y fq:y` under both. scratchpad/red7/box.php: routing through a local (`$m = $v;`) still gives elephc `direct:nn viamixed:nn` against php `direct:yy viamixed:yy`. With Iterable added to the three match sites, `--emit-asm` shows `bl __rt_mixed_instanceof` inside `_fn_as_u_iterable` yet the program still prints `iter:nn`; reverted. scratchpad/red6 (Symfony-shaped `Checker`, promoted `private iterable`, Generator argument): php `gen:false`, elephc `Uncaught TypeError: count(): Argument #1 ... Traversable given`, exit 255, probes `[type=Generator][trav=n][iter=n]` vs php `[trav=y][iter=y][converted]`, identical whether the Generator is made in AOT or interpreted code. Symfony crash report index-2026-09-12-192853.ips: EXC_BAD_ACCESS at 0x100000020 in __rt_mixed_unbox from method___..._ResourceCheckerConfigCache___isfresh.
Verified by: php -n 8.5.10 as oracle against elephc for four pure-AOT reducers, --emit-asm before and after a trial fix, and the macOS crash report for the Symfony worker
