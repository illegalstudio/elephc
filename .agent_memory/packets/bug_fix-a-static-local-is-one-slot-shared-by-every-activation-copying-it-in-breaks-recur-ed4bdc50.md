# A static local is one slot shared by every activation; copying it in breaks recursion and hangs

> A static $x was COPIED into the activation at its declaration and written back to a store on return, which is one cal…

A `static $x` was COPIED into the activation at its declaration and written back to a store on return, which is one call too late: a recursive frame read the value the slot held when the OUTER frame started. `function rec() { static $a = 1; echo $a," "; $a++; if ($a < 6) { rec(); } }` printed `1` forever and recursed until the heap gave out, because the loop guard was true in every frame. That is `tests/lang/008.phpt` in php-src.

MEASURE THE SUB-BEHAVIOURS SEPARATELY. Six were checked and FOUR were already correct: a plain function keeps its slot across calls; two instances share a method's slot; and `Child::tick()` returns 3 -- an inherited static method shares the DECLARING method's slot, NOT one per class, which is the natural guess and has been wrong since php 8.1. Only recursion and closure identity were broken. "Statics are broken" would have been a four-times-larger change than the defect.

STORAGE MODEL. The slot lives in one scope the context owns, reached by RAW POINTER exactly as the global scope already is, because a write arrives through `set_scope_cell` which only ever holds `&ElephcEvalContext`. `RefCell` is the obvious first attempt and the compiler refuses it: `RefCell` is not `RefUnwindSafe` and the FFI crosses ~100 `catch_unwind` boundaries holding the context (`crates/elephc-magician/src/ffi/*`). Raw pointers ARE `RefUnwindSafe`, which is why the global-scope pattern works. Reads and writes both go through a `static_aliases` map in the scope, mirroring `global_aliases`. `persist_static_locals` then becomes a natural no-op, since the name is no longer in the activation scope.

ONE STORE, NOT TWO. Leaving the old `static_locals: HashMap` beside the new scope made `ReflectionFunction::getStaticVariables()` and the by-reference static target read stale values (4 tests caught it). Reimplement `static_local`/`set_static_local` over the new storage instead, and every existing reader follows.

CLOSURES: key statics on the name `define_closure` mints per OBJECT, not on `EvalFunction::name()` which is the parser's name for the closure LITERAL and shared by every object made from it. php gives two closures from one factory separate storage (`121`, not `123`). The call FRAME must keep the function name, because php prints `{closure}` there -- so this needs a separate slot-key stack on the context, not a change to `push_function`.

TWO OWNERSHIP RULES THE COUNTING FIXTURE CAUGHT (the compiled binary printed the right answer both times):
1. A read through the alias must report `ScopeCellOwnership::Borrowed` WHATEVER the slot's own entry says. Handing back the slot's entry verbatim reports `Owned`, and the activation's cleanup then releases a cell the slot still holds.
2. `return $s` on a static must RETAIN. Every other return transfers ownership by `release_activation_scope` skipping the returned cell; a static has no entry in that scope to skip, so without a retain a discarded `f();` destroys the value the next call is supposed to read. The fixture reports `reached count -1`.

Rule 2 generalises: any storage the ACTIVATION does not own needs an explicit retain on return. `global` has the same shape and may carry the same latent defect -- unverified, worth a probe.

SENTINEL: the one that matters here is not a changed string. Restoring the copy makes `recursion_shares_one_slot` OVERFLOW THE STACK, which is the original defect reproduced.
Evidence: php -n 8.5.6 oracle `1 2 3 4 5 |123|123|121|12|3` reproduced byte-identically through a compiled runner. Five tests in crates/elephc-magician/src/interpreter/tests/static_locals.rs. Sentinels: restoring the copy overflows the stack on the recursion test and fails the closure test; keying closure statics on the literal fails exactly the closure test with 123 against 121. The two ownership rules were each found by the counting fixture panicking with `reached count -1` while the compiled binary printed the correct output.
