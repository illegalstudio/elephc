# A hash bucket has no shape for TaggedScalar (map it to a boxed Mixed bucket), and a call argument's own box outlives a forwarding nullable guard (release it after the call)

> Commit 8600e6af6b, two ownership/representation bugs. 1 A hash carries ONE static value tag for the whole table plus …

Commit 8600e6af6b, two ownership/representation bugs. (1) A hash carries ONE static value tag for the whole table plus two payload words per entry; a `?int`/`?bool`/`?float` value (`TaggedScalar` repr) keeps its null tag in a separate register with nowhere to go, so `["a" => $x]` with a `?int` local PANICKED the compiler in `hash_new` (`runtime_value_tag(TaggedScalar)` is `unreachable!()`, `src/codegen/lower_inst/hashes.rs`). New `hash_bucket_value_type()` maps TaggedScalar to a boxed `Mixed` bucket at allocation AND at every read/write site. `isset()`'s hash-offset-missing check (`src/codegen/lower_inst/builtins/isset.rs`) independently re-derived the element type and had the identical bug, silently answering "set" for a `?int` null. STILL OPEN: a direct read `$m["a"]` of such an entry refuses with `hash_get value PHP type Mixed with result PHP type TaggedScalar` — `require_hash_get_result`/`emit_hash_get_success_*` have no Mixed-bucket→TaggedScalar arm (fix shape: unbox via `__rt_mixed_unbox`, release the box). (2) `f(new C())` against a `?C` parameter boxes the argument, then the nullable nominal guard FORWARDS that same box; post-call cleanup asked only about the argument and released nothing, so `__destruct` never ran. New `LoweringContext::owning_box_behind_borrowed_nominal_guard` (`src/ir_lower/context.rs`, used from `src/ir_lower/expr/nullable_method_calls.rs`) recovers and releases the box the argument expression itself minted — never one borrowed from a callee's own parameter (e.g. `parent::__construct` forwarding). Side effect: the 7-block heap residual pinned in `test_a_retyped_locals_boxed_slot_is_visible_in_the_arrays_it_fills` (a `?N $p` constructor-argument chain) disappears; its pin moved from 8 blocks/416 bytes to 1 block/48 bytes (the returned array). Tests: `test_tagged_nullable_int_in_an_assoc_literal_round_trips`, `test_destruct_of_a_temporary_passed_to_a_nullable_object_parameter`, `test_nullable_object_parameter_call_leaves_a_clean_heap`. Filter sets consistent with baselines (destructors 19/19, null_sentinel 34/34, isset 47/4 pre-existing, hash 137/2 pre-existing SIGSEGVs, nullable 5, runtime_gc 35, references 2, locals_retype 8, objects:: 17). Destructor corpus after this commit: 25/32 identical; remaining gaps: an object captured by a closure `use()` never destructs; no destructor on exception unwind; `register_shutdown_function` undefined; global-shutdown destructor order; and the cycle collector `__rt_gc_collect_cycles` is only triggered by an explicit `unset()` statement, never at frame teardown or shutdown, and `gc_collect_cycles()` is undefined.
Evidence: Compiler panic reproduced then gone; php -n oracle on the three value tests; standalone probe of the constructor-argument chain going from 7 leaked blocks to `HEAP DEBUG: leak summary: clean`; each ambiguous filter failure isolated by reverting the relevant half of the diff and rebuilding (agent report 2026-09-03).
Verified by: commit 8600e6af6b; php -n; --heap-debug; narrow cargo test filters
