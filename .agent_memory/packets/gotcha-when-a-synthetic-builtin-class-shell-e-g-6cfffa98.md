# When a synthetic/builtin class shell (e.g

> When a synthetic/builtin class shell e.g. Reflection declares a private array property populated by RAW asm bakers in…

When a synthetic/builtin class shell (e.g. Reflection*) declares a private array property populated by RAW asm bakers in codegen_ir (emit_string_array / emit_mixed_array style helpers), the checker-side property/return TypeExpr MUST match the actual runtime element layout — never use the bare `array_type()` helper (TypeExpr::Named("array")), which resolves to Array<Mixed> under gradual typing. A plain string array built via emit_string_array has NO Mixed-boxed elements; if the checker believes the array holds Mixed cells (bare `array`) while codegen bakes plain string elements, any element-consuming builtin (in_array(), etc.) on that property SEGFAULTs by treating each raw string slot as a boxed Mixed cell. Fix: declare TypeExpr::Array(Box::new(TypeExpr::Str)) (or Box::new(mixed_type()) when the array truly holds boxed Mixed, e.g. built via emit_mixed_array) so the static type matches the runtime representation. This is a specific, reproducible instance of the repo's known 'static type vs runtime representation divergence' bug class. Also: ClassInfo.declared_properties/declared_static_properties (checker/schema/classes/properties.rs) is the ONLY reliable signal for 'does this property have an explicit source type hint' — an untyped property still gets an INFERRED PhpType (from its default value, or PhpType::Int as the no-default fallback), so comparing the resolved PhpType against PhpType::Mixed to detect 'has declared type' silently over-reports true for the common untyped-no-default case.
Evidence: Reproduced with `interface I {} class A implements I {} class B extends A {}`; `(new ReflectionClass('B'))->isSubclassOf('A')` SIGSEGV'd (exit 139) when the __ancestors_lower property was declared with array_type() (bare array/Mixed) while emit_string_array baked plain string elements. Fixed by declaring TypeExpr::Array(Box::new(TypeExpr::Str)) instead; isSubclassOf/implementsInterface/hasMethod/getInterfaceNames then matched php -n output exactly. Separately, ReflectionProperty::hasType() over-reported true for `private $untyped;` (no type, no default) when implemented as `resolved PhpType != Mixed`, because apply_instance_property defaults an untyped no-default property to PhpType::Int, not Mixed; switching to ClassInfo.declared_properties.contains(name) fixed it and matched php -n exactly.
