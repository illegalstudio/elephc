# Discovered a checker property-type cross-contamination bug while probing the Closure::bind

> Discovered a checker property type cross contamination bug while probing the Closure::bind scope rebind gate unrelate…

Discovered a checker property-type cross-contamination bug while probing the Closure::bind scope-rebind gate (unrelated to that feature — reproduces with plain OOP, no closures at all): a class with (a) an UNTYPED setter parameter assigned into a typed property (`public function setExpiry($e) { $this->expiry = $e; }` where `$expiry` is declared `float`) and (b) ANY method elsewhere in the class doing an array-indexed property write (`$this->newMetadata[$k] = 42;` where `$newMetadata` is declared `array`) causes the checker/codegen to later reject a COMPLETELY UNRELATED property write with "prop_set assigning PHP type Int to CacheItem::$expiry with PHP type Float" — even though `setExpiry` is never called and the int literal 42 only ever touches `$newMetadata`, never `$expiry`. Reproduced minimally in `class CacheItem { protected float $expiry=0.0; protected array $newMetadata=[]; function setExpiry($e){$this->expiry=$e;} function touch(){$this->newMetadata['k']=42;} }`. Workaround: type the setter parameter explicitly (`setExpiry(float $e)`) — this sidesteps the bug entirely (confirmed). Root cause not investigated (likely gradual param-specialization / property-refinement state keyed incorrectly, cross-contaminating two different (class,property) pairs). Not fixed — out of scope for the L2 spec's perimeter (checker inference/objects/methods.rs + inference/expr/effects.rs only, not this gradual-typing/property-refinement machinery). Worth a dedicated follow-up task.
