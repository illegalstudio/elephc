# self::CONST/parent::CONST failed with "unsupported ClassConstantFetch expression" in every

> self::CONST/parent::CONST failed with "unsupported ClassConstantFetch expression" in every class like constant initia…

self::CONST/parent::CONST failed with "unsupported ClassConstantFetch expression" in every class-like constant initializer, property default, and enum case value (not inside a method body) because eval_class_like_member_default (enum_declarations.rs) and initialize_eval_enum_cases only pushed the __CLASS__/__TRAIT__ magic scope via push_class_like_member_magic_scope, never context.push_class_scope. resolve_eval_static_class_name's self/parent arms (class_resolution.rs) read current_class_scope(), which is populated only by a live method-call frame, so it was empty during class declaration and object construction. This blocked the Symfony --web campaign at symfony/http-foundation/Request.php's `private const FORWARDED_PARAMS = [self::HEADER_X_FORWARDED_FOR => 'for', ...]` (reported against line 30, a docblock comment -- the real failing site is the FORWARDED_PARAMS array a few lines below; the line-attribution bug itself was not reproduced/fixed). Fix: push/pop class_scope alongside the magic scope in eval_class_like_member_default, and route enum case values through that same helper instead of a bare eval_expr call. This also exposed two previously-unreachable shapes now that self:: works there: (1) static:: has no meaning in these compile-time-constant positions and php refuses it as an uncatchable compile error ("static::" is not allowed in compile-time constants) -- a new context.compile_time_constant_depth counter (push/pop_compile_time_constant_context, in_compile_time_constant_context) lets resolve_eval_static_class_name's "static" arm refuse it instead of silently falling back to current_class_scope() (which would wrongly answer the same as self::, a silent wrong-value hole); (2) a self-referencing constant initializer (`const A = self::B; const B = self::A;`) now recurses through eval_class_like_constant_cell without a cached cell to stop it -- a new evaluating_class_constants HashSet<(class,name)> guard (begin/end_class_constant_evaluation) detects the reentry and raises php's own catchable `Error: Cannot declare self-referencing constant self::X` via eval_throw_error instead of a Rust stack overflow. This is a THIRD, unrelated neighbor to edb4c2046f (class-constant fetch aliased its shared cell instead of copying) and d1872bebd1 (covariant native return had no resolution branch) in the same self/parent/static resolution family -- the class-scope stack was simply never pushed outside a live method-call frame. Verified: 6 new interpreter tests in crates/elephc-magician/src/interpreter/tests/class_constants.rs, full `cargo test -p elephc-magician --lib` baseline unchanged (documented two pre-existing failures only), and the differential harness against php -n 8.5.6 for self/parent/static in const initializers, property defaults, param defaults, class-name fetches, and the cyclic-constant refusal.
Evidence: cargo test -p elephc-magician --lib class_constants:: -> 27 passed, 0 failed (6 new); full lib suite unchanged from documented baseline (only execute_program_catches_throwable_without_variable_inside_eval and execute_program_finally_return_overrides_uncaught_throw remain failing); PROBE_FILE=$R/sf404.php $R/main progressed from dying inside vendor/symfony/http-foundation/Request.php to reaching stage:request and failing later inside $kernel->handle() on an unrelated InvalidArgumentException about the environment name.
Verified by: cargo test -p elephc-magician --lib; php -n differential gate against php 8.5.6 for cc1, cf1-cf7, and 13 new self/parent/static probes (sc1-sc13)
