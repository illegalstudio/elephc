# Running a linux-x86_64 oracle locally on an AArch64 host with a persistent cargo volume

> Get a linux x86 64 oracle on an AArch64 Mac in minutes instead of a 40 minute CI round trip. Run the image elephc tes…

Get a linux-x86_64 oracle on an AArch64 Mac in minutes instead of a 40-minute CI round trip. Run the image `elephc-test-linux-x86_64` (built by ./scripts/test-linux-x86_64.sh) detached, with three mounts: the worktree bound at /app so host edits are picked up with no copy step, the session scratchpad bound at /probe so probe files and the driver script stay editable while the container runs, and a PERSISTENT named volume at /cargo-target with CARGO_TARGET_DIR pointing at it. Read progress with `docker logs`, never interactively, because the builds outlast any single tool call.

The named volume is the whole trick. Emulated amd64 pays about 35 minutes for a cold compiler build and another long haul for a test binary; with the volume that is paid once and every later run is incremental. Deleting the volume is what makes people conclude the approach does not work.

Drive it from a small sh script in the scratchpad rather than a long `docker run` command line, so the next iteration is an edit rather than a re-type. Two shapes have earned their keep: one that compiles and runs .php probes through the freshly built compiler in BOTH modes, legacy first (a defect this branch introduced usually breaks legacy too, so legacy is the first question and not an afterthought), and one that runs the exact cargo test filters the CI shard reported.

The trap that costs the most time: when localizing a SIGSEGV, build ONE BINARY PER HELPER. A buffered stdout loses whatever it still holds when the process dies, so the last PASS line printed is NOT the last check that ran, and a single probe binary covering 29 checks will point at the wrong one.

Why it is worth the setup: every x86-only defect on spike/runtime-ctx-register was invisible on the host — the movzx rsid size-suffix bug, the preg orphaned publish, five user-codegen SIGSEGVs, the DoublyLinkedList pad-into-rax, the vsprintf frame. CI tells you a test name; this gives you a shell.
Evidence: Used throughout spike/runtime-ctx-register: 29 micro-probes x 2 modes isolated five ctx-only SIGSEGVs (all callback-invoking array helpers; legacy versions of the same five passed), which is what produced the zero-tolerance user-codegen scan. docker inspect elephc-x86-tests confirms image elephc-test-linux-x86_64, /app bound to the worktree, /probe to the scratchpad, /cargo-target on volume elephc-x86-ctx; the cold build in that container took 35m09s.
Verified by: docker inspect elephc-x86-tests; docker volume ls | grep elephc-x86-ctx; the container's own build log (Finished dev profile in 35m 09s)
