# PHP's `$matches` is an ORDERED HASH: each group name is written immediately BEFORE its numeric key, PREG_OFFSET_CAPTURE replaces every entry, and PCRE2 owns the name table — never recount groups by hand

Three rules that any work on the preg family has to respect, each learned from a silent divergence. FIRST, `$matches` is not a list with extra keys: PHP writes a group's NAME immediately before the numeric key it doubles, so `preg_match('#^(?P<k>\w+): (?P<v>\d+)$#', 'a: 1', $m)` yields the order 0, 'k', 1, 'v', 2 — an order observable through foreach, array_keys and var_export. Appending the names at the end would give the right values with the wrong order, which is a false win. The array must be built as a hash of n*2 entries, the exact shape a PHP string literal array produces, with each capture PERSISTED TWICE (one owner per key, never a shared pointer), and the compiled pattern must be kept alive until the array is built because the name bytes live inside it. SECOND, PREG_OFFSET_CAPTURE does not ADD anything: it REPLACES each entry with a [text, offset] pair, so those pairs are Mixed hashes (two different tags) and always hash storage — an indexed array of strings cannot hold an array. The name-before-number rule still applies, and a named group gets TWO independent pairs. Ignoring the flag once made `$m[0][1]` read the second BYTE of the subject and return 0, which silently turned every Symfony YAML scalar followed by a comment into an empty substring. THIRD, ask PCRE2 for the group names; do not recount groups from the pattern text. `(?:`, an escaped parenthesis, a character class containing a parenthesis and lookbehind all break hand counting silently, PCRE2 has already done the analysis, and it covers all three name syntaxes. The shim (src/native_deps/recipes/pcre2_shim.c) exposes the name count and per-index name, reached through the POSIX wrapper's regex_t and pcre2_pattern_info. CRITICAL: any edit to that shim requires bumping recipe_revision in src/native_deps/catalog.rs (and the dispatcher and elephc.lock) — otherwise the cached archive, which lacks the new symbols, is reused and your change appears to do nothing.
