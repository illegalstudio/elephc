# Compiled autoload unregistration must remove callbacks from the request global owner queue

> The compiled spl autoload unregister path currently evaluates its argument and emits true without removing a callback…

The compiled spl_autoload_unregister path currently evaluates its argument and emits true without removing a callback. This is a stub, not PHP support. AOT registration meanwhile creates an independent request-retained eval context for each registration. The eval registration deduplication and unregistration helpers search only their current context, although class loading merges callbacks from all request owners. Replacing the compiled stub therefore also requires request-global callback identity, removal, ordering and lifetime handling; forwarding unregister into another empty context is not sufficient. Do not infer that this explains all memory exhaustion, and do not present an increased heap as a semantic correction. Stock web acceptance requires an actual response containing the default Welcome to Symfony page with HTTP 404, not merely successful compilation.
Evidence: Static inspection confirms the unconditional true in lower_spl_autoload_bool. The r150 worker trace shows the autoload queue growing to 57 entries and reaches RegisterServiceSubscribersPass before exhausting its 32 MiB heap without returning HTTP bytes. r150 compilation succeeded in 476.85 seconds, producing a 115 MiB executable and 832 MiB assembly. The PHP source reference is php-8.5.6 peeled commit fcc29c8d6d6ee6f5ba2d941f0a2a6ea6aa6ee633, ext/spl/php_spl.c. No autoload implementation fix or passing unregistration regression is claimed yet.
Verified by: Source inspection, successful compile followed by failed HTTP execution, and bounded worker trace
