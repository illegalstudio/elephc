# Borrow existing string bytes at the eval Rust boundary instead of detaching an ownerless copy

> RuntimeValueOps::string bytes copies the runtime byte view immediately into a Rust Vec. The generated byte view wrapp…

RuntimeValueOps::string_bytes copies the runtime byte view immediately into a Rust Vec. The generated byte-view wrapper previously called mixed_cast_string, whose string branch detaches an owned payload using str_persist. No consumer owned or released that detached allocation. Even debug tracing leaked because runtime_object_class_name passes through string_bytes. Both ABI wrappers now call the shared mixed_unbox, which already peels nested Mixed wrappers, borrow an existing string payload until Rust copies it, and retain the shared value_cast_string fallback for non-string conversion. This changes neither PHP string values nor the C ABI signature; it preserves the original input owner's lifetime. Non-string conversion lifetime paths still require their own audit.
Evidence: Reduced same-binary getName/getConstructor probes retained one 48-byte block per invocation, while a scalar assignment or pure return stayed stable. Trace-enabled sixteen-call run added sixteen more blocks. eval_string_bytes_borrows_unboxed_strings_on_both_targets passed; test_eval_string_bytes_metadata_reads_do_not_accumulate_copies passed together with all four eval_assignment tests. Full Reflection and HTTP acceptance are separate gates.
Verified by: Two-ABI emitter unit test, native macOS ARM64 differential heap test, and traced/untraced reduction, September 7 2026.
