# An array property promoted to hash storage must reach the eval bridge with its LIVE kind, not the tag frozen from the declared type

> Commit 37a2d86704. The first string keyed write from interpreted runtime included code promotes an empty INDEXED arra…

Commit 37a2d86704. The first string-keyed write from interpreted (runtime-included) code promotes an empty INDEXED array payload of an `array` property to hash storage in place — the property STORE path already accepts either shape in an `array` slot. But the eval-bridge property GETTERS (`emit_aarch64_box_property_slot` / `emit_x86_64_box_property_slot` in `src/codegen/eval_property_helpers.rs`) boxed with `runtime_value_tag(slot.ty)`, a tag frozen at compile time from the DECLARED type, so every later read handed the interpreter a tag-4 (indexed) Mixed cell wrapping a hash; `__rt_mixed_array_set` then took the indexed path and re-ran `__rt_mixed_cell_promote_to_hash` over an already-promoted payload, reading hash header words as elements and rewriting entry 0 as `int(0) => int(5)`. Reproducer: `class Bag { public array $items = []; }` with a runtime-included file doing `$bag->items["b"] = 2; $bag->items["a"] = 1;` then `count`/`array_keys`/`foreach`/index reads: php `2;b,a;b=2,a=1,;21`, elephc before `2;0,a;0=5,a=1,` + `Undefined array key "b"`. Fix on the producer side: box through `__rt_mixed_from_array_kind`, which reads the live heap kind — the helper `emit_box_current_value_as_mixed` already uses for `Array` and the rule the store path encodes; null/sentinel-safe because `__rt_heap_kind` reports 0 outside the managed heap. Tests in tests/codegen/eval.rs (`test_eval_bridge_string_key_writes_into_an_empty_array_property_stay_keyed`, `…_reads_an_array_property_promoted_to_hash_storage`, `…_nested_includes_register_services_under_string_keys`), --heap-debug clean. This was a real silent corruption on the Symfony request path (container service registration under string keys) but NOT the request's SIGSEGV. TEST TRAP discovered alongside: `include "literal.php"` of a file the test creates at runtime is currently a silent no-op in elephc (a variable path such as `__DIR__ . "/p.php"` works), so eval-bridge tests must use a computed path or they pass vacuously.
Evidence: Fails-before/passes-after verified by rebuilding the pre-fix compiler in pristine directories; php -n oracle; --heap-debug allocs=frees=26; filter sets eval_bridge 11/11, nullable 5, runtime_gc 37, locals_retype 8, references 3 identical to the 6e987c8993/ab1c5436e5 baselines.
Verified by: commit 37a2d86704; value tests; php -n
