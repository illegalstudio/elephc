# Two hazards that make a compiled-path measurement a reading of old code

> A reported finding "the compiled bridge never reaches the undefined variable warning branch" was WRONG. The warning d…

A reported finding -- "the compiled bridge never reaches the undefined-variable warning branch" -- was WRONG. The warning does fire through compiled code, correctly framed, with the right file and line. It was measured against a stale binary. Two independent hazards produce that, and both invalidate any claim made from a compiled run.

HAZARD 1: `cargo build … | head -N` SIGPIPEs the build. `cargo build --bin elephc 2>&1 | grep -E "^error" -A5 | head -6` -- `head` closes the pipe after six lines and cargo dies part-way through. It LOOKS successful (no error lines are printed, because the build never reached the point of emitting any) and the binary keeps its previous mtime. Detected by comparing mtimes: source 18:54, binary 16:23. Redirect a build to a file and `tail` it instead, and check the binary's mtime against the source's before trusting a compiled measurement.

HAZARD 2: the bridge staticlib ignores `CARGO_TARGET_DIR`. A compiled program reaches the interpreter through `libelephc_magician.a` (crate-type staticlib). With `CARGO_TARGET_DIR=…/target-dev` set on every cargo invocation, the archive the compiler actually links is still written to the PRIMARY `target/` -- observed as `target-dev/debug/libelephc_magician.a` at 18:47 and `target/debug/libelephc_magician.a` at 18:56, the latter being the one the compile used. So the second-target-dir trick that keeps concurrent `cargo test` runs from colliding does NOT isolate compiled runs: an interpreter change verified in target-dev is not necessarily in the archive the next compiled program links, and a compiled run in one lane can rebuild an archive another lane is about to link.

PRACTICAL RULES: prove an interpreter fix with a magician `--lib` test (which links the crate directly) before claiming anything from a compiled runner; when a compiled reading contradicts a passing unit test, suspect the archive before the code; do not run a compiled census while another lane is compiling, for this reason as well as disk.

SEPARATELY, the correction itself is useful: the residual `tests/lang/bison1.phpt` DIFF has two causes and neither is a missing warning -- php writes diagnostics to stdout while elephc writes to fd 2 (ordering), and php reports the realpath while elephc reported the path as given (fixed in e2f0c6629c by resolving the include path, which also corrects `__DIR__`, backtrace `file` entries and `getFileName()`).
Evidence: Source mtime 18:54 against binary mtime 16:23 after a piped build reported success. libelephc_magician.a present in both target-dev/debug (18:47) and target/debug (18:56), with the compile using the primary one. The undefined-variable warning verified firing through compiled code once the archive was current, and by a magician test asserting the resolved path.
Verified by: cargo test -p elephc-magician --lib -- 1501 passed, 0 failed. Commit e2f0c6629c; hazards written up in exec-lane/red/measurement-hazards.md.
