# Eval integer extraction must release its converted cell and avoid a textual round trip

> eval int value created an owned boxed integer via cast int, converted it to bytes, parsed the decimal text and never …

eval_int_value created an owned boxed integer via cast_int, converted it to bytes, parsed the decimal text and never released the converted cell. Each integer key normalization therefore retained one cell, and the helper has many array, filesystem, reflection and scalar consumers. It now preserves cast_int as the PHP semantic boundary, reads the resulting signed payload through raw_value_word, and releases the converted cell before returning, including when payload extraction fails. It preserves the original input owner and removes formatting, byte copying and parsing overhead. The final two cells per Reflection constructor inspection were calls through array reference-key normalization. Plain write targets independently needed optional observations to avoid allocating discarded null placeholders; repeated same-cell scope assignment is a separate ownership issue.
Evidence: eval_int_value_preserves_signed_extremes_and_input_owner passed for signed minimum, maximum, negative one, zero and one. All 11 builtins_scalars unit tests passed; 36 control_flow and 7 null_coalesce_assign tests passed. test_eval_reflection_get_constructor_result_has_balanced_ownership passed with the original complete nested-array scenario. The two-request focused web Reflection test also passed, but full stock Symfony HTTP acceptance remains open.
Verified by: Focused Magician unit tests and native macOS ARM64 differential heap/web regressions, September 7 2026.
