# The nominal-class guard borrows its operand, so a store into a nullable-object property must release the producer (destructor never ran)

> Commit 76a771f80b. class Item { function destruct { echo "D\n"; } } class H { public ?Item $p = null; } function f { …

Commit 76a771f80b. `class Item { function __destruct(){ echo "D\n"; } } class H { public ?Item $p = null; } function f(){ $h = new H(); $h->p = new Item(); }` — php prints `D` then `after`; elephc printed only `after` and left 1 live block: the `Item` was never released and `__destruct` never ran. A `?Item` slot is Mixed-repr, so `coerce_typed_assign_value` (`src/ir_lower/stmt/typed_foreach.rs`) takes the NOMINAL-CLASS GUARD arm and returns early, never reaching `box_value_as_mixed`; that guard borrows its operand and hands back its own reference (its codegen increfs precisely because its EIR result is declared owned), so nobody released the producer. The store now releases it, gated to OBJECT sources so the gradual Mixed→Mixed guard (deliberately borrowed) is untouched. Tests: 2 in tests/codegen/destructors.rs; filters destructors 0 (13→15 passing), runtime_gc 37, objects:: 17, nullable 5, references 3, locals_retype 8, foreach 8 identical. Why it matters beyond the leak: Symfony's `ServiceConfigurator` registers its definition from `__destruct()`, and a parent configurator holds the current child in a NULLABLE property released by the next `->set()` — a never-run destructor silently loses a service definition (candidate cause of `ServiceNotFoundException "secrets.local_vault"` on the cold container path; not yet measured on the request). STILL OPEN, same family, different mechanism: `f(new C())` against a `?C` PARAMETER leaks (no guard is emitted; the caller never releases the boxed argument cell); a same-shaped edit at the call-argument boundary was reverted for lack of a reproducer where it fires.
Evidence: Reproducer output php `D/after` vs elephc `after` (1 live block) before, `D/after` heap-clean after; 74 failing test names across the listed filters identical before/after.
Verified by: commit 76a771f80b; php -n oracle; --heap-debug
