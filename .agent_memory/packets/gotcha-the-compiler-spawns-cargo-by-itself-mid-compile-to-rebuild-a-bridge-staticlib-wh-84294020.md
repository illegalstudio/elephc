# The compiler spawns cargo by itself mid-compile to rebuild a bridge staticlib whose crate sources are newer than the archive, so a timing or identity gate can silently include a Rust rebuild

> linker::bridges::sources are newer than walks crates/<bridge and, when any source there is newer than the archive tar…

linker::bridges::sources_are_newer_than walks crates/<bridge> and, when any source there is newer than the archive (target/<profile>/libelephc_<bridge>.a, e.g. libelephc_magician.a), runs cargo from inside the elephc invocation to rebuild that staticlib before linking. Two consequences measured on 2026-09-05 while landing the parallel-assemble patch: (1) "one cargo at a time on this target/" cannot be enforced by agents alone, because the product spawns its own cargo, and a build's --timings can include a bridge rebuild; (2) an identity gate that compares two linked binaries is contaminated when another agent edits a bridge crate between the two compiles: the diff was 8.9 M bytes, every differing symbol a GCC_except_table* landing pad from the Rust archive, __text +1080 and __eh_frame -412, while the user object's .s was byte-identical. Freezing the archives (touch target/release/libelephc_*.a after the last intended rebuild) restores byte-identical N=1 compiles. Practical rule: run identity/timing gates in a worktree nobody else edits, or freeze the archives and say so in the report; compare the emitted .s (user object) separately from the linked binary so an archive change is attributed to the archive.
Evidence: Perf agent report 2026-09-05 13:50: libelephc_magician.a rebuilt at 13:44 during the §6.1.1 gate after the échelon 37 agent edited crates/elephc-magician; first HEAD-vs-N=1 comparison differed by 8.9 M bytes in GCC_except_table* symbols only; after touching the archives, two N=1 compiles were byte-identical.
