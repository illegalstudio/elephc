# The eval bridge emitted a constructor helper for all 25 builtin throwables and allocation metadata for eight, so a runtime-included `throw new RuntimeException` was a fatal; and class_exists never ran the autoloaders

> Commit 50cfc339de, 16 files. Three mechanisms, all generic PHP semantics, found while the Symfony web request died 18…

Commit 50cfc339de, 16 files. Three mechanisms, all generic PHP semantics, found while the Symfony web request died 186 s into the cold container build with the six-word message "Fatal error: eval() runtime failed" (bridge status 2, RuntimeFatal).

ROOT CAUSE, and it is an asymmetric gate with both halves already in the tree. Constructing a class through the eval bridge needs two things: a constructor helper, and something to allocate. codegen/eval_constructor_helpers.rs emits a constructor helper for every name in BUILTIN_THROWABLE_CONSTRUCTOR_CLASSES (25 names) whenever module.required_runtime_features.eval_bridge is set. The allocation half is codegen/runtime_metadata/classes.rs seed_runtime_throwable_class_names, whose result becomes allowed_class_names in codegen/mod.rs, which is what codegen_support/runtime/data/user.rs retains before emitting the _classes_by_name table that __rt_new_by_name linearly scans. That half seeded eight throwables unconditionally, five more only when an SPL container class was present, ReflectionException only when ReflectionClass was, and three (ArgumentCountError, AssertionError, UnhandledMatchError) under the eval_bridge gate. Any other builtin throwable allocated null; RuntimeValueOps::new_object in runtime_hooks/ops/construction_raw.rs maps a null allocation to EvalStatus::RuntimeFatal; and the interpreter reported a fatal where PHP throws a catchable Throwable that the very next catch in the same file would have taken. The seeder now reads BUILTIN_THROWABLE_CONSTRUCTOR_CLASSES under the same eval_bridge gate the constructor side uses, and the three special-cased names join that rule, so the two halves cannot drift apart again.

THE SEED ALONE CHANGED NOTHING, because every insert is guarded on module.class_infos.contains_key and the CHECKER had never registered the classes. types/checker/builtin_class_gate.rs throwables_to_register widened to the whole family for three reasons: eval, unserialize, and new with a computed class name. The fourth was missing and belongs beside them: an include or require whose path is not a string literal. Such a file is chosen at run time and executed by the same interpreter, and a throw inside it names a class no walk over the compiled program can see. A new prelude_prune::usage flag includes_runtime_php records it, set by both StmtKind::Include and ExprKind::IncludeValue when the path is not a StringLiteral. It is deliberately separate from introspects, which disables prelude pruning outright; only the throwable gate reads the new flag.

SECOND MECHANISM, measured on the way. The interpreter class_exists never consulted the autoloaders at all: it checked eval declarations, then the AOT name table, and stopped. PHP's second parameter defaults to true, the loaders run inside the call, and a loader that throws makes class_exists THROW rather than answer false. Symfony ClassExistenceResource depends on exactly that: it registers a temporary loader whose only job is to raise ReflectionException for a class it cannot provide, and it catches that at the call site. class_exists now runs the SPL chain on a miss unless the autoload argument is false, then asks the class question again rather than trusting the chain's boolean, because that boolean answers for any class-like symbol.

THIRD, the two anonymous bridge fatals. A fixed string in the generated assembly can name neither the file, the line, nor what the interpreter was doing, so emit_eval_status_check now calls a new exported __elephc_eval_report_runtime_fatal and only exits; the bridge writes the message, keeping the old constant as its prefix so every caller that reads the old diagnostic still reads it. A thread-local note in magician errors.rs carries the cause, first writer wins, cleared whenever a statement list runs to completion so an absorbed failure cannot be printed beside an unrelated fatal later. The line is dropped while an included file is executing: a context call site is the eval or include that started the fragment, so for an include it is the top of the file rather than the failing statement, and printing line 1 would be worse than printing nothing.

TWO GOTCHAS FOR THE NEXT SESSION. A bridge symbol called from generated assembly must go through emitter target extern_symbol, not a bare label: the first attempt linked with an undefined symbol on arm64 because Mach-O prepends an underscore. And the fix UNMASKS a new blocker in the Symfony request, because class_exists now autoloads and therefore parses far more of vendor than before.
Evidence: Five reducers against php -n 8.5.6, before then after. A throwing autoloader plus new ReflectionClass in a runtime-included file: php prints caught ReflectionException Class Missing38C not found then after then done and exits 0; before, elephc printed Fatal error eval runtime failed and exited 1; after, identical to php. The same loader with class_exists: php propagates the exception, before elephc answered bool false with the loader never called, after identical to php. A non-throwing loader: php prints the loader line once for class_exists with one argument and never for the two-argument false form, before elephc never called it, after identical. Five builtin throwables constructed from an included file: before, fatal at the second class, after all five caught. An uncaught one: after, php prefix on standard output with exit status 255. Filter sets, run on the working tree and again with every edit reverted to the committed tree, identical name for name: autoload 1 failing (psr4 hash context late prelude), exception 8 failing (four eval reflection constructor rows, two eval_closures callable-array rows, builtin exception message api, runtime_gc escaped caught exception), include 4 failing (two eval fragment include rows, dynamic include global scope, include_paths respecialize). spl_autoload 18 pass, class_exists 13 pass, eval_bridge 13 pass, destructors 44 pass, zero failing in each. Six new tests pass by name plus one checker unit test. The magician crate suite aborts on a stack overflow in execute_program_static_call_dispatches_runtime_method_hook with a 128 MB stack, proved pre-existing by running that test with every magician edit reverted. Cost measured: _classes_by_name grows from 17 entries to 34 on the reducer; the Symfony web binary holds 628 entries and is 108,284,200 bytes against 108,927,832 for the previous build.
