# A hash bucket has no shape for TaggedScalar (?int/?bool/?float): a hash carries one static

> A hash bucket has no shape for TaggedScalar ?int/?bool/?float : a hash carries one static value tag for the whole tab…

A hash bucket has no shape for TaggedScalar (?int/?bool/?float): a hash carries one static value tag for the whole table plus two payload words per entry, but TaggedScalar keeps its runtime null tag in a separate register beside the payload. `hash_bucket_value_type()` in src/codegen/lower_inst/hashes.rs maps TaggedScalar element types to Mixed (boxed cell) at both hash_new's allocation (hash_value_type_tag) and hash_get/hash_set's value-type read (assoc_value_type), so allocation and materialization agree. Without this, `["a" => $x]` with a `?int` $x panicked the compiler in hash_new via `runtime_value_tag(TaggedScalar)` (unreachable!() in value_boxing.rs). isset()'s hash-offset-missing check (src/codegen/lower_inst/builtins/isset.rs, emit_isset_hash_offset_missing_result) independently re-derived the element type and had the same bug: it compared the bucket's tag against 8 while the bucket actually holds tag 7 (boxed Mixed), so `isset($m['a'])` silently answered "set" for a null. Separately: `f(new C())` against a `?C` parameter boxes the argument for the Mixed ABI and runs the nullable nominal guard over that box; the guard FORWARDS the same cell (value_is_borrowed_gradual_nominal_guard), so post-call cleanup (which only asks about the argument itself) released nothing and the object's destructor never ran. Fixed by `LoweringContext::owning_box_behind_borrowed_nominal_guard` (src/ir_lower/context.rs) which recovers the box the ARGUMENT EXPRESSION itself minted (never a box borrowed from a callee's own parameter, e.g. parent::__construct forwarding its value) and src/ir_lower/expr/nullable_method_calls.rs releases it. Still open: `hash_get` reading a TaggedScalar-valued hash entry directly (e.g. `$m["a"]` as a value expression, not via foreach) fails with "unsupported EIR backend feature: hash_get value PHP type Mixed with result PHP type TaggedScalar" (require_hash_get_result in hashes.rs has no arm for value_ty=Mixed + result_ty=TaggedScalar) — foreach and var_dump($m) work because they go through different codegen paths (box_tagged_hash_payload_as_mixed in iterators.rs). Committed 8600e6af6b on reconcile/dirname-symfony.
