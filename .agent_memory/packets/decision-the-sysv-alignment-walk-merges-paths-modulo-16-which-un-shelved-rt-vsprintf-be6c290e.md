# The SysV alignment walk merges paths modulo 16, which un-shelved __rt_vsprintf

> The SysV call alignment audit src/codegen support/runtime/sysv call alignment.rs used to merge control flow paths by …

The SysV call-alignment audit (src/codegen_support/runtime/sysv_call_alignment.rs) used to merge control-flow paths by EXACT rsp offset from the helper entry, and declared a helper unanalyzable whenever two paths reached one instruction at different depths. That is stricter than the rule it enforces: System V asks only which 16-byte boundary rsp sits on, so paths differing by a multiple of 16 never disagreed about alignment. Comparing `offset.rem_euclid(16)` instead makes the walk correct AND strictly more capable.

Concretely it bought back `__rt_vsprintf`, which reaches its formatting tail at -72 or -88 depending on whether the record loop ran (both 8 mod 16). Because it sat in NOT_STATICALLY_ANALYZABLE for that non-disagreement, nothing objected when the rbx-preservation work on spike/runtime-ctx-register took its frame from `sub rsp, 64` to `72`, flipping every call in its body onto the forbidden boundary — the float path reaches snprintf, whose first aligned SSE spill faults. That cost a day of emulated-amd64 container bisection. With the merge in place the audit prints the helper, the callee, the line and the boundary directly.

The lesson generalizes beyond this module: an analysis that gives up on a disagreement should first check whether the disagreement is about the property it actually measures. Every entry on a "cannot analyze" allowlist is a place where a future change goes unchecked, so the allowlist is a liability and shrinking it is worth more than adding another targeted test beside it.

The merge rule itself is pinned by three tests feeding a synthetic two-path helper to `analyze()`: -72/-88 merges with no finding, -72/-80 is still REFUSED (and the refusal text names boundaries, not depths), and -88/-104 merges and reports the call at 0 mod 16. Without that third case a too-generous merge would silently wave through the exact class the module exists to catch.
Evidence: Negative control run in-session: `sub rsp, 80` was temporarily set back to the broken `sub rsp, 72` and the audit failed with "__rt_vsprintf calls __rt_sprintf_pack_mixed at line 10602 with rsp -80 bytes past its entry (0 mod 16, needs 8)", then the correct frame was restored and all tests went green. `the_unanalyzable_allowlist_shrinks_only` independently demanded the NOT_STATICALLY_ANALYZABLE entry be deleted once the merge landed.
Verified by: cargo test --bin elephc sysv_call_alignment (9 passed, up from 6)
