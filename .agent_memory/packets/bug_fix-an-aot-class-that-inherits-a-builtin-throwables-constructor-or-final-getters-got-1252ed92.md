# An AOT class that INHERITS a builtin Throwable's constructor or final getters got no eval slot, and the bridge fatalled where PHP constructs

> A builtin Throwable's construct and its four final getters getMessage/getCode/getFile/getLine have NO EIR body: AOT n…

A builtin Throwable's `__construct` and its four final getters (getMessage/getCode/getFile/getLine) have NO EIR body: AOT `new Exception(...)` lowers to a runtime helper, never to an `Exception::__construct` function. `collect_class_constructor_slot` (src/codegen/eval_constructor_helpers.rs) and its method-side twin only build a slot when `emitted_methods` contains an EIR body for the IMPLEMENTING class, so a class that INHERITS those members can never get a slot. Such a class then matched NEITHER dispatch: not the compact builtin-id dispatch (its own class id is not one of the 25 builtin ids) and not the slot table. The generated helper ends with "a resolved target must match one generated constructor slot" -> jump to fail -> `__elephc_eval_value_construct_object` returns 0 -> `EvalStatus::RuntimeFatal`.

FIX: both `collect_builtin_throwable_constructor_class_ids` and `collect_builtin_throwable_method_class_ids` now also add the class id of every class whose `method_impl_classes` entry for the member resolves to a builtin throwable. Running the builtin initializer/getter for them is CORRECT, not a fallback: PHP resolves `new AotEx($m)` to `Exception::__construct`, and the object carries the inherited throwable fields at the same offsets because it descends from the builtin.

WHY SHADOWING IS SAFE on the method side, and this is the argument that licenses routing by class id: the builtin method dispatch runs BEFORE the slot dispatch, so it would hide a subclass override -- but the only methods it answers are the four in BUILTIN_THROWABLE_SCALAR_GETTERS, and php-src declares every one of them `final`. Adding a non-final method to that table breaks this argument.

THE SHAPE THAT REPRODUCES, and four that do NOT: the class must be compiled AOT and must declare no constructor of its own, and the construction must come from eval-bridge code. An eval-DECLARED subclass of a builtin throwable takes a different path and passed throughout; so did a 3-level chain bottoming out in an SPL exception, a --web build, and a runtime-written include. Also note stripped binaries make `nm` symbol counts meaningless -- elephc strips by default, so measure with --keep-symbols or you will read 0 eval symbols in a binary that is full of them.

This is the same mechanism recorded as DEFERRED for `getPrevious()` in repo:lazy-petting-popcorn:gotcha:deferred-found-but-not-fixed-an-eval-declared-subclass-of-a-native-throwable-cal; the constructor half was never separately recorded.
Evidence: Reducer (scratchpad red3, 25 lines): main.php declares `class AotEx extends InvalidArgumentException {}` plus an unrelated AOT class with a constructor, and includes a file through `getenv('PROBE_INC')`; the included file does `throw new AotEx("boom")` and catches it. php -n 8.5.10 prints `widget:x / caught:AotEx:boom / after` exit 0. Before the fix elephc printed `Fatal error: eval() runtime failed: unsupported NewObject expression ... on line 5` exit 1, with trace `native_constructor stage=resolved requested="AotEx" declaring="Exception" args=1 / stage=signature details=Some((3,3,0,true)) / stage=bound args=3 / native_constructor_error stage=construct class="Exception" status=RuntimeFatal` -- byte-for-byte the shape Symfony produced for EnvNotFoundException at EnvVarProcessor.php:224. With only the constructor half fixed it printed `caught:AotEx:` and then died on `$e->getMessage()` with `unsupported MethodCall expression`. With both halves it matches php exactly, exit 0. Adding a bare `new Exception` to the AOT side did NOT fix it, which is what proved the builtin constructor has no EIR body at all. Regression test test_runtime_included_code_constructs_an_aot_class_inheriting_a_builtin_throwable_constructor in tests/codegen/eval.rs: FAILED on the tree with the two fixes reverted, ok with them. Focused slice `cargo test --test codegen_tests exception` with RUST_MIN_STACK=33554432: 145 passed, 2 failed, and both failures (test_builtin_exception_message_api, test_regression_escaped_caught_exception_retained_once) reproduce identically on the untouched tree, so they are pre-existing reds.
Verified by: php -n 8.5.10 as oracle on the red3 reducer; the regression test failing before / passing after with the fixes reverted and reapplied; cargo test --test codegen_tests exception (145/147, 2 pre-existing reds confirmed on a pristine tree)
