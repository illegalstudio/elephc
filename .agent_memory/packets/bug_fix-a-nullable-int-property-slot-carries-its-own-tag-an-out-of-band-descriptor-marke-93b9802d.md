# A nullable-int property slot carries its own tag: an out-of-band descriptor marker (11) folded at every descriptor read replaces the wrong "boxed cell pointer" tag 7

> Commit 6683884da4 fixes the open gotcha about ?int properties . A ?int / int|null property has codegen repr == Tagged…

Commit 6683884da4 (fixes the open gotcha about `?int` properties). A `?int` / `int|null` property has `codegen_repr() == TaggedScalar`: payload at `offset`, its own runtime value tag (0 = int, 8 = null) at `offset+8`. The per-class descriptor tables carry ONE static tag per property and `prop_value_tag` (`src/codegen_support/runtime/data/user.rs`) fell through to 7 = "boxed Mixed cell pointer", so every whole-object reader (`(array)`, `get_object_vars`, `var_dump`, `print_r`, `var_export`, `json_encode`, `serialize`, `==`) took the raw payload for a cell address and `__rt_mixed_unbox` dereferenced `NULL_SENTINEL` — the per-request SIGSEGV of the Symfony fixture (`Definition::__serialize()` iterating `(array) $this` over `?int $decorationOnInvalid`). Design: no value in 0..=10 can describe that slot, so it gets an out-of-band descriptor marker `PROP_DESC_TAG_TAGGED_SCALAR` (11, `src/codegen_support/sentinels.rs`), and every reader folds it away with `emit_resolve_prop_desc_tag` — three branch-free instructions (`cmp`/`csel`/`csel` on aarch64; `cmp`/`mov`/`cmove`/`cmove` on x86_64) that adopt the slot's own tag word and clear the high word — placed AFTER the uninitialized-property check, which reads the same word. Folding at the descriptor read was chosen over a shared boxing wrapper because the direct-render readers never box. The gc descriptor gets tag 0 instead (a tagged scalar owns nothing; tag 7 had been handing a PHP int to `__rt_decref_any` on every object release). Two more divergences fixed by the round trip: `unserialize` now writes BOTH words of such a slot (`N;` no longer read back as PHP_INT_MAX-1) and no longer writes a bare NULL_SENTINEL into a boxed-Mixed slot (`unserialize(serialize($o))->x === null` segfaulted for an untyped or `?float` property); `var_dump` prints `uninitialized(?int)` rather than `uninitialized(mixed)`. Readers touched, both arches: `runtime/objects/{object_vars,print_r_object,export_props}.rs`, `runtime/io/var_dump_object.rs`, `runtime/system/{serialize,json_encode_object}.rs`, `runtime/system/unserialize/storage_{aarch64,x86_64}.rs`. Still open after this commit: `serialize` does not omit uninitialized typed properties (pre-existing, `int $i` too — the count word is emitted up front, needs a pre-pass); `["a" => $x]` with a TaggedScalar `$x` PANICS the compiler at `value_boxing.rs:35 unreachable!` (loud backend refusal via a static property); `null|int $x` (null first) fails to parse.
Evidence: 4-line reproducer: php n=NULL, elephc before n= then SIGSEGV 139, after n=NULL; 7 value tests in tests/codegen/objects/property_access/nullable_int_defaults.rs (every object reader, the cast-then-bool serialize shape, uninitialized named and omitted, heap clean), 2 in tests/codegen/serialize.rs, 1 in tests/codegen/json/encode_object.rs; filters var_dump 0, print_r 0, var_export 0, json 3, serialize 0, get_object_vars 0, object_to_array 0, cast 1, compar 2, nullable 5, runtime_gc 37, locals_retype 8, references 3 — failing names identical before/after; Symfony --web rebuilt (647 s): worker no longer dies with signal 11 (now a clean PHP fatal on the cold container path).
