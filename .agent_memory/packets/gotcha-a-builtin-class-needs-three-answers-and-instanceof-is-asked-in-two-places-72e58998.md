# A builtin class needs three answers, and instanceof is asked in two places

> The eval interpreter's interpreter/constants.rs known class list makes a class NAMEABLE, not usable: new ArrayIterato…

The eval interpreter's `interpreter/constants.rs` known-class list makes a class NAMEABLE, not usable: `new ArrayIterator([...])` succeeded and returned an object with no members, no interfaces, and nowhere to keep the array. Implementing such a class needs three independent answers, and each one is load-bearing on its own: (1) construction, intercepted in `eval_new_object_result()`; (2) the members, dispatched in `eval_method_call_result_with_evaluated_args()`; (3) the interface answer for `instanceof`.

The trap is (3): `instanceof` is answered in TWO distinct code paths that do not share an implementation -- the free function in `interpreter/builtins/symbols/is_a.rs`, and the context method `ElephcEvalContext::dynamic_object_is_a()` in `context/classlike_objects.rs`. A declared return type check such as `getIterator(): Traversable` goes through the SECOND one. Wiring only `is_a.rs` gives a class that passes an explicit `$x instanceof Iterator` test while an `IteratorAggregate` returning it throws UncaughtThrowable on the declared return type. Factor the interface list into one free function (here `eval_array_iterator_class_is_a` in `context/classlike_objects.rs`) and call it from both.

The interface answer is also load-bearing for things that look like member calls: `$it["a"]`, `count($it)`, `foreach` and `iterator_to_array()` each gate on `instanceof ArrayAccess`/`Countable`/`Traversable` BEFORE they ever reach a member. Sentinel evidence: with member dispatch disabled 5 of 6 tests fail; with the interface answer disabled all 6 do. So a complete set of members answers nothing if `instanceof` says the object is neither.

Instance state for such a class lives on the context (`ElephcEvalContext.array_iterators`), because the runtime object it is built on carries no eval-visible storage. The backing array is OWNED: retained on the way in, replaced through one helper when a write returns a different cell, and pushed into the owned-values Vec by `forget_dynamic_object` so it is released when the object dies.

Separately: `iterator_to_array()` refused anything that was not already an array. It now drains a Traversable through `eval_spread_source_entries()` -- the walker the array-literal spread already used -- rather than a second walker that could disagree with it.

Why it matters: every Symfony bag (HeaderBag, ParameterBag, AttributeBag) returns `new \ArrayIterator($this->...)` from `getIterator()`, so a dumped container running interpreted reaches this on the request path.
