# REFUTED: instanceof is NOT what lets a ServiceClosureArgument reach a string context on the Symfony --web request; every relation probe in the failing request answers exactly as php would

> Measured on the real web binary built at commit 99f98db775 990 s, 119,656,104 bytes , with the enriched ELEPHC EVAL T…

Measured on the real --web binary built at commit 99f98db775 (990 s, 119,656,104 bytes), with the enriched ELEPHC_EVAL_TRACE that now prints the receiver's identity, its eval class, its runtime class and which table decided. The cold request still dies with the same verbatim message ("Fatal error: Uncaught Error: Object of class Symfony\Component\DependencyInjection\Argument\ServiceClosureArgument could not be converted to string", worker exit 255), and the trace is 44,065 lines — byte-for-byte the same length as the pre-fix trace, i.e. the request reaches exactly the same point. The last probes before the throw name the receiver and are ALL CORRECT: identity 4456830832, runtime class ServiceClosureArgument, answers instanceof TypedReference=false, instanceof Definition=false, instanceof ArgumentInterface=true; identity 4456853328, runtime class TypedReference, answers instanceof TypedReference=true, ArgumentInterface=false, Definition=false. The final line is an Error object asked instanceof Exception = false (correct: Error does not extend Exception) — that is the uncaught-throwable path, not the cause. This REFUTES the central claim of the earlier OPEN packet ("on that value instanceof ServiceClosureArgument answered false and instanceof Reference answered true"): no instanceof answer in the request is wrong. Distribution over the whole request: 19,024 probes decided by AOT metadata, 12,424 with a null ctx that fell back to AOT (owner_lookup=missing), and only 4 decided by an eval class table — those four are compiler passes declared by the interpreter (runtime class stdClass) asked instanceof CompilerPassInterface, all true, and all seven CompilerPassInterface answers are identical before and after the fix. So the Symfony objects in this path are real AOT-constructed objects whose class ids answer correctly, and the eval-context instanceof fix, while a genuine php-conformance fix with its own reducer, changes NOTHING on this request. ALSO RULED OUT by probe, not by reading: the AOT dynamic-instanceof metadata gate class_interfaces_supported_for_dynamic_instanceof (an interface that declares a method excludes its implementors) produces no wrong answer — a three-class probe over both the dynamic `$o instanceof $name` form and the named form is identical to php -n, and classify_named_target in src/codegen/lower_inst/objects/instanceof_helpers.rs:315 reads ctx.module.class_infos directly, not the restricted dynamic set; identity reuse (an AOT object allocated at the address a just-freed eval object had) answers correctly; `!$v instanceof X` precedence and `continue` inside `if` inside `foreach` are identical to php. WHERE TO LOOK NEXT: the thrown Error is built by the object-to-string ladder added in 4c645c3838 (__rt_sprintf_mixed_to_string), which is reached from AOT-lowered string-conversion sites, so the offending `(string)`/concat/sprintf is in AOT-compiled Symfony code and its guard is an AOT instanceof that never reaches the bridge (a function that owns no eval context emits the plain AOT path and is invisible to ELEPHC_EVAL_TRACE). The next step is therefore to make the thrown Error carry a file and line, or to trace the AOT string-conversion ladder, NOT to look at instanceof again. Timing note: the fatal lands anywhere between 200 s and 652 s into the cold request depending on machine load, so a 250 s curl budget can time out (curl 28) before the fatal appears and look like a different failure.
Evidence: Enriched ELEPHC_EVAL_TRACE of one cold request on the binary built at 99f98db775: last three probes on the ServiceClosureArgument receiver read `identity=4456830832 class="|runtime=Symfony\Component\DependencyInjection\Argument\ServiceClosureArgument" decided_by=aot-metadata target="...TypedReference" result=Ok(false)`, then `target="...Definition" result=Ok(false)`, then `target="...Argument\ArgumentInterface" result=Ok(true)` — all three are what php answers. Trace totals: 44,065 lines (identical to the pre-fix trace), 19,024 decided_by=aot-metadata, 12,424 owner_lookup=missing, 4 decided_by=eval-class. CompilerPassInterface answers: 4 true / 3 false both before and after the fix, and all seven are correct by inspection of the named classes. Gate probe (three AOT classes, an empty interface and a method-declaring interface, both instanceof forms): elephc identical to php -n.
