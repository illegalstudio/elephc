# An undiagnosable failure is a grouping problem: name it at the dispatcher, first-writer-wins

> 225 of the 2556 cases in php src's language corpus ended in a bare Fatal error: eval runtime failed no phase, no name…

225 of the 2556 cases in php-src's language corpus ended in a bare `Fatal error: eval() runtime failed` -- no phase, no name, no line. The insight worth keeping is that this is not a severity or politeness problem, it is a GROUPING problem: every other bucket in the sweep (missing functions, wrong values, parser refusals by token) could be sorted into causes and worked on; this quarter could not be sorted at all, so none of it could be started. Fix diagnosability BEFORE fixing behaviour when a large bucket is anonymous.

MEASURE BEFORE ANNOTATING. `ELEPHC_EVAL_TRACE=1` already made `execute_statements` print the failing statement and `trace_class_decl_result` print the failing validation stage, so the 225 could be grouped with NO rebuild at all -- just run the corpus with the env var and extract the most specific trace line. That said which paths the corpus actually reaches (Expr 90, ClassDecl 55, StoreVar 15 ...) instead of annotating every `Err(RuntimeFatal)` in the crate. The information existed; it just never reached the user-facing message.

THE FIX SHAPE. `note_eval_runtime_failure` is first-writer-wins and the INNERMOST frame writes first as the error unwinds. That makes a fallback at a central dispatcher safe: put one in `eval_expr` (names the expression variant) and one in `execute_statements`' error arm (names the statement variant), and a path that already describes itself keeps its own message. Assert that explicitly -- `undefined constant "X"` must still read as itself; if first-writer-wins were not respected the change would make diagnostics WORSE while appearing to improve them.

Name the variant by reading it off `Debug` (`format!("{expr:?}")` split at the first `(`/`{`/space) rather than writing sixty match arms that drift from the enum. Only reached on the terminal failure path, so the cost is irrelevant.

RESTRICT THE FALLBACK TO THE STATUS THAT WAS ACTUALLY OPAQUE. All 225 were `RuntimeFatal`; `UnsupportedConstruct` reaches the user through a different bridge message that already carries its own wording (`eval() fragment uses an unsupported construct: call to undefined function error_reporting()`). Widening the fallback would double-describe the half that was never the problem.

WHEN A GENERIC FALLBACK COLLAPSES A REAL GROUP, name that group specifically. `unsupported ClassDecl statement` merged 40 distinct corpus cases into one useless bucket, so class declarations get their own note carrying the class name. It has to be attached at the DISPATCH site, not inside `execute_class_decl_stmt`: the stage helper cannot hold `context` because every call already borrows it mutably for the validation it wraps. The stage stays available through the trace.

Result: 225 opaque -> 0 opaque, 24 named groups (largest: unsupported Call 50, class <N> could not be declared 40, ClassConstantFetch 20, MethodCall 13, PropertyReferenceBind 12, DynamicCall 11). Five turned out to be `undefined constant "__COMPILER_HALT_OFFSET__"` -- already named, and previously lost.

SENTINEL DESIGN for this kind of change: the sentinel that matters is not "the string is missing" but "it degrades to the useless bucket". Removing the class naming makes the test read `unsupported ClassDecl statement`, which is exactly the failure the commit exists to fix.
Evidence: Measured on php-src tests/lang + Zend/tests (2556 cases): 225 opaque before, 0 after, regrouped into 24 named causes by re-running the same list against the rebuilt runner. Three tests in interpreter/tests/refusal_diagnostics.rs; sentinels show the expression fallback removed leaves an empty description and the class naming removed degrades to `unsupported ClassDecl statement`.
Verified by: cargo test -p elephc-magician --lib &lt; /dev/null -- 1487 passed, 0 failed, 0 filtered (built in a second CARGO_TARGET_DIR so the codegen suite kept the primary target/). Commit fd255fe20a.
