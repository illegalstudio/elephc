# OPEN: on the Symfony --web cold request a ServiceClosureArgument reaches (string) $v behind two instanceof tests that exclude it, so an instanceof answer under the eval bridge is wrong

> After the object to string fix commit 4c645c3838 the Symfony web request fails with the php correct message "Uncaught…

After the object-to-string fix (commit 4c645c3838) the Symfony --web request fails with the php-correct message "Uncaught Error: Object of class Symfony\Component\DependencyInjection\Argument\ServiceClosureArgument could not be converted to string" (worker exit 255, curl 52). In ServiceLocatorTagPass::processValue the only reachable (string) $v sits inside `if ($v instanceof Reference)` and after `if ($v instanceof ServiceClosureArgument) { $services[$k] = $v; continue; }`; ServiceClosureArgument implements ArgumentInterface and does not extend Reference, so on that value `instanceof ServiceClosureArgument` answered false and `instanceof Reference` answered true, unless the checker's narrowing or the control flow replaced the runtime test. The values come from a Mixed hash read as `$value->getArguments()[0] ?? null`; the objects are AOT classes often constructed inside runtime-included config files (interpreter-side construction through the FFI, crates/elephc-magician/src/ffi/object_construction.rs); under --web an instanceof on a Mixed value goes through the eval-bridge probe lower_eval_object_is_a (facade src/codegen/lower_inst/builtins/eval_facade.rs, implementation src/codegen/lower_inst/builtins/eval/introspection.rs) into the interpreter's eval_instanceof_object_result (crates/elephc-magician/src/interpreter/expressions/evaluation.rs) and the object_is_a method in crates/elephc-magician/src/interpreter/runtime_ops.rs. One request's ELEPHC_EVAL_TRACE=1 output has 44,065 lines, 31,456 of them object_is_a (71 %), 12,424 with owner_lookup=missing, and ArgumentInterface answered 4,029 false / 442 true; the trace carries the object's identity only on the owner_lookup=missing lines, so the proof is Symfony's source, not the trace. Candidate mechanisms to decide by reducer, not by reading: the object's class id resolved through the wrong table (AOT and interpreter class-id tables are dense and ordered differently), a default answer when the owner lookup is missing, the checker's narrowing after instanceof Reference standing in for the runtime test, or continue-inside-if-inside-foreach control flow. The 31,456 bridge probes per request are also a cost worth remembering once correctness is settled.
