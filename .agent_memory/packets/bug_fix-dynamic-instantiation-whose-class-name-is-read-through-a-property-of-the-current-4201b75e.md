# Dynamic instantiation whose class name is read through a property of the current object failed to parse, and the vendor file holding it was silently dropped from the autoload index

> Commit 369c234027 in src/parser/expr/prefix complex.rs adds new variable base. The current object keyword lexes as it…

Commit 369c234027 in src/parser/expr/prefix_complex.rs adds new_variable_base. The current-object keyword lexes as its own token kind, and the dynamic branch of parse_new_object accepted only the plain variable token kind, so an instantiation that reads the class name through a property of the current object and then an array offset fell through to the class-name path and failed to parse. The chain parser behind it already handled offsets and property accesses; only the base was too narrow. Six forms measured against php: plain variable, one offset and nested offsets were already accepted, every form starting from the current object was rejected; all six are now identical to php, pinned by a codegen value test and a parser test. Consequence on the Symfony fixture: the routing component's Router class file contains six such sites, so the whole file failed to parse and the class silently disappeared from the autoload index and the compiled program, without any diagnostic, surfacing days later as a runtime exception during the cold container build saying the router service class lacks a method that lives on its parent. Lesson: a vendor file that fails to parse, or that fails the checker (that same file now gets six checker errors: list destructuring, dynamic properties on stdClass, nullsafe on a two-interface union), must produce a build diagnostic naming the file instead of vanishing. Still open: instantiation through a static property of a class, instantiation from the current object itself (php instantiates the object's class), and ReflectionMethod getName returning a lowercased name. Filter sets identical with the fix disabled.
Evidence: Form matrix against php before and after; autoload index probe showing the Router file absent before the fix; strings on the rebuilt web binary; Symfony request verdict unchanged after the fix because the class is still outside the compiled set.
Verified by: commit 369c234027; php oracle; parser and codegen tests; Symfony rebuild and request
