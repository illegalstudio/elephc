# A promoted array must be probed by every reader, whatever its static element type

> An indexed PHP array in elephc is promoted to hash storage at RUN TIME by rt array set mixed key whenever a written k…

An indexed PHP array in elephc is promoted to hash storage at RUN TIME by `__rt_array_set_mixed_key` whenever a written key does not fit the packed 0..n-1 shape (`$a[5] = x` on a 1-element array). Promotion is decided by the KEY, never by the element type, so an `array<int>` is promoted exactly like an `array<mixed>` — a reader may not trust its static type and skip the probe.

Every reader that walks the payload therefore has to ask `__rt_heap_kind(p) == 3` (HASH) first and take the hash path when it answers yes. Before this fix seven readers walked the packed slots unconditionally and rendered a promoted array as its stale pre-promotion prefix: `var_dump`, `print_r`, `serialize`, `var_export`, `json_encode` (both the int and the dynamic encoder), `implode`/`join`, `array_values`, and `foreach` over a boxed array.

The probe is emitted per call site (~32 aarch64 instructions, ~130 bytes) rather than hoisted into a runtime helper, because the extraction is parameterised by element layout (elem_size 8 vs 16, and the append is word / string-persist / mixed-box). This matches the shape `array_values` already used. A helper-per-layout refactor (5 helpers) would buy that size back and is the obvious follow-up if implode call-site size ever matters.

Verification that actually decides it: each half of the fix needs its own assertion AND its own sentinel — reverting one half must turn exactly one test red. That is how the implode half and the array_values half were each proven to be load-bearing.
Evidence: 15 tests in tests/runtime_promoted_array_reader_tests.rs, every expectation taken from `php -n`. Three sentinel runs: reverting the implode half alone reddens exactly `implode_joins_a_promoted_array` (13 passed / 1 failed); reverting the array_values half alone reddens exactly its own case; both restored gives 14/14 then 15/15. A differential sweep of the four readers against `php -n` on a concrete-element-type probe (`$a = [1]; $a[5] = 2; $a[9] = 2`) reports IDENTICAL.
Verified by: cargo test --test runtime_promoted_array_reader_tests (15 passed), cargo test -p elephc --lib (1687 passed), cargo test -p elephc --bins (1912 passed), plus var_dump/print_r/var_export/array/ownership suites all green
