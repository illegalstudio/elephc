# The Reflection surface gate never asks whether the program includes PHP at run time

> Reflecting on a class that an autoloader's include declared dies with the eval runtime failed fatal, while the identi…

Reflecting on a class that an autoloader's include declared dies with the eval-runtime-failed fatal, while the identical code inside an eval string works. That asymmetry is the whole diagnosis, and it points away from the interpreter rather than at it.

The interpreter is correct here, and that is worth pinning rather than assuming. Run against a complete class table, it reflects on an include-declared class from the caller, reflects on it from inside the include frame that declared it, reports a declared property type and default, and handles a caller declaration made after the include. Four cases, all green. So nothing in the include path, the include frame's own call site and file magic, or the class table is at fault.

What a compiled binary lacks is the metadata. A non-literal include path is recorded as its own usage flag, separate from the flag eval sets, and the comment on that flag says outright that only the throwable gate reads it and only to widen the throwable set. The Reflection surface gate never consults it: it answers on the eval/introspection flag, on the builtins that manufacture a Reflection object, on dynamic class construction, and on Reflection class names spelled in the source. A runtime include spells nothing any static walk can read, so the fourteen Reflection classes are never registered, their descriptors are never emitted, the by-name runtime lookup answers null, the value-ops layer maps a null allocation to a fatal status, and the bridge prints the fatal. Eval works for exactly one reason: eval sets the introspection flag, which that gate does read.

This is the same failure the throwable half of the same family already fixed, one class family over. Both the runtime-metadata emitter and the throwable gate document it in prose as a runtime helper materializing a class whose metadata was never emitted, and both name a runtime include as the case that had been missing. The lesson generalises past Reflection: EVERY gate that decides which builtin class metadata to emit has to treat a runtime include the way it treats eval. Prelude pruning is the exception and stays keyed to the eval flag alone, because eval also hands over the symbol table while a runtime include only needs the construction surface widened. The SPL, datetime and generator gates read the eval flag and not the include flag, so they are worth auditing for the same hole.

Two traps for whoever writes the fixture. The include path must NOT be a string literal: a literal path is resolved and inlined at compile time, which puts the included declarations into the program the checker walks and makes the fixture prove nothing. And the entry file must name no Reflection class, call no eval, use no dynamic class construction and call no attribute-reading builtin, because each of those independently makes the gate answer true and the test then passes without exercising anything. Pair the failing case with the eval twin as a control; if the twin passes while the include case fails, the difference is the gate rather than the interpreter.

Separately, and NOT the same bug: reading a property value through a reflector returns empty, with no error and no output, for a simple one-class fragment, while a longer existing suite fixture using the same API passes. Nine shapes were measured and all nine fail, which rules out a great deal: it is not the include, not the call site, not whether the property is typed, not its visibility, not inheritance, not whether the reflector is chained off its own construction or held in a variable, not whether the object argument is built inline or held in a variable, not comma-echo versus separate echo statements, and not the value being an integer rather than a string. Reading the property directly returns the value, so the default does materialize. The empty result rather than an error is the tell: the handler bails to the not-handled branch when the reflector's identity is absent from the reflection registry, and the caller then yields nothing. A one-line reproducer: declare a class with one public property holding a string, construct it, construct a reflector for that property by class and property name, and echo the value read back.
Evidence: Oracle is php -n 8.5.6. The reduced fixture, an included file declaring a class with one typed property and reflecting on it, prints loaded;reflected;S1Plain;int;done; the compiled binary printed loaded; and then the eval-runtime-failed fatal. Four interpreter tests run that same fixture against a complete class table and all pass, which is what places the failure outside the interpreter. The gate's own source is the rest of the evidence: the usage flag for a non-literal include path carries a comment stating that only the throwable gate reads it, and the Reflection gate's predicate lists its four conditions with that flag absent from all of them. The nine measured shapes of the separate reflected-property-read finding all returned an empty string where php returns the value, including the shape run without any include and without a call site.
