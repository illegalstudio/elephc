# Pre-existing runtime GC leak in reflection.rs's "boxed-object-in-Mixed-property" idiom: em

> Pre existing runtime GC leak in reflection.rs's "boxed object in Mixed property" idiom: emit reflection parameter arr…

Pre-existing runtime GC leak in reflection.rs's "boxed-object-in-Mixed-property" idiom: emit_reflection_parameter_array (src/codegen_ir/lower_inst/objects/reflection.rs) allocates a ReflectionNamedType object, persists its __name string via __rt_str_persist, boxes the object pointer as Mixed via emit_box_current_value_as_mixed, and stores it into a property slot (e.g. ReflectionParameter::__type). This leaks: confirmed via sentinel A/B rebuild that `getParameters()[0]->getType()->getName()` on a typed parameter alone (no other reflection features touched) leaks 4 live_blocks/240 bytes for 2 calls, with the leak scaling per call. The N1 checker-bundle item-3 getReturnType() feature reuses the exact same idiom for ReflectionFunction::__return_type (emit_reflection_function_return_type) and inherits/compounds the identical leak — confirmed baseline-vs-mine comparison showed the leak doubling per ReflectionFunction construction that resolves a return type, whether or not PHP code ever calls getReturnType() (it bakes eagerly at construction like every other slot). Root cause is presumed to be in how the owning object's property-cleanup/destructor sweep (or __rt_mixed_from_value's object-tag handling) fails to recursively free a Mixed slot holding a nested object pointer — NOT specific to ReflectionFunction/ReflectionNamedType. This is a runtime ownership/GC issue, out of scope for checker/codegen-shell work; needs a dedicated GC-focused session. No heap-clean test exists yet for either ReflectionParameter::getType() or ReflectionFunction::getReturnType() because both would fail honestly — this was intentionally left undocumented as a passing test (see tests/codegen/oop/reflection.rs note above test_reflection_function_get_return_type_dynamic_throws_catchable) rather than asserting a false "clean" heap.
Evidence: Sentinel A/B heap-debug rebuild: baseline (git HEAD, before N1 item 3 changes) with `function f(int $x): string {} function reflectParams(){ $rf=new ReflectionFunction('f'); $p=$rf->getParameters(); echo $p[0]->getType()->getName(); } function run(){ reflectParams(); reflectParams(); } run();` compiled with --heap-debug shows `live_blocks=4 live_bytes=240`. Same probe rebuilt WITH the N1 item 3 getReturnType() codegen changes present (but getReturnType() never called in this probe) shows `live_blocks=8 live_bytes=480` — confirming the new code doubles the pre-existing per-call leak unconditionally.

## Verification

Sentinel A/B heap-debug rebuild: baseline (git HEAD, before N1 item 3 changes) with `function f(int $x): string {} function reflectParams(){ $rf=new ReflectionFunction('f'); $p=$rf->getParameters(); echo $p[0]->getType()->getName(); } function run(){ reflectParams(); reflectParams(); } run();` compiled with --heap-debug shows `live_blocks=4 live_bytes=240`.
