# `?array &$p = null` is a boxed Mixed cell, not an `array &$p`: every array boxed into a Mixed cell must read its kind at RUNTIME, and a static assoc literal into such a parameter still refuses to compile

> Adding ? to a by reference array parameter changes its REPRESENTATION, not just its type. function w2 string $p, stri…

Adding `?` to a by-reference array parameter changes its REPRESENTATION, not just its type. `function w2(string $p, string $s, array &$m)` gives `m: Heap(Array) php=array<mixed>`, while `function w1(string $p, string $s, ?array &$m = null)` gives `m: Heap(Mixed) php=array<mixed>|null`. Every array written into such a parameter therefore crosses a boxing boundary (array_to_mixed / a mixed-from-value helper carrying a container tag) and crosses back at write-back. The 30-second test that settles which one you are looking at: `--emit-ir` and read the parameter's type — Heap(Array) or Heap(Mixed); the second obliges you to CLASSIFY the storage at run time on both sides. Two distinct defects come out of that one mechanism. The first is fixed for preg_match: the boxing site wrote a hardcoded "indexed" container tag, so a hash was read back as a dense list — right values, keys lost, no error at all — and the fix classifies at run time (read the heap kind, choose the hash tag). The general rule to carry forward: ANY boxing of an array into a Mixed cell must read the kind at runtime; a hardcoded container tag is a silent failure the moment the producer can return the other representation, and other sites still box with a hardcoded tag. The second is still OPEN, but at least it is LOUD: assigning a statically typed associative literal into such a parameter — `function f(?array &$m = null): void { $m = ['a' => 1, 'b' => 2]; }` — is refused with `EIR backend error: unsupported EIR backend feature: array_to_mixed for PHP type AssocArray { key: Str, value: Int }`. It refuses to compile rather than producing a wrong result, so it is a gap to close, not a bug to hunt. Note that this is the shape real framework code uses: Symfony never calls preg_match directly, it goes through a wrapper declared `?array &$matches = null`.
