# Eval array insertion must settle temporary element owners and generated key cells

> The eval array setter borrows its key and retains the element for storage. A non object append statement therefore mu…

The eval array setter borrows its key and retains the element for storage. A non-object append statement therefore must release its generated integer key and any owned RHS result after insertion, while preserving a borrowed variable alias. Indexed literal construction must likewise release generated keys after reference binding and settle scalar as well as container temporary results. Retaining the RHS temporary stranded the entire nested object graph, even after the destination array was destroyed. Dedicated heap comparisons must hold the executable, eval activation count, argument count and argument lengths constant; process-level eval state prevents an unconditional empty-heap assertion from isolating this mechanism. Associative literal keys, other mutation forms and error cleanup still need separate audit; this packet does not certify those paths or full HTTP acceptance.
Evidence: The append destructor test produced abdc before the fix versus PHP output dabddc; after the fix test_eval_array_append_releases_owned_values_and_preserves_borrowed_values passed. test_eval_indexed_array_literal_releases_generated_keys passed with equal live heap summaries for one versus four nested arrays in the same binary. Reflection differential dropped from 85 to 12 then 10 extra blocks per inspection, but remained failing at that checkpoint.
Verified by: Focused native macOS ARM64 regressions and PHP CLI output comparison on September 7, 2026.
