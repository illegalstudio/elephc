# The interpreter now carries an `owned` flag on evaluated call arguments and releases owned cells after the call (spread elements, `new`/literal positional args, variadic packing, coercion, array-literal elements)

> Commit f64ece2904 crates/elephc magician/src/interpreter/ , 21 files, +613/−44 . Ownership table: a positional variab…

Commit f64ece2904 (`crates/elephc-magician/src/interpreter/`, 21 files, +613/−44). Ownership table: a positional variable argument is BORROWED (the caller scope owns); `f([new T])`, `f(new T)`, `f(clone $x)` produce OWNED fresh cells that were never released; `f($a[0])`/`f($o->p)` produce owned cells (STILL not released — provenance unverified, open); a spread element read by `append_unpacked_call_arg_values` via `values.array_get` is OWNED on every path (`src/codegen_support/runtime/objects/mixed_array_get.rs`: increfs a stored boxed cell or freshly boxes a typed slot), was bound `ScopeCellOwnership::Borrowed` and never drained; `call_user_func_array` elements likewise; variadic packing via `values.array_set` takes its own ref (`__elephc_eval_value_array_set` increfs) so the value's debt is settled at the store; parameter coercion may return a NEW cell and abandoned the old handle; array-literal elements were never released after the store. Releasing at the read is wrong (a fresh cell from a typed slot would hand the callee freed storage), so one `owned: bool` on `EvaluatedCallArg` and `BoundMethodArg` carries the debt to the natural release points: `native_execution.rs` (`BoundNativeFunctionArgs::owned_temporaries`, after `release(arg_array)` and write-back), `native_method_execution.rs` (instance, static), `native_constructor_defaults.rs`, `closure_execution.rs` ×2, `dynamic_method_execution.rs` ×2 — each guarded against the returned handle (a callee may hand back the very cell it was given, the guard `release_activation_scope` already uses); early settles `settle_coerced_bound_arg` and `settle_stored_array_element`; `eval_expr_is_owning_temporary` decides (array literal, `new`, `clone` allocate; a variable or property read does not). All releases go through `eval_release_value` so eval-declared `__destruct` runs. Measured with a sentinel forcing every flag false (one binary answers both sides): spread of one object 7 blocks/576 B → 4/432 and `destruct local` now printed; two objects 12/816 → 6/528; by-ref spread 10/720 → 7/576; interpreted `$a = [new T]; unset($a)` 32/2736 → 29/2560. Nine new fixtures in tests/codegen/destructors.rs (35 → 44). Filter name sets identical: spread 11, eval_closures 4, eval_bridge 11/11, eval_callables 4, callable 24, runtime_gc 35, references 2, objects:: 17. Symfony verdict UNCHANGED and the configurator refcount ladder on the real --web binary is IDENTICAL before/after (632 releases, object_refs 1..16, 6 at 1): the configurator's extra references come from a path none of the five eval-bridge lots touched. Pre-existing divergences made visible: an assoc container frees its elements in a different order from php; the by-ref spread warns and skips write-back (php binds by reference); `echo takesInt(...$args);` under an eval context fatals with `Call to undefined function takesint()` while discarding the call is fine.
Evidence: Reducers php -n vs elephc before/after with --heap-debug block counts under a sentinel that forces the flag off; filter name sets before/after; Symfony rebuild (716 s) + curl + ELEPHC_EVAL_RELEASE_TRACE ladder before/after identical.
Verified by: commit f64ece2904; php -n; --heap-debug; cargo test -p elephc-magician narrow filters; rebuild + curl
