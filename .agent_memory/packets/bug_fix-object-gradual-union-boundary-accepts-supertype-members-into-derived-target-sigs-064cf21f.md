# Object gradual-union boundary accepts supertype members into derived target (SIGSEGV, no runtime guard)

> Object boundary soundness hole in gradual union flows into src/types/checker/type compat/unions.rs:155 . The match co…

Object-boundary soundness hole in gradual_union_flows_into (src/types/checker/type_compat/unions.rs:155). The match condition `self.type_accepts(expected, member) || self.type_accepts(member, expected)` counts the SUPERTYPE direction (`type_accepts(member, expected)`) as a satisfying match. For object flows this is unsound: a union member that is a supertype of the concrete target (e.g. Base in a `Base|Sub` or `?Base` = `Union([Object(Base), Void])` union) is treated as acceptable into a more-derived param/return (Sub), but elephc emits NO runtime instanceof guard, so a runtime Base object reaching a Sub-only method call dereferences garbage -> SIGSEGV (exit 139). Combined with gradual_other_member_coercible treating Void (null) as coercible for any target, the extremely common nullable `?Base`/`?Iface` type flows straight through. Reproduced natively on macOS-aarch64: `?Base` into `Sub $x` param, `Base|Sub` into `Sub` (null-free, isolates the supertype clause), `?Base` returned where `Sub` declared (return position), and `?Animal` runtime Cat into `Dog $x` (interface union) all COMPILE and SIGSEGV while PHP 8.5 throws TypeError. Plain concrete `Base` into `Sub` is correctly rejected (only the union/gradual path leaks). The round-2 fix (array_family_gradual_accepts + mixed-variadic guard) did NOT touch this line, so the hole is pre-existing and still open. Fix must make the object case require a PROVEN subtype: for a class/interface target, only `type_accepts(expected, member)` (member is a subtype) may count as a match; the reverse supertype direction must not, and null/Void must not be silently absorbed into a non-nullable object target.
Evidence: Native macOS-aarch64 repro: `?Base`->Sub param, `Base|Sub`->Sub, `?Base`->Sub return, `?Animal`(runtime Cat)->Dog all compile (elephc exit 0) and SIGSEGV (binary exit 139, empty output); PHP 8.5 throws TypeError on each. Concrete Base->Sub correctly rejected at compile.
Verified by: elephc target/debug compile + run vs php 8.5, side by side

## Verification

Native macOS-aarch64 repro: `?Base`->Sub param, `Base|Sub`->Sub, `?Base`->Sub return, `?Animal`(runtime Cat)->Dog all compile (elephc exit 0) and SIGSEGV (binary exit 139, empty output); PHP 8.5 throws TypeError on each. Concrete Base->Sub correctly rejected at compile.
