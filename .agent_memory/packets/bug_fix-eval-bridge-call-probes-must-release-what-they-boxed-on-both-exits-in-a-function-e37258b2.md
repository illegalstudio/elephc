# Eval-bridge call probes must release what they boxed on both exits: in a function owning an eval context every typed method call is probed first, and the miss path stranded +1 per call

> Commit 11949c8a41. In a function that OWNS an eval context — which web declares in far more functions if ctx.web { ct…

Commit 11949c8a41. In a function that OWNS an eval context — which `--web` declares in far more functions (`if ctx.web { ctx.declare_eval_context_local(); }` in `promote_eval_bridge_method_argument_locals`) — `src/codegen/lower_inst/method_dispatch.rs` (~:97) prefixes EVERY statically typed method call with `lower_eval_owned_method_call`: the receiver is boxed (`__rt_mixed_from_value`, +1), array arguments too (`__rt_mixed_from_array_kind`, +1), then `__elephc_eval_method_call`; on miss (the ordinary outcome for AOT code) the native dispatch follows. The bridge only BORROWS those cells (`RuntimeCellHandle` is `Copy` with no `Drop`), so the frame stays their owner, and BOTH exits — the serviced `dynamic_dispatch_done` and the miss `eval_owned_method_miss` which pops the frame — dropped them without decref: +1 on the receiver per probed call. Reproducer (3 lines): `function run(){ eval('$seed = 1;'); (new Cfg())->args([1,2])->tag('x'); echo "after"; }` — php prints `destruct/after/end`, elephc never ran the destructor; delete the `eval()` line and elephc was already correct. That is the whole build-dependence behind the Symfony configurator refcounts (1/2/2 in a small build vs 2/4/6 in `--web`). Fix in `src/codegen/lower_inst/builtins/eval/argument_results.rs` and `dynamic_calls.rs`: release what the call boxed on both exits across the eval-bridge call ABI (function call, owned function call, `new`, dynamic-new fallback, method call, owned-method probe, static call, late-static override probe); a serviced call keeps the one cell the bridge published as its result (an interpreted `return $a;` hands back the very cell it was passed); the override probe answers before anything is boxed, so it got its own exit rather than decref'ing uninitialized scratch. Two sites deliberately left alone, with evidence: a static-property WRITE hands the value to the store, which keeps it (an A/B proved the first attempt there was the only real regression among 9 reds — 8 were pre-existing); the by-reference argument marker boxes a frame ADDRESS under an invoker tag, never a heap value. Three value fixtures in tests/codegen/destructors.rs; filters destructors 27/0, eval_bridge 11/0, runtime_gc 35, objects:: 17, locals_retype 8, nullable 5, references 2 — all at baseline. The Symfony verdict did NOT change (still `secrets.local_vault` missing): a further pre-existing leak remains — under an eval context, a method that RETURNS ONE OF ITS ARGUMENTS strands that argument (`$keeper->keep($local)` never destructs `$local`; correct without the `eval()`), on the untouched borrowed-marker path; `AbstractConfigurator::processValue($value)` returns its argument on every call of the chain. Debt: the `static`, `late`, `callable` filters show failures not yet attributed (HEAD vs 4d96033129), including `…_preserves_by_ref_argument` tests. Reproduce the `--web` shape in seconds by adding `eval('$seed = 1;')` to the enclosing function of a probe.
Evidence: Verbatim asm of the probe (boxing, bl ___elephc_eval_method_call, tbnz to the miss exit that pops the frame without decref); 3-line reproducer php vs elephc before/after; A/B with the gate disabled proving 8 of 9 reds pre-existing; filter tables; Symfony rebuild + curl byte-identical verdict.
Verified by: commit 11949c8a41; php -n; --heap-debug; check_asm_comments.py; rebuild + curl

## Verification

a static-property WRITE hands the value to the store, which keeps it (an A/B proved the first attempt there was the only real regression among 9 reds — 8 were pre-existing); the by-reference argument marker boxes a frame ADDRESS under an invoker tag, never a heap value. Three value fixtures in tests/codegen/destructors.rs; filters destructors 27/0, eval_bridge 11/0, runtime_gc 35, objects:: 17, locals_retype 8, nullable 5, references 2 — all at baseline. The Symfony verdict did NOT change (still `secrets.local_vault` missing): a further pre-existing leak remains — under an eval context, a method that RETURNS ONE OF ITS ARGUMENTS strands that argument (`$keeper->keep($local)` never destructs `$local`; correct without the `eval()`), on the untouched borrowed-marker path; `AbstractConfigurator::processValue($value)` returns its argument on every call of the chain. Debt: the `static`, `late`, `callable` filters show failures not yet attributed (HEAD vs 4d96033129), including `…_preserves_by_ref_argument` tests. Reproduce the `--web` shape in seconds by adding `eval('$seed = 1;')` to the enclosing function of a probe.
