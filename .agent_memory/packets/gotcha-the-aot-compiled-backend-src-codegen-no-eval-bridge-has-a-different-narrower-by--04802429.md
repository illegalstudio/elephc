# The AOT-compiled backend (src/codegen, no eval bridge) has a DIFFERENT, narrower by-refere

> The AOT compiled backend src/codegen, no eval bridge has a DIFFERENT, narrower by reference closure capture defect th…

The AOT-compiled backend (src/codegen, no eval bridge) has a DIFFERENT, narrower by-reference-closure-capture defect than the interpreter's: compiling scratchpad/r200/q3.php directly (single `use (&$closure)` capture of an appended array slot, plus `unset($closure)`, no loop) already matches php exactly (`call1=first:x` / `call2=later:y`), so the interpreter fix in this session's commit (a-use-x-closure-capture...) did not need to touch codegen for that shape. But compiling scratchpad/r200/q5.php directly (the SAME capture pattern repeated across a `foreach ([1,2] as $n)` loop, each iteration doing `$closure = &$optimized[]; $closure = static function(...) use (&$closure, $n) {...};`) produces `a1=first2:x a2=later2:y b1=later2:x b2=later2:y` where php gives `a1=first1:x a2=later1:y b1=first2:x b2=later2:y` -- both loop iterations' closures print as if they share the SAME captured cell (both show "later2"), suggesting codegen's lowering of a `use (&$x)` capture inside a loop body does not allocate a distinct captured storage location per loop iteration/per closure instance, unlike the interpreter which (after this session's fix) gets this right. This is a measured, UNFIXED divergence, deliberately not scheduled: the task that produced this packet was scoped to the interpreter (crates/elephc-magician), and codegen's capture-lowering is a different subsystem (likely something under src/codegen/lower_inst/callables.rs or wherever closure `use` clauses are lowered to captured storage) that would need its own investigation before any fix.
Evidence: target/release/elephc compiled q3.php and q5.php directly (no PROBE_FILE/eval bridge) and ran the resulting native binaries: q3 matched php -n 8.5.6 exactly, q5 diverged with both loop iterations' closures showing the second iteration's replacement value.
Verified by: target/release/elephc scratchpad/r200/q3.php and scratchpad/r200/q5.php, running the compiled binaries directly, compared to php -n 8.5.6

## Verification

target/release/elephc compiled q3.php and q5.php directly (no PROBE_FILE/eval bridge) and ran the resulting native binaries: q3 matched php -n 8.5.6 exactly, q5 diverged with both loop iterations' closures showing the second iteration's replacement value.
