# Four comparators decide PHP ordering and they disagree: `<` on two numeric strings is bytewise (__rt_strcmp) while `<=>` is Zend-correct (__rt_php_compare); sort() uses a third; exact-long strings lose precision; [] <=> false is wrong

> Measured 2026 09 04 on HEAD bacfbc1a7c with 11 reducers frozen against php n session scratchpad laravel/transfer/comp…

Measured 2026-09-04 on HEAD bacfbc1a7c with 11 reducers frozen against php -n (session scratchpad laravel/transfer/compare/): 2 identical, 6 divergent, 3 refused. PHP 8 semantics (php-src `zend_compare`, the "saner string to number comparisons" RFC): two PHP-numeric strings compare NUMERICALLY, not bytewise; exact 64-bit integer strings keep exact long ordering, and same-direction overflows that round to one double fall back to byte order; int vs string compares as longs when the string is an exact long (so integers above 2^53 keep exact ordering) — while `strcmp()` stays bytewise. Divergences: on the same line `'10' ~ '2'` gives `<=> = 1` (correct, via `__rt_php_compare`) but `< = true` (wrong: `<` reaches bytewise `__rt_strcmp`), 13 of 21 table lines differ; `9007199254740993 <=> '9007199254740992'` → 0 (php 1, exact-long precision lost); `sort()` on a string array is bytewise through a THIRD comparator (`src/codegen_support/runtime/arrays/sort_str.rs`); `[] <=> false` → 1 because `__rt_php_truthy` reports every array truthy; `array_search('1e1', ['10'])` → false (php finds it); `sort($a, SORT_FLAG)` and `max('apple', 10)` are refused outright. Correct and not to regress: `strcmp` bytewise, `usort` with `<=>`, 23 of 24 table rows including every INF/NAN case. Fix shape: implement the classification ONCE inside `__rt_php_compare` (`src/codegen_support/runtime/compare/php_compare.rs`) and route every ordering site to it — `src/ir_lower/expr/comparisons.rs` (~:85), `src/codegen/lower_inst/comparisons.rs` (~:33), the sort comparator, `builtins/arrays.rs` (~:952 array_search/in_array loose equality), `src/builtins/array/sort.rs` (~:18) — so the comparators cannot drift apart again; the Laravel branch's three runtime emitters (`str_php_cmp.rs`, `int_str_php_cmp.rs`, `str_classify_php_number.rs`) are portable as reference implementations but its `Op::IntStrCmp` no longer exists.
Evidence: Comparison table probe (21 lines, 13 differ), exact-long probe, sort()/array_search/max probes vs php -n; refusals recorded verbatim (agent report 2026-09-04).
