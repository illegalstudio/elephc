# Nullable nominal return guards must transfer the source local owner through cleanup

> A nullable nominal RuntimeCall validates the class but forwards the same boxed Mixed cell. Return cleanup must trace …

A nullable nominal RuntimeCall validates the class but forwards the same boxed Mixed cell. Return cleanup must trace this forwarding guard to its source local and transfer that local owner, rather than freeing the cell at function exit. Concrete object guards retain an independent unboxed payload and must remain excluded. Adding an unconditional retain after the nullable guard fixes the immediate double free but leaks when the function returns an unchanged borrowed argument. A second ownership edge matters at the caller: when argument cleanup transfers an owned temporary to an identical result, retaining-store cleanup must not also suppress release of that result. The suppression in user_call_result_may_alias_argument is reserved for borrowed arguments. These focused fixes do not establish full application acceptance or close other return-alias leaks.
Evidence: The original compiled nullable-return helper reproduced a worker double free. Three test_nullable_nominal_return regressions now pass with a clean heap: borrowed recursive argument including null, fresh mixed call result, and reassigned mixed parameter. The frame unit test nominal_return_guard_transfers_only_forwarded_boxed_local passes. Two accumulator aliasing regressions pass. After also resetting dynamic class declarations between requests, web_eval_reflection_constructor_survives_array_roundtrip passes twice in one worker. Two conditional-return legacy regressions still leak and are not claimed closed. Full r150 compiles but exhausts its fixed heap before any HTTP response.
Verified by: Focused macOS executable tests, frame ownership unit test, and LLDB return-cell tracing
