# The eval bridge has its own constant and builtin surface: `ENT_*` names are missing (fatal inside a runtime-included file), `getmypid()` is unimplemented, `sys_get_temp_dir()` answers /tmp, `ReflectionClass::getFileName()` answers the entry file

> Code that reaches the interpreter an eval , or any file included at run time does NOT see the compiler's constant tab…

Code that reaches the interpreter (an `eval()`, or any file included at run time) does NOT see the compiler's constant table; it sees the interpreter's own, in crates/elephc-magician/src/interpreter/constant_eval.rs. The `ENT_*` family is defined only on the compiler side, in src/types/ent_constants.rs, so `htmlspecialchars($s, \ENT_QUOTES, 'UTF-8')` inside a runtime-included file stops the program with `Fatal error: eval() runtime failed` — while the same call in AOT code is fine. DIRECTORY_SEPARATOR, PHP_EOL, PHP_INT_MAX and PHP_SAPI were measured as passing, so "some constants work" is not evidence that yours does; check the interpreter's table by name before assuming. Three more environment answers diverge from php and are worth knowing before you chase them as bugs of your own: `getmypid()` is not implemented anywhere in the tree (the bridge reports an unsupported construct); `sys_get_temp_dir()` answers the hardcoded `/tmp` rather than `$TMPDIR`, which is wrong on macOS — the builtin declaration is src/builtins/io/sys_get_temp_dir.rs and the runtime carries a fixed `/tmp/elephc-XXXXXX` template in src/codegen_support/runtime/data/fixed.rs; and `ReflectionClass::getFileName()` answers the program's ENTRY file for every class, on both the AOT dispatch (src/codegen/lower_inst/objects/reflection/owner_dispatch.rs) and the interpreter (crates/elephc-magician/src/interpreter/reflection/class_api.rs) — harmless only when the entry file happens to sit beside composer.json, as it does in the Symfony fixture, and quietly wrong for anything that derives a project root from it.
Evidence: Probe pass W1/W2/W4 of 2026-09-02, every form measured against `php -n`: htmlspecialchars with ENT_QUOTES in a runtime-included file gave the eval-runtime fatal while DIRECTORY_SEPARATOR, PHP_EOL, PHP_INT_MAX and PHP_SAPI resolved; sys_get_temp_dir answered /tmp instead of the macOS $TMPDIR; getmypid was refused as an unsupported construct; getFileName answered the entry file for every class. Re-checked in the tree at HEAD f7a17151de on 2026-09-04: the literal name "ENT_QUOTES" appears only in src/types/ent_constants.rs (and its own test), no occurrence of getmypid exists under src/ or crates/, and the /tmp template is at src/codegen_support/runtime/data/fixed.rs:1430.
Verified by: Reduced probes diffed against `php -n` (session note dated 2026-09-02); the constant-table and builtin absences re-verified by searching the tree at HEAD f7a17151de on 2026-09-04.
