# A by-reference return must hand back a RETAINED cell and a target that outlives the activation

> Binding to a call was refused because nothing handed a writable target from a callee back to its caller. The mechanis…

Binding to a call was refused because nothing handed a writable target from a callee back to its caller. The mechanism that works is a side channel on the context: a return statement inside a body declared to return by reference resolves its expression as a reference SOURCE and leaves the target plus the value cell there, and the caller's bind takes that ownership over. WHATEVER OUTLIVES THE CALL OWNS ITS REFERENCE, so the cell is RETAINED before it is left behind, and an unclaimed one — a by-reference call whose result nobody binds — is released.

THE TARGET MUST BE REWRITTEN, and this is the part that is not obvious. The activation scope is drained the moment the call returns, so a scope-based Variable or ArrayElement target becomes a dangling pointer. Four cases, each different: a STATIC LOCAL needs its own reference-target variant naming the context's static-local store, which is the same store the next call reads from; a BY-REFERENCE PARAMETER already carries the CALLER's target, so an element of it becomes a nested element of that target and reaches the caller's own array; a property, static property or element rooted at one already outlives the frame and is kept; and a PLAIN LOCAL's storage really does die, so only the retained cell remains — php keeps the value alive by refcounting the reference and there is no storage left for a write to reach, which is what php shows too.

A NON-REFERENCE return under the marker is not an error: php emits Notice Only variable references should be returned by reference and binds a copy. Refusing it would reject code php runs.

TWO SENTINELS worth copying, because they fail in different registers. Removing the retain makes the counting fixture name the exact handle: released a fake cell nobody owned, reaching count -1. Removing the target rewrite SIGSEGVs — the caller writes through a pointer into the drained scope. A wrong answer would have been the kinder failure, and it is worth saying so in the commit: an ownership defect that segfaults is easier to find than one that quietly writes nowhere.

Flag plumbing: save and restore the returns-by-reference flag around each body rather than keeping a parallel stack, because the sites that run a body already own that save/restore shape and a second stack can desync from the function stack on an early return.
Evidence: php -n 8.5.6 prints 5, 9;42;200, 77, 4;8, 6 and 5;2 with two notices on the six fragments and elephc now prints the same. Sentinels: removing the retain fails the counting fixture with released a fake cell nobody owned, handle 1 reached count -1 holding Int(100); removing the target rewrite SIGSEGVs; removing the notice fails exactly the non-reference test. Symfony measurement: 3 refused files become 1, ExtensionTrait.php and ProfilerListener.php parse in full, KernelTrait.php moves from line 547 to 670 onto a different construct; the reducer corpus goes from 12 refusals of 37 to 10 with g15 and g18 accepting.
