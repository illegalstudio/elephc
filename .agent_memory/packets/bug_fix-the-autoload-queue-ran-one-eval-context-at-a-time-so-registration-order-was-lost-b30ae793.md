# The autoload queue ran one eval context at a time, so registration order was lost

> PHP has ONE autoload queue per request and runs it in registration order. elephc keeps each callback on the context t…

PHP has ONE autoload queue per request and runs it in registration order. elephc keeps each callback on the context that registered it -- that is where it is retained and released -- and `eval_spl_autoload_class()` ran one context's whole list before starting the next, so with two contexts the order became the order of the CONTEXTS rather than of the registrations. Symfony appends `ClassExistenceResource::throwOnRequiredClass` from one context and needs it to run AFTER Composer's loader, which lives in another, so this is on the request path.

THE FIX IS A REQUEST-WIDE NUMBER ON EACH CALLBACK, not a shared list. Storage stays per context; `register_autoload_callback()` stamps each entry with a number from a pair of atomics, appends counting up and prepends counting down, so a prepend lands ahead of everything registered before it whichever context owns it. The dispatcher merges every owner's entries, sorts by that number, and invokes each one with the runtime hooks bound to its own owner. The recursion guard moved with it: it was taken per context inside the per-context loop, and is now taken once around the whole queue by the context that asked.

`spl_autoload_functions()` answers from the same merged list, so what it reports is what will run. It also has to RETAIN what it puts in the array -- the array takes the value it is given, and handing it the cell the registry still owns put a reference the registry owns into userland, which read back as integers instead of the registered callables.

TWO NEIGHBOURING DEFECTS MEASURED AND LEFT ALONE, both codegen-side. An autoloader registered from COMPILED code with a LITERAL string callable never enters the runtime queue at all: `spl_autoload_register('probe_loader_one')` at file scope is turned into a compile-time autoload rule, and php runs `one(NopeK);two(NopeK);` where elephc runs only `two(NopeK);`. A computed name such as `__CLASS__ . '::method'` cannot become a rule and does reach the queue, which is why the Symfony loader works and a plain name does not. And the compiled `spl_autoload_functions()` lowering emits an array of compile-time rule PLACEHOLDERS (`lower_spl_autoload_functions` in `src/codegen/lower_inst/builtins/spl.rs`), unconnected to the runtime registry: three registrations, two integer entries.
Evidence: Three contexts with a nested autoload: php 8.5.6 prints `ctxA;ctxB;aot:ProbeMissingOne:null;closure:ProbeMissingOne;ctxC;aot:ProbeMissingTwo:null;closure:ProbeMissingTwo;n;ctxCdone;n;ctxBdone;seen=ProbeMissingOne,ProbeMissingTwo;done`, and before the fix elephc ran the closure first at both levels and recorded the two class names reversed. The committed test fails with the fix removed, printing exactly that reversed sequence. The literal-callable gap is a separate three-line probe: php `ce=one(NopeK);two(NopeK);n;done`, elephc `ce=two(NopeK);n;done`.
Verified by: cargo test --test codegen_tests on the new order test (green with the fix, red without); elephc-magician lib 1372 passed 0 failed with no skips; filters eval_bridge 13 of 13, destructors 44 with 3 known reds, runtime_gc 35, objects 17, include 162 with 7, autoload 126 with 1 red that is also red before this work

## Verification

Three contexts with a nested autoload: php 8.5.6 prints `ctxA;ctxB;aot:ProbeMissingOne:null;closure:ProbeMissingOne;ctxC;aot:ProbeMissingTwo:null;closure:ProbeMissingTwo;n;ctxCdone;n;ctxBdone;seen=ProbeMissingOne,ProbeMissingTwo;done`, and before the fix elephc ran the closure first at both levels and recorded the two class names reversed. The committed test fails with the fix removed, printing exactly that reversed sequence. The literal-callable gap is a separate three-line probe: php `ce=one(NopeK);two(NopeK);n;done`, elephc `ce=two(NopeK);n;done`.
