# FIXED: unserialize matched only MANGLED property keys, so a `__serialize()` class's own key spelling silently dropped every private property

> FIXED, on both architectures. rt obj store prop compared the parsed key against the class's serialize property info r…

FIXED, on both architectures. `__rt_obj_store_prop` compared the parsed key against the class's serialize property-info rows and nothing else, and those rows carry the MANGLED name — `"\0Class\0name"` for a private property, `"\0*\0name"` for a protected one. A class with a `__serialize()` picks its own keys, and the natural spelling there is the DECLARED name, so the key never matched any row and the loop's "unknown key is ignored" arm dropped it. The typed property then stayed uninitialized and the first read raised `must not be accessed before initialization`.

REFERENCE PHP, verified with `php -n` 8.5.10: it accepts BOTH spellings. Symfony's `FileResource` is the case in the wild — `private string $resource` plus `__serialize(): array { return ['resource' => $this->resource]; } ` and no `__unserialize()` — and its `.meta` files, written by real PHP, hold `s:8:"resource"`.

THE FIX is a SECOND PASS, not a widened comparison. Pass one matches the row key verbatim across every row; pass two retries, narrowing each row key to whatever follows its LAST NUL (rows with no NUL are skipped, having already been compared). Two passes rather than comparing both spellings per row so an explicit mangled key still wins over an unmangled alias when a class declares both — the same precedence php-src has.

WHERE NOT TO PUT IT: `_class_serprop_ptrs` is shared with `serialize()`, `get_object_vars()`, `var_dump` and the export helpers. Adding alias ROWS to the table would have been a one-line change in the emitter and would have made `serialize()` emit every private property twice.

STILL WRONG, separately: the INTERPRETER's `serialize()` ignores `__serialize()` and emits the mangled key where PHP emits the class's own. The AOT `serialize()` honours it. scratchpad/red18 vs red19 shows the two side by side.
Evidence: scratchpad/red19/main.php, run against `php -n` 8.5.10: before, `AOT roundtrip:` raised `Typed property Probe\FileRes::$resource must not be accessed before initialization`; after, all four lines (`blob`, `roundtrip`, `literal-set:1`, `mangled-set:1`) match PHP exactly. codegen_tests `serial`: 88 passed / 1 failed, and that one failure (`test_phase4_spl_doubly_linked_list_serialization_helpers`) reproduces with the second pass disabled, so it is pre-existing.
Verified by: scratchpad/red19 differential against php -n 8.5.10; the Symfony --web request advanced past FileResource into the GlobResource freshness check.
