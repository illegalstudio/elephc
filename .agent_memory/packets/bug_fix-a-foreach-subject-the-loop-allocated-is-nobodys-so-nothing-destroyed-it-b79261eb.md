# A foreach subject the loop allocated is nobody's, so nothing destroyed it

> In the eval interpreter a foreach whose subject expression PRODUCES a value new C , f , gen , $o m never released it.…

In the eval interpreter a `foreach` whose subject expression PRODUCES a value (`new C()`, `f()`, `gen()`, `$o->m()`) never released it. The value is never bound to a scope name, so no activation teardown ever sees it. PHP's destruction is observable -- `__destruct` on the temporary, and a generator's `finally` when the loop is abandoned -- and elephc printed none of it.

The fix decides ownership from the subject EXPRESSION, before evaluating it: the rule `eval_expr_is_owning_temporary` already uses for call arguments (Array, NewObject, DynamicNewObject, NewAnonymousClass, Clone), widened by the nine call shapes. The widening is justified, not guessed: an interpreted call hands its return value to the caller, because `release_activation_scope` excludes exactly that handle from the activation's teardown, and the statement-expression path in dispatch.rs already releases any expression result on that basis. A read of existing storage such as `LoadVar` hands back a BORROWED cell and must be left alone -- releasing it destroys an object its owner still holds, which is why the negative case is pinned beside the positive ones.

The release sits on EVERY exit edge: the loop's result is bound rather than propagated with `?`, so completion, `break`, `return` out of the enclosing function and a throw passing through all reach it.

Two consequences that are easy to miss. First, PHP destroys an `IteratorAggregate` temporary as soon as `getIterator()` has RETURNED, not at the end of the loop: `foreach (new Bag("temp") as $x) { echo $x; }` prints `destruct:temp;12`, not `12destruct:temp;`. Second, that early release is only sound because a generator method's `$this` is now OWNED -- a generator's scope outlives the call that built it, so a borrowed receiver is a dangling pointer waiting for a resumption.
Evidence: php -n 8.5.6: `a=1,b=2,tag=new,destruct:new;|a=1,b=2,tag=call,destruct:call;` for allocated subjects; `a=1,b=2,tag=held,afterC;destruct:held;` for a variable subject (NOT destroyed by the loop); `a=1,destruct:broken;|destruct:returned;r|destruct:thrown;caught;` for break, return and a throw; `1fin;|12fin;` for a generator broken out of and run to completion. For `foreach ((new GC())->m() as $v)` php prints `78d;` while elephc printed `d;78`, which is the generator-receiver half.
Verified by: Commit 0c773dcd9c. cargo test -p elephc-magician --lib -- --skip runtime_callables --skip runtime_fallback: 1316 passed / 16 pre-existing failed, byte-identical failure list before and after, +5 tests.
