# Binary size: dead-stripping the user object and sparse class tables are worth ~0; the prize is the eval bridge (thunk surface, the linked interpreter) and never-named compiler-supplied classes

> Measured read only on 2026 09 03 debug profile elephc and bridges; release shrinks the Rust bridge columns . The 119 …

Measured read-only on 2026-09-03 (debug-profile elephc and bridges; release shrinks the Rust bridge columns). The 119 MB `--web` Symfony binary is 98.8 MB of `__text` (user object ≈ 92 %, elephc `__rt_*` runtime ≈ 0.1 %); `__common` 1.5 GB is the zero-fill heap and costs no file bytes. On the 33 MB probe with symbols: `__text` = `libelephc_magician` (the Rust eval interpreter) 49.7 %, user object 32.1 %, `libelephc_tls` 13.6 %, pcre2 2.7 %, runtime 1.1 %. (1) DEAD-STRIP of the user object (`.subsections_via_symbols`, which today only the runtime object gets in `src/codegen_support/driver_support.rs`) needs `localize_internal_labels` (`src/codegen_support/emit.rs`) first or `as` refuses with 52,384 errors; done right it strips only name-string records (`_class_vd_pkey_*`, `_class_json_desc_*`, `_class_callable_methods_*`, `_callable_user_fn_name_*` emitted in `src/codegen_support/runtime/data/user.rs`) = 0.21 % of the stripped binary (0.89 % unsafe ceiling) — AND both dead-strip variants break the program (empty stdout; SIGSEGV in `ReflectionObject->getFileName`) although the same object linked without `-dead_strip` is byte-identical to baseline and `__data` keeps every string at the same offset: `-dead_strip`'s per-atom repacking of `__text` (−8,384 B of padding) exposes a latent contiguity/alignment assumption in emitted TEXT, not located. Not a size lever; the dead records are referenced by symbol with explicit length, so the B1 "adjacency" hazard is a `__data` REORDERING hazard, a different thing. (2) Class-id tables are 100 % dense (ids 0..126, 3,040 B of `_missing` filler, 0.38 % of the .s; 94 % of class metadata is per-class descriptors): sparse encoding saves ~3 KB — not a lever; `allowed_class_names` filters before `max_class_id` in `user.rs`. (3) Compiler-supplied classes: 127 classes = 41.7 % of the .s; 61.8 % of those bytes belong to 107 classes NEVER named anywhere (DateTime 4.7 MB asm, DateTimeImmutable 2.0 MB, DateInterval, DateTimeZone ≈ 1.06 MB of binary, fixed), 13.1 % to one class named only inside a string literal (`Filesystem` via the composer classmap); EVERY one of the 127 has a direct `bl _method_…` call site because supplied classes call each other, so reachability by edges can never prune them: pruning needs ROOTS (what the program names), and the positive-control corpus (7/20 wrong today) is its gate. (4) THE PRIZE: eval-bridge thunks `__elephc_eval_*` = 22,858 symbols, 28.3 % of the .s, 1,989 (class, method) slots + 866 property slots; against the xdebug ledger only 57 of 1,989 slots (2.9 %) name a method the real app ever calls → up to ≈ 22 MB of the 91 MB user object. And the cliff: ONE computed `include` turns a 68,672 B stripped binary into 10,845,216 B (×158), 98.1 % of which is the linked `elephc_magician` Rust code (emitted thunks 1.1 %). Floor `echo 1;` = 68,672 B, always emitting 8 builtin classes; 7 × `_class_propinit_N` = 32.8 % of the floor's text. Levers 1–3 all change semantics and hinge on the same unresolved question (narrowing the unresolvable-include hazard); a semantics-neutral variant to design is table-driven GENERIC thunks (one marshaller per signature shape) instead of 22,858 specialized ones.
Evidence: size -m / otool -l on examples/symfony-app/public/index; link map of the probe (base.map) by contributor; dead-strip variants (b)–(e) with stdout/exit and segment deltas; per-class byte classification against the probe's static include closure and the composer classmap; thunk slots vs target/symfony-native-xdebug/ledger (447 distinct Class::method); floor probes echo 1; and one computed include (all match php -n). Scripts and artifacts in the session scratchpad perf/size/.
Verified by: otool/size/nm/ld -map on binaries linked with elephc's exact link line; php -n oracle on the floor probes
