# lower_nested_array_assign's general fallback (src/ir_lower/stmt/mod.rs) lowers a nested wr

> lower nested array assign's general fallback src/ir lower/stmt/mod.rs lowers a nested write target e.g. $x $i $j = v …

lower_nested_array_assign's general fallback (src/ir_lower/stmt/mod.rs) lowers a nested write target (e.g. `$x[$i][$j] = v`, `$obj->prop[$i][$j] = v`) by reading the WHOLE nested ArrayAccess chain as an rvalue via lower_expr(ctx, target), then emitting a 2-operand Op::RuntimeCall(target, value) that codegen lowers via lower_mixed_cell_runtime_assign — which mutates whatever cell the read returned, IN PLACE. This only works when the read returns a LIVE shared pointer into the original structure, which __rt_mixed_array_get only does for keys that ALREADY hold a tag-7 boxed-Mixed entry (array/hash/existing Mixed cell). For a MISS or scalar leaf (false/null/missing key) — exactly the auto-vivify case — __rt_mixed_array_get allocates a FRESH disconnected Mixed(null) cell via __rt_mixed_from_value; mutating that cell is a silent no-op that never reaches the original structure. Proven pre-existing and independent of any Union/gradual-typing work: `$x = json_decode('[false]', true); $x[0]["k"] = 1;` (fully Mixed, no Union involved) already silently no-ops on origin/main-equivalent HEAD. This blocks any nested (2+ level) auto-vivify write through Mixed/Union receivers; single-level writes (e.g. $this->v["k"]=1 via PropGet+__rt_mixed_array_set) are unaffected since PropGet gives the property's own storage cell directly, no read-then-mutate-same-cell indirection. Fixing nested vivify needs lower_nested_array_assign to read the PARENT container + key and vivify/set into the parent's slot properly, not rely on the shared-pointer read trick.
Evidence: cargo run -- --emit-ir probe showed: array_get (read $h->items[0], Heap(Mixed)) -> runtime_call (read the missing "k" key, produces a fresh disconnected Mixed cell) -> 2-operand runtime_call(target=fresh cell, value) which lower_mixed_cell_runtime_assign mutates in place; the mutation never reaches $h->items[0]. Confirmed independently with a pure Mixed json_decode case (no Union/gradual typing involved): $x=json_decode('[false]',true); $x[0]["k"]=1; var_dump($x[0]); prints bool(false) unchanged instead of PHP's array(1){["k"]=>int(1)}.
Verified by: manual --emit-ir inspection + standalone json_decode repro, both on branch reconcile/dirname-symfony HEAD 3a2bb667a
