# Compiled eval scopes need live native bindings and an explicit capability symbol

> Literal eval AOT must keep lexical locals distinct from GLOBALS aliases. A copied scope value is insufficient when a …

Literal eval AOT must keep lexical locals distinct from GLOBALS aliases. A copied scope value is insufficient when a local is bound to native global storage: a write must be visible during the compiled fragment, not just after reload. Compiled scope entries now distinguish call-bounded native reference markers and global-name bindings; generated getters and setters access live storage, reload skips stale snapshots, and return restores owned value views. Owned-to-borrowed replacement of an identical cell must release the former scope owner. The explicit scope_bind_native entry point prevents old bridges from silently dropping the binding metadata. This is focused evidence, not complete GLOBALS parity or stock application HTTP acceptance.
Evidence: The eval_globals integration module passed all 13 then-present tests in 73.83 seconds before capability hardening. The native binding FFI roundtrip and same-cell owner downgrade tests passed. native_scope_binding_capability_on_all_targets passed for five target configurations. The rebuilt debug static archive exports the new scope_bind_native symbol. Read-only reference optimization, interpreter observers, additional ownership edges and full HTTP acceptance remain open.
Verified by: Focused CLI integration tests, Rust scope tests, five-target emitter test and static archive symbol inspection
