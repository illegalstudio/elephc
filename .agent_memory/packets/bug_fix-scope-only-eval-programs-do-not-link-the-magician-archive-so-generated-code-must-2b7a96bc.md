# Scope-only eval programs do not link the magician archive, so generated code must never call a bridge-only symbol: the fatal reporter broke 65 tests at link time

> Commit 7bb4aee883. A program whose eval fragments are ALL compiled ahead of time sets eval scope and NOT eval bridge …

Commit 7bb4aee883. A program whose eval fragments are ALL compiled ahead of time sets `eval_scope` and NOT `eval_bridge`, and that distinction is load-bearing: `runtime_features::link_requirements_for_runtime_features` asks for libelephc-magician ONLY when `eval_bridge` is set, while `codegen_support/runtime/eval_scope.rs` emits the program's own native `__elephc_eval_scope_*` helpers into the always-linked runtime object. The invariant is stated on `function_contains_eval_scope_state`: "Scope-only functions use the native scope helpers and must not force the magician bridge staticlib into the link."

Échelons 37/38 moved the anonymous fatal's wording into the bridge crate and made `emit_eval_bridge_fatal_exit` call `__elephc_eval_report_runtime_fatal` unconditionally, breaking that invariant. Result: `Undefined symbols ... "___elephc_eval_report_runtime_fatal", referenced from: _fn__u__u_elephc_u_list_u_identifiers in test.o` on about one eval test in seven — 71 link-error lines, 65 tests.

HOW TO DIAGNOSE THIS CLASS OF BUG IN ONE STEP, which is the reusable part: emit the assembly for the reducer and list every bridge symbol it names — `grep -o '__elephc_eval_[a-z_]*' x.s | sort | uniq -c`. On the reducer that printed SEVEN names: scope_new/get/set/unset/free and value_null, all of which RESOLVE because the runtime object defines them, plus report_runtime_fatal which does not. One symbol out of seven lacking a native definition is the entire bug, and it takes seconds to see. Control the finding by compiling a program that uses the SAME prelude but no eval: it references the reporter zero times and links, proving the reference is gated on eval lowering rather than on the prelude.

THE FIX IS A LAYER CHOICE. Making the feature scan set `eval_bridge` for these references would link the whole ~30 MB interpreter into programs that compiled every fragment ahead of time — the exact cost scope-only AOT exists to avoid. Instead, when the bridge is absent the wording is written inline, using the same two constants the reporter itself falls back to when the interpreter recorded no clause (and with no interpreter there is never a clause), mirroring its silence for every other status. With the bridge linked, nothing changes.

GENERAL RULE: any symbol generated code may reference must be defined in the ALWAYS-LINKED runtime, or its emission must be gated on the same predicate that puts its defining archive on the link line. A bridge-only symbol reached from a builtin-class emission is reachable in programs that never asked for the bridge, because those emissions carry their arms whether or not the fragment needed the interpreter.

MEASUREMENT NOTE: run these gates WITHOUT any ELEPHC_*_LIB_DIR frozen-archive overrides. Those point at release archives frozen for timing work; an integration test must link the archives cargo just built or the link being proved is not the link that ships.
Evidence: cargo test --test codegen_tests eval_ with a debug compiler: BEFORE 1047 passed / 200 failed with 71 link-error lines naming ___elephc_eval_report_runtime_fatal; AFTER 1112 passed / 135 failed with 0 such errors, 65 tests fixed and 0 new failures (after-set a strict subset, verified with comm). Symbol census on the reducer assembly showing 7 eval symbols of which only the reporter is undefined. Reducer runs and prints done:0. The single remaining Undefined symbols in the run is the pre-existing zlib/bzip2 gap (_inflate, _BZ2_bzBuffToBuffDecompress).
Verified by: Identity gate: a program using no eval emits byte-identical assembly before and after (194,869 B, cmp exit 0). Bridge path intact: the dynamic eval($code) reducer still emits 36 reporter calls while the scope-only reducer emits 0 and carries the 2 constants. Reproduced with ELEPHC_ASM_JOBS=1 and ELEPHC_ASM_CACHE=0, ruling out the splitter and slice cache.
