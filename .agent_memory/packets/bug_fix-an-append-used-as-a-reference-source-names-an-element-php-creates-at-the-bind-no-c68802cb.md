# An append used as a reference source names an element PHP creates at the bind, not at first write

> A reference source ending in an empty bracket pair was refused with ExpectedSemicolon pointing at the bracket. The ca…

A reference source ending in an empty bracket pair was refused with ExpectedSemicolon pointing at the bracket. The cause is a deliberate parser behaviour one layer away: parse_postfix stops in front of an empty bracket pair so the statement parser can claim an append, so a source ending in one arrives with the brackets unconsumed and the statement then demands its semicolon and finds a bracket. The diagnostic reads like a broken statement rather than a missing rule, which is why this shape did not look like part of the reference family it belongs to. Whenever a diagnostic complains about a missing terminator at a bracket, check whether an earlier parser deliberately declined to consume it.

The missing rule is a node naming the element an append WOULD create: EvalExpr::ArrayAppendSlot in the eval IR. It exists only as a reference source and eval_expr refuses it, because php refuses the same syntax where a value is wanted -- reading a bare append slot is the fatal Cannot use [] for reading.

The semantic detail a weaker lowering skips: PHP CREATES the element at the BIND, not at the first write through the alias. After binding to an append slot the array has one more entry, that entry reads back as null, and only then does writing the alias reach it. Assert the count and the null BEFORE the write, or a lowering that merely produced an alias and deferred creation passes.

Implementation shortcut worth reusing: append the null through the ordinary value path, remember the integer key it took, then resolve the reference source as target-bracket-key. Every rule the element path already applies -- autovivification, writing the container back, building the reference target for a property or static-property root -- is reused instead of reimplemented.
Evidence: php -n 8.5.6 prints null;1;set for the create-then-write sequence, [5,6] for two successive binds, and 5 for a plain local array; elephc now prints the same. Sentinels: disabling the parser rule fails all three tests; creating no element while still returning the key fails exactly the test that reads the count and the null and leaves the two write-through tests green. Symfony measurement: 6 refused files become 5, event-dispatcher/EventDispatcher.php parses in full; the reducer corpus stays at 19 of 37 because it carries no fragment of this shape.
