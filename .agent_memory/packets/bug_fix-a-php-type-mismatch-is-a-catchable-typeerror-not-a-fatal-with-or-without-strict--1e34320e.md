# A PHP type mismatch is a catchable TypeError, not a fatal, with or without strict_types

> Two findings, and the second is the larger one. declare was in the eval parser's reserved word list with no statement…

Two findings, and the second is the larger one.

declare was in the eval parser's reserved-word list with no statement behind it, so the whole directive parsed as a CALL and died on the equals sign inside it — an assignment to a constant. A reserved word with no parser is worse than an unknown one, because the diagnostic points inside the construct instead of at it. Only strict_types is accepted; ticks and encoding change behaviour the interpreter does not model and are REFUSED rather than accepted and ignored, since a silently dropped directive is a divergence nobody can see.

The larger finding: a type mismatch was EvalStatus::RuntimeFatal, and php raises a CATCHABLE TypeError — even WITHOUT declare(strict_types=1). Measured: passing a non-numeric string to a method declared with an int parameter prints the TypeError message and the script KEEPS RUNNING. A fatal makes try-catch around such a call impossible to write, which is a shape real code uses. Three expectations in the suite pinned the fatal and were corrected against php: the scalar parameter mismatch, the scalar and static halves of the return-type test, and the registered-native return type. A return-type violation is a TypeError whatever the callee is; the void return case is genuinely still a fatal and stays one.

STRICT MODE is one gate consulted by both coercion sites, the argument binder and the return-value check, so they cannot drift. It turns every scalar coercion off with ONE exception php keeps: an int where a float is declared still widens. Test it by running the SAME fragment twice, with the directive and without, because the difference IS the feature — a test of the strict half alone passes against an interpreter that always throws.

php's messages, measured: an argument reads NAME(): Argument #N ($param) must be of type DECLARED, GIVEN given with a called-in FILE on line N suffix when there is a call site to name, a method is named Class::method, and a return reads NAME(): Return value must be of type DECLARED, GIVEN returned with no call site at all.

SCOPE limit worth recording: php scopes strict_types to the FILE whose calls it governs, not to the callee. One flag with save and restore gives that for a single file; a call CROSSING files uses the flag in force at binding time, which is the caller's only when the callee does not itself call across files.
Evidence: php -n 8.5.6 prints 6;6;5;7;end without the directive and TypeError;6;5;RetTypeError;end with it, plus the three exact TypeError messages and caught;still running for the lenient catchable case; elephc now prints the same. Sentinels: making the gate always allow coercion fails all four strict tests; removing the int-to-float widening fails exactly the test asserting a float parameter still accepts an int in both modes. The reducer corpus goes from 10 refusals of 37 to 9 with g22_declare_strict.php accepting.
