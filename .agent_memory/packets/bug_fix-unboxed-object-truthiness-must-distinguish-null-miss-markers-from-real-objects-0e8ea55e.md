# Unboxed object truthiness must distinguish null miss markers from real objects

> An EIR value whose PHP storage type is Object can still carry zero or the internal null container sentinel after an a…

An EIR value whose PHP storage type is Object can still carry zero or the internal null-container sentinel after an absent typed-array read followed by null coalescing. lower_is_truthy returned constant true for every Object and lower_empty constant false. A negated assignment condition therefore skipped its null fallback and later called a method on null. Both paths now use the shared container-null predicate; truthiness inverts it on each ABI. Packed values and resources were not changed or certified by this fix. EIR constant folding was checked and only folds actual constant truthiness operands, not arbitrary Object-typed values.
Evidence: Generic object-array reducer failed with label() on null, then passed after truthiness correction. A standalone empty check returned false:full versus PHP false:empty before the sibling fix. The extended native reducer now passes false/empty/none:true/full/set. object_truthiness_checks_null_on_every_supported_target passed for IsTruthy and Cast across macOS ARM64, iOS device/simulator, Linux ARM64 and Linux x86_64 emission. Full r151 had failed at newInstance() on the same raw null marker; a new full HTTP replay remains required.
Verified by: Native macOS regression, PHP CLI comparison, five-target emitter unit test and full-worker trace, September 7 2026.
