# Assembled slices are cached by content: an unchanged rebuild assembles in 339 ms instead of 7.74 s, and a restored object is a hardlink that must be unlinked before any fallback writes it

> Commit ab23772ddc, src/linker/asm cache.rs new + src/linker/mod.rs, on top of the parallel slice split. Every identit…

Commit ab23772ddc, src/linker/asm_cache.rs (new) + src/linker/mod.rs, on top of the parallel-slice split. Every identity gate in the compile-time campaign showed two compiles of one program emit a byte-identical .s, so a slice whose RENDERED text is unchanged must assemble to the same object. That object is now published and reused.

KEY = FNV-1a of the RENDERED slice text (not a byte range of the input — a rendered slice carries its section replay, its promoted renames and its own visibility footer, so it is self-contained), mixed with a cache format version and the assembler's identity: path, arguments, LENGTH and MTIME. The length/mtime matter because /usr/bin/as on macOS IS A SHIM THAT EXECS CLANG, so its output tracks the installed Command Line Tools and a toolchain upgrade keeps the same path.

THE HAZARD THAT SHAPES THE CODE, and the thing to remember if anyone touches this: a cache hit is materialized as a HARDLINK into the build directory. Anything that then writes to that object IN PLACE writes straight through into the cache and poisons it for every future build. The fallback path in assemble_parallel calls assemble(.., obj_path) where obj_path IS slice 0's object, so every fallback must fs::remove_file the restored objects first — unlinking drops the name and leaves the entry's inode alone, which is exactly what makes handing out a hardlink safe.

MEASURED, freshprobe2, release, five configurations back to back: plain single `as` 7.74 s; split 8 no cache 2.69 s; cold cache 2.58 s (publishes 8); WARM CACHE 339.38 ms (8/8 reused) = 22.8x vs serial and 7.6x vs the cold split; one published entry deleted 2.04 s (7 reused, 1 assembled). Correctness, all byte comparisons and so load-independent: cold and warm binaries BYTE-IDENTICAL, and uncached-split / cold / warm / one-dirty are all the same binary; stdout+exit+stderr identical in all five; __text 8,275,360 and __data 1,113,904 in all five including the unsplit path; 315 nm additions all _elephc_xslice_-prefixed, zero losses.

STORAGE lives in its OWN directory ~/.cache/elephc/asm/, never the runtime object's, because runtime_cache::storage prunes by matching a canonical NAME and a shared directory would let one cache evict the other's entries; a test pins that a slice name can never satisfy that matcher. Atomic publish (unique temp then rename), integrity sidecar written only AFTER the object is in place and verified before every reuse, hardlink with copy as cross-device fallback, bounded pruning that keeps this build's entries and never touches a foreign file. ELEPHC_ASM_CACHE=0/off takes the plain path (the identity gate's reference); only those two spellings disable it.

STILL OPEN: the cut policy is size-balanced, so ANY edit moves `total`, moves every cut, and the next build misses on every slice. The cache therefore pays off on an unchanged rebuild (CI re-runs, branch switches, repeated measurement) but not yet in the edit loop. Content-defined cuts (a boundary is a cut iff the hash of ITS OWN symbol name falls in a residue class) fix that, but finer cuts publish more cross-slice symbols — this input already publishes 6,506 at 8 slices — so that change must earn its own measurement.
Evidence: Five freshprobe2 builds back to back on one release compiler with frozen bridge archives and a private XDG_CACHE_HOME: assemble phase 7.74 s / 2.69 s / 2.58 s / 339.38 ms / 2.04 s with the build's own note reporting 0/0/0/8/7 slices reused. cmp exit 0 for uncached-split vs cold, cold vs warm, cold vs one-dirty and warm vs one-dirty binaries; size -m equal in all five; nm diff 315 additions all prefixed, 0 losses.
Verified by: cargo test -j 2 -p elephc --bins linker:: 60 passed 0 failed 0 warnings, including 11 linker::asm_cache::tests (key depends on text and on assembler, published object reused, tampered object refused, object without sidecar refused, canonical-name matcher, slice name is not a runtime-cache name, pruning keeps active entries and ignores foreign files); crate-wide --bins 1859 passed / 19 failed, failing set identical to before the change
