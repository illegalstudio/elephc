# Why the compiled Symfony binary rebuilds its container on every request: the freshness test throws a TypeError that an empty `catch (\Throwable)` swallows, and `unserialize` of undeclared classes drops entries

> The Symfony web binary takes the COLD path recompiling the whole container on every request even though the cache fil…

The Symfony `--web` binary takes the COLD path (recompiling the whole container) on every request even though the cache files are on disk, and it does so SILENTLY: the freshness test in examples/symfony-app/vendor/symfony/dependency-injection/Kernel/KernelTrait.php wraps `is_file($cachePath) && is_object($this->container = include $cachePath) && (!$this->debug || $cache->isFresh())` in a `try` whose `catch (\Throwable $e) {}` body is EMPTY, so anything thrown in there becomes "rebuild, no diagnostic". Everything before the throw was measured identical to php (getProjectDir, getCacheDir, the class name, is_file/filemtime on the .php and the .meta, and the include returning the right container object), so do not re-audit that half. Two elephc defects reach the throw. First, `is_array()` answered false on a promoted `private iterable $resourceCheckers = []` that really holds an array (`get_debug_type` said `array` at the same time), so `\count($this->resourceCheckers)` raised `TypeError: count(): Argument #1 must be of type Countable|array`. That half was fixed by 54723228bd, "answer is_array/is_object/gettype on an `iterable` from the value" (lowering in src/codegen/lower_inst/builtins/type_predicates.rs, count in src/codegen/lower_inst/builtins/count_empty.rs) — re-measure before treating it as still broken. Second, and still open: `unserialize` of an array of 10 objects whose classes are NOT declared in the program returned 5 entries instead of 10 `__PHP_Incomplete_Class` instances, with the object's own fields surfacing into the OUTER array; with the classes declared, all 10 come back correct and the NUL-mangled property names survive. On the real `.meta` file that is 4 entries against php's 10. Note also that the freshness test is AOT code: `ELEPHC_EVAL_TRACE` shows nothing of it, only a direct probe can observe it.
Evidence: Direct probe of 2026-09-02 reproducing the exact shape of KernelTrait::initializeContainer (examples/symfony-app/freshprobe2.php), every step diffed against php: the pre-throw half identical, `is_array()` false on the promoted iterable, the TypeError raised at ResourceCheckerConfigCache.php:65, the empty catch at KernelTrait.php:144 swallowing it. The unserialize half measured on a 10-object array (5 entries returned, fields leaking into the outer array) and on the real .meta (4 entries against php's 10). From the session note dated 2026-09-02. The is_array/count half is claimed fixed by commit 54723228bd, present at HEAD f7a17151de.
Verified by: Probe output diffed against php (session note dated 2026-09-02); commit 54723228bd confirmed present in the log at HEAD f7a17151de on 2026-09-04. The unserialize half has not been re-measured since and no test in the tree pins it.
