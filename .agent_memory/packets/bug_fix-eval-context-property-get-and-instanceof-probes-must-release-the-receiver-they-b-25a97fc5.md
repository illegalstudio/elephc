# Eval-context property-get and instanceof probes must release the receiver they boxed (a property READ stranded one reference per read); array/spread-argument probes still strand the elements

> Commit 35dc808c9a. In a function that owns an eval context, lower eval property get src/codegen/lower inst/builtins/e…

Commit 35dc808c9a. In a function that owns an eval context, `lower_eval_property_get` (`src/codegen/lower_inst/builtins/eval/dynamic_calls.rs`) boxes the receiver with `__rt_mixed_from_value` (which retains) before `__elephc_eval_property_get`, which only BORROWS the cell — and nothing released it, so every property READ stranded one reference on the object it read; `__destruct` then never ran. The "returned-argument" lead was a red herring: bisecting `$keeper->keep($local)` variants showed the leaked object is always the one whose PROPERTY was read (same call without `$held->n` clean; no-arg call plus `$held->n` leaks `$held`), and a function with an eval SCOPE but no eval CONTEXT keeps the AOT path. This is exactly the Symfony configurator shape: `ServiceConfigurator::args()`/`tag()` read `$this->definition` first, matching the measured refcount ladder 1/2/2 (small build) vs 2/4/6 (`--web`), one strand per read. Fix: `lower_eval_property_get` tracks its boxed receiver and releases it with `emit_release_eval_boxed_operands_keeping_result` (a cell the bridge republishes as the result is not double-dropped); `lower_eval_object_is_a` (`introspection.rs`) releases on both exits, its int answer parked in the unused scratch result slot across the decref. Four value tests asserting destructor output and ORDER in tests/codegen/destructors.rs (a2, a5, a6, a14, a15, instanceof b3, configurator shapes b4/b5 with the eval context in the caller and in the method). Filters at baseline: destructors 31/0, eval_bridge 11/0, references 2, nullable 5, locals_retype 8, objects:: 17, late 5, static 29, callable 24 (identical sets), runtime_gc 35 with two newly passing. Attribution done in the same lot: every `static`/`late`/`callable` failure predates 11949c8a41 (A/B by materializing the two pre-commit files with `git show <rev>:<path> > <path>`, restored the same way). The Symfony verdict is STILL byte-identical after the rebuild. STILL OPEN: under an eval context a SPREAD/ARRAY-ARGUMENT call strands the array's ELEMENTS (`takes(...$args)` to a plain AOT function; `call_user_func_array('takes', $args)` on an eval-declared function; positional `takes($local)` clean; `$args = [$local]` alone clean) — a release added at `lower_eval_function_call_array`/`lower_eval_owned_function_call_array` did NOT fix it and was reverted, so the stranded references are on the elements (array→Mixed conversion for the bridge?) or in the spread materialization; Symfony's DI passes arrays everywhere (`->args([...])`). Also a residual ALLOCATION leak: references balanced but 5 heap blocks stranded per property read. `lower_eval_object_class_name` and `emit_eval_object_is_a_named_fallback` box without release but no leak reproduced through them. NOTE: `eval('$seed = 1;')` forces an eval context only in ITS function; the `--web` breadth comes from `if ctx.web` in `promote_eval_bridge_method_argument_locals` (mixed receivers), so the configurator ladder must be measured on the real binary via the bridge's release trace, not in a small probe.
Evidence: Emitted asm of the property-get probe (box, borrow, no release); reducers a2/a5/a6/a14/a15/b3/b4/b5 php -n vs elephc before/after; filter name sets before/after; A/B attribution tables for static/late/callable; Symfony rebuild (730 s) + curl verdict unchanged; heap-debug 7 vs 27 live blocks for 1 vs 5 property reads.
Verified by: commit 35dc808c9a; php -n; --heap-debug; --emit-ir; check_asm_comments.py
