# Pay-for-use for a bridge-backed builtin is a LOWERING-time decision, not a link-time or AST-time one

> opcache get status had to report the runtime script cache, which lives in elephc magician . Calling the bridge uncond…

`opcache_get_status()` had to report the runtime script cache, which lives in `elephc-magician`. Calling the bridge unconditionally would make every program that merely calls `opcache_get_status()` link the interpreter — measured at 16.2 MB against 88 KB.

Three approaches were considered and two rejected:
- WEAK SYMBOLS: works, but needs linker-specific handling across the five supported targets.
- AN AST-LEVEL PREDICATE in the prelude (`detect.rs`): the prelude runs BEFORE name resolution and long before the link set is known, so it could only approximate "does this program use eval", and `eval_bridge` is set by a wide family of dynamic constructs (`Op::Eval*`, `LanguageConstructCall`, dynamic calls). A false negative silently under-reports.
- THE ONE THAT WORKS: decide in the per-instruction LOWERING, reading `ctx.module.required_runtime_features.eval_bridge`. `ir_lower::program` calls `include_lowered_runtime_features` TWICE, the second time right before `validate_module`, so the flag is a settled fact by the time `lower_inst` runs — the same source `register_eval_regex_provider` already reads for regex. When it is false the lowering folds the call to the empty-cache answer (`0`, or an owned empty string through `__rt_str_persist`) and the bridge symbol is never referenced.

There is no circularity risk: the builtin lowers to `Op::RuntimeCall` with its own `RuntimeFnId`, which is not one of the ops that set `eval_bridge`.

VERIFIED, not argued: a probe calling `opcache_get_status()` with no eval compiles to 88 KB and `nm -u` finds zero `opcache_rt` references; the same probe with an eval-hosted include is 16.2 MB.

🔴 GOTCHA that cost a link failure: a bridge call must go through `ctx.emitter.target.extern_symbol(name)`, never a bare string. macOS prefixes C symbols with an underscore, so `abi::emit_call_label(ctx.emitter, "__elephc_eval_…")` emits two underscores where the archive exports three (`___elephc_eval_…`) and the link fails with "symbol(s) not found for architecture arm64". `__rt_*` names are the exception — they are labels this compiler emits into the runtime object itself, so they are named literally.
Evidence: Compiled probes: `status_noeval` 88 KB with 0 bridge references from `nm -u`; the eval-hosted probe 16.2 MB. `tests/opcache_runtime_cache_tests.rs::a_binary_without_eval_reports_only_the_manifest` pins the reported values for the folded path.
Verified by: cargo test --test opcache_runtime_cache_tests (6/6), plus a byte-identical differential of the whole status array against reference PHP 8.5.6.
