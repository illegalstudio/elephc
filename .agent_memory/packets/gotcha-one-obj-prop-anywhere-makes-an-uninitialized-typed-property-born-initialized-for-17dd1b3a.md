# One `&$obj->prop` anywhere makes an uninitialized typed property born initialized for every instance, and the one-line fix exposes a use-after-free

> A property that is a REFERENCE slot is decided WHOLE PROGRAM, and excluding reference slots from the construction tim…

A property that is a REFERENCE slot is decided WHOLE-PROGRAM, and excluding reference slots from the construction-time uninitialized marker makes an unrelated line change every instance's semantics.

`uninitialized_property_marker_offsets` (src/codegen/lower_inst/objects/interface_layout.rs) skips owned reference slots. Whether a slot is a reference depends on whether ANY `&$obj->prop` exists anywhere in the program, so one such line makes that property born INITIALIZED for every instance of the class: `isset()` answers true, `get_object_vars()` lists it, a read PHP refuses returns the empty cell, and an indexed write SEGFAULTS. Reproducer (11 lines, aarch64): `class Seg { public array $a; }` plus `$w = new Seg(); $w->a['k'] = 1;` plus a `&$other->a` elsewhere — segfault; delete the `&` line and it is correct. Two classes identical apart from that line disagree on all four.

Dropping the exclusion LOOKS like a one-line fix and does fix all four, but it must not be shipped as one: it makes the uninitialized guard fire for reference slots, and a CAUGHT uninitialized-property fatal on a reference slot then corrupts an unrelated live heap string — a 9-byte result came back with its first 8 bytes replaced by a pointer, deterministic in shape and ASLR-varying in value, i.e. a freed block's free-list link. The same program with `throw new Error` is clean, and the same probe on a NON-reference slot is clean, so the fault is in what the reference-slot fatal frees on the way out, not in the marker. Fix that release path first.

There are TWO authorities for this table that must stay in step: `uninitialized_property_marker_offsets` (direct allocator) and `class_uninitialized_property_marker_offsets` in src/codegen_support/runtime/data/user.rs (dynamic construction). Changing one alone makes the two describe different observable states for the same class; syncing them does NOT fix the corruption above (measured), so they are independent concerns.
Evidence: aot4.php: two classes identical apart from a later `&$v2->t` answer `n|d|THROW` vs `y|t,d|NOTHROW` where php -n 8.5.6 answers `n|d|THROW` for both. refseg.php (11 lines) segfaults on AOT, exit 139. With the exclusion dropped, t1.php returns `n|d|THROW;<8 pointer bytes>W;z,q` across three runs, bytes varying with ASLR.
Verified by: three-way php/AOT/eval-bridge probe harness; toggling the exclusion and rebuilding the release compiler in both directions
