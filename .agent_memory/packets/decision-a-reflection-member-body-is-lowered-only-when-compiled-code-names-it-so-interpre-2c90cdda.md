# A reflection member body is lowered only when compiled code names it, so interpreted calls found nothing

> Keeps the Reflection member class bodies when the program includes PHP at run time: +1,652,592 B on the Symfony build…

Keeps the Reflection member-class bodies when the program includes PHP at run time: +1,652,592 B on the Symfony build; interim until the interpreter answers ReflectionParameter/ReflectionMethod members itself -- echelon 57.

THE MECHANISM. `lower_builtin_reflection_class_methods()` in `src/ir_lower/reflection.rs` skips every member absent from `referenced_builtin_reflection_methods()`, and that set is built by walking LOWERED EIR -- i.e. by what compiled code names. Interpreted code names members no compiled line mentions, and those calls reached a method with no body: `native_method_error stage=invoke`, printed as the six-word `Fatal error: eval() runtime failed`. Proven both directions with `--emit-asm`: a compiled program calling `getParameters()` and `$p->getName()` emits exactly `ReflectionParameter::getName` and no more; the same program with those calls only in interpreted code emits ZERO `Reflection*` bodies while emitting 1,019 slot accessors for the same classes.

TWO WRONG PLACES TO LOOK, both measured before being discarded. `program_may_reference_reflection` governs class INJECTION only -- all 17 classes were already injected, so widening it changes nothing. And the SPL roots pass (`referenced_builtin_spl_methods`) is a different mechanism; adding reflection roots there emitted no bodies at all.

IT REVERSES A DELIBERATE CHOICE. `spl_discovery.rs` records that reflection values owned by the bridge "are dispatched by Magician, whose interpreter exposes the complete Reflection surface without forcing those bodies into AOT". That holds for the CLASS-level members, which the interpreter answers; it does not hold for `ReflectionParameter`, `ReflectionNamedType` and the parts of `ReflectionMethod` it does not. The reachability test that pinned the old rule is inverted rather than deleted, with the reason in its docblock, so it fails when echelon 57 removes the keeping.

WHAT ECHELON 57 NEEDS, measured so it is not re-derived. A class-scoped slot read in the interpreter WORKS and costs nothing: the member classes are declared by the compiler as slot getters whose slots `reflection_owner_new()` fills identically whichever provider supplied the metadata, and the slots are PRIVATE, so the read runs inside `push_class_scope(<reflection class>)` -- the same scope stack the interpreter uses to run a method of that class, which is what the generated accessor's scope check is written against. But it reaches only 4 of the 66 cells, because `getParameters()`, `getNumberOfParameters()`, `getReturnType()` and `getAttributes()` are REAL methods and every parameter and type cell sits behind `getParameters()`. The remaining 62 are handlers over `EvalReflectionFunctionMethodTarget` (which already carries parameters, visibility, static/final/abstract and the return type) and `EvalReflectionParameterMetadata` (name, position, optional, variadic, by-reference, PROMOTED, has_type, allows_null, type metadata, default value and its constant name, attributes) -- both already assembled in `parameter_metadata.rs` and `member_metadata.rs`, so no compiler publication is needed for either provider.

SIZE NOTE: the obvious narrowing is not one. Dropping the four `ReflectionAttribute` members the interpreter already answers -- on the theory that `newInstance` lowers a body enumerating every attribute class -- is BYTE-IDENTICAL. The cost is spread across the member classes.
Evidence: The 184-cell reflection surface -- 46 members asked of the same class shape declared four ways (runtime include, compiler, eval, builtin) and diffed against php 8.5.6 -- went from 77 different to 11. Both provider tests print the same string, which is the point: `ProbeIncSig[3|1|n:0:int:nonull:builtin:req:fix;tag:1:string:null:builtin:opt:fix;rest:2:int:nonull:builtin:opt:var;]` and the identical line for the compiled class. Symfony binary 108,552,152 to 110,204,744 bytes. Removing the change turns the compiled-provider test red.</evidence>
<parameter name="verified_by">cargo test --test codegen_tests on both provider tests (green with the change, the compiled one red without it); elephc-magician lib 1454 passed 0 failed with no skips; filters eval_bridge 13 of 13 after moving the reachability expectation, include 166 with 4 reds and two of the previous reds fixed; the built binary compiles a PHP file (startup smoke check)</verified_by>
