# The checker refused a class only a runtime include or an autoloader can supply; the autoloader signal cannot be scanned for, because the registry strips the call before the checker runs

> A program that brings classes into existence at RUN TIME — through an include / require whose path is not a literal, …

A program that brings classes into existence at RUN TIME — through an `include`/`require` whose path is not a literal, or through a registered autoloader — was refused at TYPE CHECK when it named one of those classes, where `php -n` 8.5.6 runs it to completion. Measured on fe40d73962.

LOWERING WAS ALWAYS READY; ONLY THE CHECKER STOOD IN THE WAY. `ir_lower::stmt::includes::lower_include` already calls `ctx.apply_eval_barrier()`, so `ir_lower::expr::object_construction` lowers a `new` of an unknown class to `Op::EvalObjectNew`, resolved at run time through the bridge. What refused was `Checker::allows_absent_runtime_class`, which was `!null_probe_scope_is_top_level || eval_barrier_active`, and the checker's own eval barrier is set ONLY by a literal `eval` builtin call (src/types/checker/inference/expr/effects.rs). A runtime include never sets it. The fix adds a program-wide `Checker::program_defers_unknown_classes`.

IT MUST BE PROGRAM-WIDE, NOT POINT-IN-TIME. Both routes can sit textually BELOW the `new` that needs them — `spl_autoload_register(...)` in a bootstrap with the `new` inside a function called later is the ordinary Symfony shape — so a flag set as the walk passes something would still be false at the site being judged.

THE AUTOLOADER SIGNAL CANNOT COME FROM A USAGE SCAN, and this is the trap worth remembering. `autoload::Registry::build` (src/autoload/registry.rs) returns "the program with consumed register sites stripped": it CONSUMES every `spl_autoload_register` call it can collect and removes it from the AST before the checker walks it. So scanning the checker's program answers false exactly when a loader really was registered. Proved with a temporary probe printing the scan's own fields: an inline closure argument, a closure in a variable, and a named function that exists all gave `spl_autoload_register=false introspects=false`; the ONE case the collector had to reject — a string naming a function that does not exist — gave `true`. The inversion is total, so a test using the rejected form would pass while every real form failed. The fix threads `CheckOptions::registers_autoloader` from `autoload_registry.rule_count() > 0` in src/pipeline.rs, ORed with `includes_runtime_php` and with the still-visible call (a rejected registration is still an autoloader at run time). Same lesson as echelon 44's `required_runtime_features.eval_bridge`: ask the pass that owns the answer.

THE REFLECTION GATE IS THE RESOLVER, NOT THE PER-OWNER VALIDATORS. `reflection_class_literal_arg` (src/types/checker/inference/objects/constructors.rs) resolves the literal name and errors `ReflectionClass::__construct(): undefined class 'X'` BEFORE `validate_reflection_class_attrs` is ever reached, so opening only the validators changed nothing. The resolver now carries the written name through unresolved when the flag is set.

DEFERRING IS ONLY HONEST IF THE RUNTIME RAISES THE RIGHT THING, and the terminal decision was in a third place again. `eval_new_object_result` is NOT where an unknown name ends up for the FFI path: `execute_context_try_new_object_outcome` (crates/elephc-magician/src/interpreter/mod.rs) checks AOT metadata, then the context, then the autoloader, and returns `Ok(None)`; its caller `execute_context_new_object_outcome` turned that into `EvalStatus::UnsupportedConstruct`, printed as `Fatal error: eval() fragment uses an unsupported construct`. The split now lives at that terminal caller — never in the `try_` variant, whose `Ok(None)` is what lets the FFI fall through to other autoload context owners. A name PHP provides as a builtin class (catalog: `reflection::class_lookup::eval_reflection_class_like_is_internal`, the predicate `ReflectionClass::isInternal()` already answers from) reports `builtin class "X" is not available in this build` — a gap in this build, since PHP would have constructed it. Any other name gets PHP's catchable `Error: Class "X" not found`, returned as an `EvalOutcome::Throwable` so the caller's `catch` receives it.

STILL DIVERGENT, and it belongs to the registry rather than to this deferral: a loader whose body is `eval("class …")` is consumed into a compile-time rule that cannot resolve it, and is no longer registered at run time either, so the callback chain is empty (`phase=spl_autoload_local callbacks=0`) and the binary prints `Uncaught Error: Class "MadeByLoader" not found` where PHP prints `loaded;done`.

A HARNESS THAT DOES NOT MODEL THE PIPELINE PROVES NOTHING. `tests/codegen/support/projects.rs` builds an autoload registry and then type-checked with default `CheckOptions`, so it would have type-checked a different program than the one that ships; it now threads `registers_autoloader` from the registry it just built.
Evidence: php -n 8.5.6 as the oracle. Before: `new ReflectionClass("S1Plain")` after a non-literal include reported `error[4:26]: ReflectionClass::__construct(): undefined class 'S1Plain'`, and `new MadeByLoader()` under spl_autoload_register reported `error[7:6]: Undefined class: MadeByLoader`; php exits 0 on both. After, four reducers match php exactly and exit 0: `S1Plain;done`, `loaded;7;done`, `Error: Class "NoSuchClassAnywhere" not found;done`, and `loaded;Error: Class "NoSuchClassAnywhere" not found;done`. A runtime-included `new Fiber(...)` now reports `builtin class "Fiber" is not available in this build` instead of a misleading not-found. Identity gate: three no-include control programs, one of them a top-level `new` plus a `new ReflectionClass` on a declared class, emitted byte-identical .s before and after (147,248 / 1,185,077 / 3,990,355 bytes, cmp clean) with identical sorted stderr. codegen `include_` filter by NAME on the same base: 108 passed / 8 failed before, 112 passed / 7 failed after — the brief's gate test `include_reflection::test_caller_reflects_on_a_class_a_runtime_include_declared` went green plus three new tests, and the 7 are exactly a subset of the 8. Full `error_tests` target run on BOTH trees: 1366 passed / 94 failed on each, and `diff` of the two sorted failing-name lists is empty.
Verified by: cargo test -j 2 --test codegen_tests include_ on the parked and restored trees, compared by name; cargo test -j 2 --test error_tests run on both trees with the failing sets diffed by name (identical, 94 each); six php -n 8.5.6 reducers; cmp of three control .s files; a temporary ELEPHC_DEFER_PROBE build that printed the usage scan's own fields across five autoloader shapes; ELEPHC_EVAL_TRACE=1 traces
