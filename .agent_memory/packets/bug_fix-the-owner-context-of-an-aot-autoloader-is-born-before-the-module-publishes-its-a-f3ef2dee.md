# The owner context of an AOT autoloader is born before the module publishes its AOT metadata

> A spl autoload register compiled by the AOT backend ALWAYS hands the bridge a null context handle: the lowering in sr…

A `spl_autoload_register()` compiled by the AOT backend ALWAYS hands the bridge a null context handle: the lowering in `src/codegen/lower_inst/builtins/eval/introspection.rs` loads an immediate zero into the first argument on purpose, so the registration ABI in `crates/elephc-magician/src/ffi/callables.rs` allocates the owner context on the spot and retains it for the whole request. That allocation imported the module's published AOT metadata once, AT CREATION -- and a registration call is usually the request's FIRST eval operation, so nothing had been published yet and it imported nothing. The owner then knew no native signature for any generated class for the rest of the request.

The consequence is invisible until a loader is an AOT static method named by a string. The autoload chain calls it with the one argument it supplies; if the method declares a second parameter with a default, the bridge has no signature and therefore no default to materialize, the generated by-name dispatcher refuses, and the process prints the six-word anonymous `Fatal error: eval() runtime failed`. This was the Symfony `--web` request's stop, in `ClassExistenceResource::throwOnRequiredClass`, whose second parameter is `?Exception $previous = null`.

THE FIX IS LAZINESS, NOT AN EARLIER COPY. Syncing inside the registration ABI changes nothing -- I measured that first and the probe stayed red -- because at that moment there is no snapshot to take. The snapshot is a module constant, so a context still holding nothing of its own can take it later: `sync_global_eval_aot_metadata_when_empty()` in `crates/elephc-magician/src/context/global_registry.rs` is called from `eval_spl_autoload_class_in_owner()` in `crates/elephc-magician/src/interpreter/builtins/symbols/spl_autoload.rs`, the ONE doorway into a foreign owner's callbacks, and imports only when the context's own native function, method, static-method and constructor tables are all still empty.

WHAT THE REDUCERS RULED OUT, each against `php -n` 8.5.6: the namespace (the same probe without one fails identically), the string form of the callable, and the class being unknown to the module -- the emitted assembly registers the method key and both parameters either way, and `--emit-asm` shows the same 74 static-method registrations with and without the second parameter. The axis is the second parameter alone: dropping `?Exception $previous = null` makes the same probe pass on the OLD code, which is the control the test keeps.

TWO MEASURED DEFECTS ARE STILL OPEN ON THIS SAME MECHANISM, both codegen-side and neither touched here. (1) An AOT `class_exists()` / `interface_exists()` never runs the SPL chain: with no eval or include anywhere in the program the eval-bridge runtime feature stays off, `lower_class_like_exists()` in `src/codegen/lower_inst/builtins/member_queries.rs` then folds a literal name against the module class table and lowers a dynamic name to a name-match table, and worse, the emitted assembly for such a program contains no autoload symbol at all -- the `spl_autoload_register()` call itself is gone. php prints the loader line twice where elephc prints nothing. (2) PHP keeps ONE global autoload queue in registration order; elephc keeps a queue per context and runs the current context's callbacks before walking other owners, so a loader registered FIRST in another context runs LAST. A three-context reducer prints php's `aot:One` before the nested include and elephc's after it.
Evidence: Reducer b2 (an AOT class arms `spl_autoload_register(__CLASS__ . '::throwOnRequired')`, a runtime-included file calls `class_exists()` for a missing class) printed `armed;main;driver;` then `Fatal error: eval() runtime failed` where php prints `armed;main;driver;cb:Probe\Missing\One;no;driverdone;done`; after the fix the two are identical. Control b3, the same probe with a single-parameter loader, was green before and stays green. The committed test `test_a_nested_autoload_calls_an_aot_loader_that_left_a_parameter_to_its_default` crosses three contexts and asserts php's `ctxA;ctxB;closure:ProbeNeedNested;ctxC;aot:ProbeNeedAot:null;n;ctxCdone;n;ctxBdone;done`; with the fix removed it fails with `ctxA;ctxB;closure:ProbeNeedNested;ctxC;` and the same anonymous fatal.
Verified by: cargo test --test codegen_tests test_a_nested_autoload_calls_an_aot_loader_that_left_a_parameter_to_its_default (green with the fix, red without it); filters eval_bridge 13 of 13, include 157 with 8 known reds, destructors 44 with 3, runtime_gc 35 reds, objects 17 reds, elephc-magician lib 1334 passed with the 16 known reds -- every count equal to the branch baseline
