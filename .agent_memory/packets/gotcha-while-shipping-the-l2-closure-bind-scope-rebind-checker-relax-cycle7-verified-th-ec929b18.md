# While shipping the L2 Closure::bind scope-rebind checker relax (cycle7), verified the real

> While shipping the L2 Closure::bind scope rebind checker relax cycle7 , verified the real Symfony ContractsTrait::doG…

While shipping the L2 Closure::bind scope-rebind checker relax (cycle7), verified the real Symfony ContractsTrait::doGet() target shape against elephc and found THREE more pre-existing, unrelated runtime/codegen gaps that block full end-to-end compilation of that exact file (all reproduced with NO Closure::bind/scope-rebind involvement, i.e. not caused by this campaign's work): (1) `unset($arr[$k])` on a BY-REF array parameter (`function f(?array &$m) { unset($m['k']); }`) fails EIR codegen with "unsupported EIR backend feature: unset target shape with N lowered operands" for N=1 AND N=3 — completely unrelated to arg count, so likely the by-ref-array-element unset lowering path itself is missing. (2) A CHAINED assignment into two different targets through a closure invoked via the dynamic callable-descriptor path (`$obj->prop[k] = $byRefParam[k] = val;` inside a closure called as `$f(...)` where $f holds a Callable-typed/descriptor value, NOT a direct function call) SEGFAULTS (exit 139) — reproduced with a PUBLIC property (no visibility involved) and with a REGULAR (non-static) closure; the SAME statement works fine as a normal top-level function body. (3) A BY-REF `?array &$metadata` parameter's write-through does not propagate to the caller's variable when the closure is invoked through the SAME dynamic callable-descriptor path (`\Closure::bind(function(&$x){$x['k']=1;}, null)($caller_var)` leaves $caller_var empty) — likely the same family as the existing "Uniform-invoker per-arg leak" gotcha but this is a correctness gap (silently dropped write), not just a leak. All three are in the callable_descriptor_invoke / uniform-invoker codegen path (`src/codegen_ir/lower_inst/`), NOT in closure_bind.rs, static_locals.rs, or the checker — explicitly out of this campaign's assigned perimeter (which excluded call-argument/invoker materialization). Confirmed the checker's own scope-rebind relaxation works correctly end-to-end for the parts these gaps don't block (protected property read AND write through a bound-scope parameter, verified with compile_and_run — see test_closure_bind_scope_rebind_allows_protected_property_{access,write}_on_param in tests/codegen/callables/closures.rs).
