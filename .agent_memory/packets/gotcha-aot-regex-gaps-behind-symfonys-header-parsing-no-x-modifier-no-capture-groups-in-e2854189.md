# AOT regex gaps behind Symfony's header parsing: no /x modifier, no capture groups in preg_match_all, no named groups

> Symfony's HeaderUtils::split needs four things the AOT regex path does not do; the interpreter magician already does …

Symfony's `HeaderUtils::split()` needs four things the AOT regex path does not do; the interpreter (magician) already does all of them, so this is an AOT-only gap.

1. The `/x` (extended) modifier is not parsed. `__rt_preg_strip` in src/codegen_support/runtime/system/preg_strip.rs scans trailing modifiers for `i`, `m`, `s`, `u`, `U` and `A` and silently ignores everything else, so a `/x` pattern is compiled with its literal whitespace and `#` comments treated as pattern text and simply never matches. The shim already had the plumbing -- `ELEPHC_PCRE2_CFLAG_EXTENDED` (0x4000) in src/native_deps/recipes/pcre2_shim.c maps to PCRE2_EXTENDED -- only the modifier byte 'x' (120) was missing from the scanner. FIXED on both arches.

2. `preg_match` with a named capture group wrote a HASH into a destination the checker typed as an indexed array. `src/types/checker/inference/expr/effects.rs` widened only the ELEMENT type to `Mixed`, keeping the container `Array(...)`, on the belief that `Array(Mixed)` reads both key kinds back. It does not -- consumers read the static type. The runtime side was already correct (`__rt_preg_match_capture_named` builds the ordered hash). FIXED by typing the destination `AssocArray{Mixed, Mixed}` when a LITERAL pattern declares `(?<name>`, `(?P<name>` or `(?'name'` (lookbehind `(?<=` / `(?<!` excluded).

3. AOT `preg_match_all` only ever materializes capture group ZERO. src/codegen_support/runtime/system/preg_match_all.rs says so outright ("one outer pattern-order column: capture group zero"), so subgroups, named groups and PREG_SET_ORDER are all absent: `preg_match_all('/([a-z]+)([0-9]+)/', 'a1b22', $m, PREG_SET_ORDER)` answers `[["1","22"]]` where PHP gives `[["1"],["22"]]`. STILL OPEN. `preg_replace_callback` already hands the callback a full per-match numbered capture array, and `types::checker::builtin_spl_classes::regex` already builds RegexIterator's ALL_MATCHES/SET_ORDER/OFFSET_CAPTURE semantics on top of it, so that is the cheap construction route rather than new assembly.

4. `preg_match_all` with PREG_SET_ORDER and zero matches fills `$matches` with `[[]]` where PHP leaves `[]` (PATTERN_ORDER correctly gives `[[]]` in both). This is what makes Symfony answer `Cache-Control: , private` instead of `no-cache, private`: `parseCacheControl('')` returns a non-empty array, so `!$this->cacheControl` is false and `computeCacheControlValue()` takes the `$header.', private'` branch with an empty `$header`. STILL OPEN, and blocked on 3 (the AOT path never reads the flags word at all).
Evidence: Measured with php -n 8.5.10 against compiled binaries in examples/symfony-app (which has the pcre2 native package): `preg_match('/ a b /x', 'ab')` gave 0 vs PHP 1; `preg_match('/(?<word>[a-z]+)(?<num>[0-9]+)/', 'a1', $n)` gave `n=[0,4,1,0,-1]` vs PHP's five keyed entries; `preg_match_all('/\d+/', 'abc', $m, PREG_SET_ORDER)` gave `[[]]` vs `[]`; `preg_replace_callback` with numbered groups already matches PHP exactly.</evidence>
