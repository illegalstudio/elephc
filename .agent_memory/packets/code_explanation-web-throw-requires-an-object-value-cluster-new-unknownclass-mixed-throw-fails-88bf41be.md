# --web "throw requires an object value" cluster: new UnknownClass -> Mixed -> throw fails

> Symfony web cluster "Type error: throw requires an object value" 65x has ONE compiler mechanism: new <ClassNotInClose…

Symfony --web cluster "Type error: throw requires an object value" (65x) has ONE compiler mechanism: `new <ClassNotInClosedWorld>` degrades to PhpType::Mixed in src/types/checker/inference/objects/constructors.rs:47-59 (warn_absent_class path, intended for class_exists-guarded optional deps), then `throw <Mixed>` hits the generic `_` arm in src/types/checker/stmt_check/control_flow.rs:340-343 (StmtKind::Throw) and src/types/checker/inference/expr/mod.rs:406-409 (ExprKind::Throw). Three reasons the class is unknown: (A, dominant ~50) conditionally-declared Symfony exception classes — Symfony\Component\Cache\Exception\{InvalidArgumentException,CacheException,BadMethodCallException,LogicException} are each declared inside `if (interface_exists(SimpleCacheInterface::class)) { class X ... } else { class X ... }`; the checker's top-level class collection never descends into If bodies, and unlike functions (src/resolver/hoist_conditional_functions.rs) there is NO hoist_conditional_classes pass — so `new InvalidArgumentException` -> Mixed. (B ~10) missing PHP Core throwables not in the builtin registry: \ErrorException, ArithmeticError, DivisionByZeroError, ArgumentCountError, UnhandledMatchError, AssertionError — registry is src/types/checker/builtin_types/declarations.rs:69-79 (Throwable/Error/TypeError/ValueError/Exception/RuntimeException/JsonException/Fiber/FiberError) + src/types/checker/builtin_spl_exceptions.rs:21-35 (SPL Logic/Runtime tree). The set_error_handler(static fn(...) => throw new \ErrorException(...)) arrow-fn appears in many cache adapters. (C ~3) genuinely-absent optional-dep classes e.g. ProcessFailedException (symfony/process not installed). Ordinary `catch(\Exception $e){throw $e;}` re-throws do NOT error (typed catch var is Object); the only variable throws that error are chained from a Mixed `new` (e.g. ErrorHandler.php:441 $errorAsException = new \ErrorException(...); :453 throw $errorAsException). Fixes: quick-win = accept Mixed/nullable-object/union-with-Throwable in the two Throw arms (same gradual-typing family as tasks #17/#41/#64); proper = register missing Core throwables + add a hoist_conditional_classes pass mirroring hoist_conditional_functions.rs (run after the interface_exists/class_exists fold collapses the if/else to one branch).
Evidence: Reproduced with elephc debug binary: `throw new \DomainException` (registered SPL) compiles; `throw new \ErrorException`/`\ArgumentCountError`/`\DivisionByZeroError` (missing Core) and `throw $mixed` fail with the exact message. Conditional-decl repro: class declared in if/else both branches is NOT discovered -> throw errors, while top-level class is fine. catch-var rethrow confirmed OK.
Verified by: ./target/debug/elephc on minimal repros + examples/symfony-app --web (65 occurrences)
