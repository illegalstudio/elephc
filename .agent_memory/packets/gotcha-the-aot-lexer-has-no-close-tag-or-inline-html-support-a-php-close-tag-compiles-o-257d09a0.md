# The AOT lexer has no close-tag or inline-HTML support: a PHP close tag compiles only through the runtime-include path, which keeps the newline PHP swallows

> The compiler's own lexer in src/lexer/scan.rs demands the PHP open tag as the first characters of the file and then t…

The compiler's own lexer in src/lexer/scan.rs demands the PHP open tag as the first characters of the file and then treats the whole rest as pure PHP: the enum in src/lexer/token.rs has no close-tag and no inline-HTML variant, and a question mark always lexes as one of the question-mark operators. A template file — a close tag, then markup, then an open tag again, the ordinary shape of a plain-PHP view — therefore cannot be STATICALLY included: it fails with an "Unexpected" diagnostic naming the Question lexeme, and if the inline part is HTML or CSS the lexer trips even earlier, reporting "Unexpected character 'p' after decimal literal" on a CSS rule. The interpreter is the opposite: crates/elephc-magician/src/lexer/php_tags.rs implements find_php_close_tag, so the same template reached through a RUNTIME include (the eval bridge) renders fine. That asymmetry is why a plain-PHP view works at run time and refuses at compile time; when planning template work, choose the runtime-include path or add the missing lexer support, and expect no checker or backend diagnostic to tell you which path you are on. One measured divergence remains on the working path: PHP swallows exactly one newline immediately after a close tag and elephc keeps it, which made a real Symfony response body 39,323 bytes against php's 39,315 over 8 close-tag sites — a body that is byte-different but visually identical, so template output must be compared byte for byte, never by eye.
Evidence: Probe pass of 2026-09-02 (session note): static inclusion of the Symfony welcome template failed to compile with the two lexer errors quoted; the same template through a runtime include rendered, and the response body differed from php by exactly 8 bytes over 8 close-tag sites (39,323 vs 39,315), with the "Welcome to Symfony!" marker present in both. Re-checked in the tree at HEAD f7a17151de on 2026-09-04: searching src/lexer/token.rs for close-tag or inline-HTML variants returns 0 hits, src/lexer/scan.rs:40-46 requires the open tag at the start of the file, and crates/elephc-magician/src/lexer/php_tags.rs:20 defines find_php_close_tag.
Verified by: Compile attempts and a byte-count diff of the rendered body against php (session note dated 2026-09-02); the lexer facts re-verified by reading the files at HEAD f7a17151de on 2026-09-04.
