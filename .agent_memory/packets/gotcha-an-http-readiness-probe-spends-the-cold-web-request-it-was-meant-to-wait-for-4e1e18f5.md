# An HTTP readiness probe spends the cold web request it was meant to wait for

> Two harness defects that silently corrupt every before/after number taken on a web binary. Both bit me while gating t…

Two harness defects that silently corrupt every before/after number taken on a `--web` binary. Both bit me while gating the AOT-metadata Arc change, and any curl-based script in the Symfony campaign that shares the shape carries the same distortion.

1. AN HTTP READINESS PROBE SPENDS THE COLD REQUEST. The obvious loop `until curl -s -o /dev/null --max-time 2 http://127.0.0.1:$port/; do sleep 1; done` is wrong: the listener accepts immediately but the first Symfony request takes seconds, so `--max-time 2` fails and the loop RETRIES -- and every retry is a real request the worker starts executing. With `--workers 1 --max-requests N` this exhausts N before the measurement begins, the supervisor recycles the worker mid-run (the worker pid changes under you, so the process you sampled is not the one that served), and the request you finally time is a WARM one. The tell was a trace file growing past 60k lines for what should have been one request. Fix: readiness is a TCP connect, `until nc -z 127.0.0.1 $port; do sleep 1; done`, then exactly ONE curl with a long `--max-time`.

2. `ELEPHC_EVAL_TRACE=1` IS ~10% OF THE WORKER'S OWN PROFILE. One Symfony request emits ~5400 lines, i.e. ~5400 `write()` syscalls; in a `sample` of the worker that is `write (in libsystem_kernel.dylib)` at 10.7% of exclusive samples, and it inflates the request itself (6.0 s traced vs 5.1 s untraced on the same binary). The trace run and the timing/sample run must be SEPARATE: traced for the stop point and the trace diff, untraced for wall time and profiling.

Two smaller ones from the same session:
3. `sample <pid> N 1 -mayDie -file X &` followed by `kill $sampler` writes NO FILE AT ALL. Give it a window near the request length and `wait` for it.
4. The generated web binary is STRIPPED, so frames come back as `??? (in index) load address ...` and there is no `__elephc_eval*` share to read without `--keep-symbols`. The symbol-independent substitute is allocator traffic from the sample's EXCLUSIVE section -- and note the count there is the LAST field on the line, not the first, unlike the inclusive section above it.

When diffing two traces, normalise `identity=<decimal>` (object heap addresses), `0x...` pointers and the listen port, or the diff is thousands of meaningless lines. Always sentinel the normaliser against a knowingly different trace, or an over-aggressive `sed` will report "identical" for anything.

Scripts live in the session scratchpad exec-lane: `webserve.sh` (serve a prebuilt binary, TCP readiness, one request, `TRACE=0` switch), `tracediff.sh`, `sampshare.sh`, and `HARNESS-NOTES.md`.
Evidence: Observed directly: worker pid changed between polls (79151 -> 80824) and the trace passed 66601 lines for a nominal single request under the HTTP readiness loop; after switching to nc -z, the same binary gave a stable 5444-line trace and one worker pid. Traced vs untraced on the identical binary: 6.0 s / 5444 lines vs 5.1 s, with write() at 338 of 3516 exclusive samples (10.7%) in the traced run and 57 of 2636 (2.2%) untraced.
Verified by: Re-running the same prebuilt Symfony --web binary under both harness shapes and comparing worker pids, trace line counts and sample composition
