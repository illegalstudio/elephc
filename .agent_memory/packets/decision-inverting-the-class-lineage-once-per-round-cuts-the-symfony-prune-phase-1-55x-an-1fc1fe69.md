# Inverting the class lineage once per round cuts the Symfony prune phase 1.55x, and the retained set was proven identical by a sorted keep-set dump

> Commit 91fd0b420e perf optimizer . seed vtable slot families in src/optimize/reachability/graph.rs ran class is or de…

Commit 91fd0b420e (perf(optimizer)). `seed_vtable_slot_families` in src/optimize/reachability/graph.rs ran `class_is_or_descends_from(candidate, lineage_root)` for EVERY (kept method x live class) pair, allocating a fresh String per parent hop plus a HashSet per call. Nothing in that product depends on the method — the predicate is a pure function of the declaration index's parent chains — so the chains are now walked ONCE per fixed-point round and inverted into `lineage root -> positions in live_classes`.

MEASURED, release compiler, Symfony --web, paired so only this change differs: "Pruning unreachable declarations" 24.44 s -> 15.75 s = 1.55x, -8.69 s. The earlier estimate of ~18 s was optimistic; the real figure is 8.7 s because the seeding walk is not the whole phase.

THE METHOD THAT MATTERS — how the retained set was PROVEN rather than argued. A temporary probe (ELEPHC_DUMP_REACHABILITY=1) prints the four keep-sets SORTED at the end of `graph::compute`; sorting is the whole point because they are HashSets whose raw iteration order differs run to run. Dump on HEAD+probe, dump on HEAD+probe+change, diff. Result: freshprobe2 950 entries identical, Symfony entry 19,782 entries identical (1,457 classes, 654 externs, 719 functions, 16,952 methods). Remove the probe with `git apply -R <probe>.patch`, which reverses only the probe's hunks and leaves the real change standing — `git show HEAD:graph.rs > graph.rs` would take BOTH down, since both edit that one file, and `git stash` is forbidden here because the stash stack is shared across every worktree of this repo.

TWO TRAPS HIT WHILE DOING IT.
1. `--web` and `--emit-asm` are MUTUALLY EXCLUSIVE (src/cli.rs), so the Symfony keep-set dump has to be a full --web compile; there is no cheap way to stop after pruning.
2. BSD grep SILENTLY PRINTS NOTHING — not even `grep -c` returning 0 — when it decides a file is binary, and the Symfony stderr capture contains a byte that trips that. My first comparison reported "0 keep-set lines" for Symfony and looked like the probe had never fired. Use `grep -a` on any captured compiler stderr in this repo.

A PHP-level characterization test must be run GREEN ON THE UNPATCHED TREE first (apply only the tests.rs half, or apply the patch then `git show HEAD:graph.rs > graph.rs`); if it is red there, the assertion is wrong, not the change.
Evidence: Sorted ELEPHC_DUMP_REACHABILITY=1 keep-set dumps captured with and without the change on two inputs, compared with cmp: freshprobe2 950 lines exit 0, Symfony 19,782 lines exit 0. Paired --timings phase tables from the same two runs. Identity gate: cmp exit 0 on emitted assembly, linked binary, program stdout, nm -n, and sorted stderr against the same compiler without the change.
Verified by: cargo test -p elephc --lib: vtable_lineage_index_tests 3/3, the PHP-level pin green on the UNPATCHED tree first and after, optimize::reachability 85 passed + 1 pre-existing red; crate-wide --lib 1640 passed/19 failed and --bins 1842 passed/19 failed, both failing sets exactly the 19 pre-existing reds (passed counts up by the 4 tests this change adds)
