# Uninitialized typed property: PHP's quiet fetch is a fetch mode with a call barrier, and elephc has three paths

> PHP's "quiet fetch" for an uninitialized typed property is a FETCH MODE, not error suppression, and elephc has THREE …

PHP's "quiet fetch" for an uninitialized typed property is a FETCH MODE, not error suppression, and elephc has THREE paths that must each implement it.

Measured against `php -n` 8.5.6 (30-cell family probe): `isset($o->p)` is false, `empty($o->p)` is true, `$o->p ?? $d` is `$d`, `$o->p ??= $v` assigns, `property_exists` is true, `get_object_vars` OMITS it, a plain read raises `Error: Typed property C::$p must not be accessed before initialization`, `&$o->p` raises the DIFFERENT sentence `Cannot access uninitialized non-nullable property C::$p by reference` (and does NOT raise for a NULLABLE typed property, which it initializes to null), and an indexed write `$o->p['k'] = 1` AUTO-INITIALIZES to an array — unless the declared type cannot hold one, which is `TypeError: Cannot auto-initialize an array inside property C::$p of type int`.

Two scope rules that a naive "answer instead of raising" gets wrong, both measured:
- the mode reaches down the WHOLE property/dim chain, including an uninitialized link in the MIDDLE (`$n->leaf->t ?? 'D'` answers 'D' with `Node::$leaf` itself uninitialized), so it must wrap the whole operand, not the outermost node;
- it does NOT cross a call boundary: `f($o) ?? 'D'` and `$o->getT() ?? 'D'` both RAISE. This is the opposite of `@`, which does propagate into callees — and `@` never stopped a throw anyway, which is why the error suppression already wrapped around `??` was not enough.

In the interpreter the depth must be THREAD-LOCAL, not a context field: one PHP expression routinely crosses several eval contexts, and a per-context counter goes quiet on the context that entered `isset()` while the context performing the read still raises. Saving/zeroing it in `push_call_frame` and restoring in `pop_call_frame` makes the call barrier automatic.

THE THIRD PATH, still open: AOT-compiled code reading an EVAL-OWNED object's property goes through `lower_eval_owned_property_get` (src/codegen/lower_inst/builtins/eval/dynamic_calls.rs), which emits `push_class_scope` -> `__elephc_eval_property_get` -> `pop_class_scope`. Nothing there pushes the quiet mode, so `empty($this->p[$k])` compiled AOT over an eval-owned receiver still raises. This is the Symfony stop: `CheckCircularReferencesPass::$checkedLazyNodes`. Identify it by that exact three-symbol sequence under `ELEPHC_EVAL_TRACE=ffi` — the absence of a `phase=statement` line is NOT evidence the caller is compiled, because statement tracing does not cover method bodies.
Evidence: 30-cell family probe against `php -n` 8.5.6: both paths IDENTICAL (diff, not size) once no reference is present; interpreter identical with references too. Magician --lib 1501/0. Filter sets 789 passed/59 failed vs HEAD baseline 788/59, and all 59 fail on HEAD unchanged (0 passed/59 failed run by name). Commit 3c567c41ab.
