# Under `--web`, a function whose method receivers need a Mixed fallback gets an eval context, and every statically typed method call in it is probed through the bridge FIRST — a measurement trap and a per-callsite size cost

> This is the architectural fact behind a whole family of "green standalone probe, red real request" investigations, an…

This is the architectural fact behind a whole family of "green standalone probe, red real request" investigations, and it is worth knowing before you write any probe for a `--web` defect. In promote_eval_bridge_method_argument_locals (src/ir_lower/expr/method_calls.rs:201, reached from method_calls.rs:164 and nullable_method_calls.rs:139), a receiver that needs a Mixed fallback triggers `if ctx.web { ctx.declare_eval_context_local(); }` — so a `--web` build declares an eval context in FAR more functions than an ordinary build. In any function that owns such a context, src/codegen/lower_inst/method_dispatch.rs prefixes EVERY statically typed method call with lower_eval_owned_method_call: the receiver is boxed, array arguments are boxed, the bridge entry is called, and only on a miss (the ordinary case for AOT code) does the native dispatch run. The bridge only BORROWS the cells it is handed — each entry takes a Copy handle with no Drop — so the frame stays the owner and every emitter must release what it boxed on both exits. Two consequences to plan around. FIRST, the measurement trap: four batches of standalone destructor probes (32 forms, up to the real vendor loader) were all green while the real request failed, because the difference was the BUILD, not the shape of the code. An `eval('$seed = 1;')` inside the enclosing function forces an eval context in THAT ONE function and is a fine three-line reducer, but it does NOT reproduce the WIDTH of `--web`; for anything scale-dependent (a refcount ladder, a leak that only appears across a call chain) compile a small program WITH `--web` and measure on the real binary. SECOND, the cost: the probe is code emitted PER CALLSITE — a Symfony configurator's `args()` method went from roughly 100 bytes to 3,452 — plus one bridge call at run time for every AOT method call in those functions. That makes "declare the eval context only in functions that can actually meet interpreted code" a size AND execution-time lever for `--web`, not just a correctness cleanup.
Evidence: Established over the Symfony --web campaign of 2026-09-03..04 (session notes of those dates): four batches of standalone destructor probes green while the request failed; the Symfony configurator's refcount ladder measured 1/2/2 in a small build against 2/4/6 under --web; `args()` emitted at 3,452 bytes against ~100; the release-trace ladder on the real binary unchanged (object_refs 1..16, 6/632 at 1) after three separate leak fixes, which is what proved the `eval()` reducer does not stand in for the --web width. Code re-read at HEAD f7a17151de on 2026-09-04: the `if ctx.web { ctx.declare_eval_context_local(); }` guard sits at src/ir_lower/expr/method_calls.rs:215 behind the dynamic_method_receiver_needs_mixed_fallback test, and method_dispatch.rs:105 calls lower_eval_owned_method_call.
Verified by: Probe batches, emitted-size comparison and ELEPHC_EVAL_RELEASE_TRACE ladders on the real --web binary (session notes dated 2026-09-03 and 2026-09-04); the lowering sites re-read at HEAD f7a17151de on 2026-09-04.
