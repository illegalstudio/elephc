# DEFERRED, found but not fixed: an eval-declared subclass of a native Throwable calling an

> DEFERRED, found but not fixed: an eval declared subclass of a native Throwable calling an inherited native method tha…

DEFERRED, found but not fixed: an eval-declared subclass of a native Throwable calling an inherited native method that nothing in AOT-compiled code (and nothing in another reachable method's body) ever calls fails at 'stage=invoke' with RuntimeFatal, even though the class-declaration gate now accepts it. Reduced case: `class A8 extends RuntimeException {} ... $e->getPrevious()->getMessage();` -- getMessage()/getCode() work (their EIR bodies happen to be reachable because Exception::__toString()'s own compiled body calls them, and __toString is unconditionally emitted), but getPrevious() has no other producer and its EIR body is dead-code-eliminated, so the runtime dispatch has no symbol to invoke. This is DIFFERENT from the abstract-flag bug fixed today (repo:...:an-eval-declared-class-extending-any-native-class...): that bug was about REFLECTION METADATA being wrong; this one is about the METHOD BODY itself never being emitted at all. A full fix needs a method-body reachability seed (parallel to seed_runtime_throwable_class_names' class-name seeding) that keeps the whole Throwable interface surface (getMessage, getCode, getFile, getLine, getTrace, getTraceAsString, getPrevious, __toString) reachable whenever eval_bridge is required, in src/optimize/reachability (which currently has no eval_bridge-aware seeding at all -- only a blunt whole-program eval_forced escape hatch gated by a --with-crates=eval flag, PruneOptions.eval_forced in src/optimize/reachability.rs, unrelated to whether the program calls the eval() builtin). Not attempted this session due to time budget; the class-declaration and parent::__construct fixes already shipped do not depend on this.
Evidence: scratchpad/r200/cls8.php: php -n prints prevmsg:inner; elephc-compiled probe fatals 'unsupported MethodCall expression' with ELEPHC_EVAL_TRACE showing phase=native_method_error stage=invoke class=RuntimeException method=getPrevious
