# The interpreter kept one call stack per eval context where php has one per request

> TWO INDEPENDENT DEFECTS kept debug backtrace from telling an autoloader what asked for the class, which is the one th…

TWO INDEPENDENT DEFECTS kept `debug_backtrace()` from telling an autoloader what asked for the class, which is the one thing Symfony's `ClassExistenceResource::throwOnRequiredClass` reads.

REACHABLE BY NAME. PHP resolves an unqualified call written inside a namespace against the namespaced name first and the global name second, and generated code hands the bridge the namespaced candidate. The bridge decided by asking which eval context DECLARED that function -- `execute_context_function_outcome()` consulted only `context.function(name)`, and `lower_eval_owned_function_call()` in `src/codegen/lower_inst/builtins/eval/dynamic_calls.rs` went straight to an undefined-function fatal when `__elephc_eval_function_owner_context()` answered null. No context declares a RUNTIME HANDLER: the two backtrace functions, the OPcache family, the procedural date aliases, every builtin the interpreter implements. So `debug_backtrace()` written in a namespace died as `Call to undefined function <namespace>\debug_backtrace()`. The fix is one table for both questions: `context_function_is_callable()` is the predicate `function_exists()` answers with AND the set the call dispatches through, exposed over the ABI as `__elephc_eval_bridge_can_call_function`, and the positional and array function-call entries now accept the null handle that means "resolve this yourself".

ONE CALL STACK PER REQUEST. The frames lived on the context that pushed them, and the interpreter runs an autoload callback in the context that REGISTERED it, not the one that asked. A loader calling `debug_backtrace()` therefore saw its own frame and nothing above it. Moving the ledger to a thread-local -- a request runs on one thread and a forked web worker gets its own copy -- makes the trace php's.

TWO MORE FRAMES WERE SIMPLY NEVER RECORDED. A class probe written in COMPILED code reaches the autoload chain through `__elephc_eval_dynamic_class_exists` and recorded nothing, where the interpreter's own probes had pushed a frame for a while. And php describes an include and an `eval()` as frames of their own: the include named for the form written (include / include_once / require / require_once) and carrying the path as its single argument, the eval carrying NO arguments because the code it ran is not one.

STILL SHORT, deliberately: a COMPILED call is not a frame the interpreter records, so a namespaced `debug_backtrace()` inside a compiled function counts one frame fewer than php. Recording those means a push and a pop in every generated function, which every binary pays for; it sits below what Symfony reads (frames 0 and 1 are the loader and the probe).

METHOD NOTE worth reusing: the reducer that finally reproduced this needed the eval bridge to be ON. With no eval or include anywhere in the program the runtime-feature flag stays off, and the compiler emits a hard undefined-function error instead of ever calling the bridge, so the same PHP looks like a different defect.
Evidence: Three probes went from wrong to identical to php 8.5.6. A namespaced unqualified call at file scope: php `piece;main;array;0;printed;done`, elephc previously `Fatal error: eval() fragment uses an unsupported construct`. A loader started by a compiled class probe: php `0:report|Probe\Loader\Reporter|::|NopeA;1:class_exists|-|-|NopeA;2:none`, elephc previously `1:none;2:none`; the interpreted-inside-eval variant adds php's eval frame above it, and `new` on a missing class correctly adds no frame at all on both sides. Include and eval frames: php `1:include|-|-|piece.php` and `1:eval|-|-|-`, elephc previously `1:none`. All three committed tests fail with the fix removed.
Verified by: cargo test --test codegen_tests on the three new tests (green with the fix, all three red without it); elephc-magician lib 1372 passed 0 failed with no skips; codegen filters eval_bridge 13 of 13, destructors 44 with 3 known reds, runtime_gc 35 known reds, objects 17 known reds, include 162 with 7 reds where the only name not in the previous set is a separate pick regression reduced to four lines

## Verification

Three probes went from wrong to identical to php 8.5.6. A namespaced unqualified call at file scope: php `piece;main;array;0;printed;done`, elephc previously `Fatal error: eval() fragment uses an unsupported construct`. A loader started by a compiled class probe: php `0:report|Probe\Loader\Reporter|::|NopeA;1:class_exists|-|-|NopeA;2:none`, elephc previously `1:none;2:none`; the interpreted-inside-eval variant adds php's eval frame above it, and `new` on a missing class correctly adds no frame at all on both sides. Include and eval frames: php `1:include|-|-|piece.php` and `1:eval|-|-|-`, elephc previously `1:none`. All three committed tests fail with the fix removed.
