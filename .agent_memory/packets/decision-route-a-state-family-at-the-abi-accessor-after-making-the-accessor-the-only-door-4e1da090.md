# Route a state family at the abi accessor, after making the accessor the only door

> Migrating a global state family to per context storage is cheap when every access already goes through a shared acces…

Migrating a global state family to per-context storage is cheap when every access already goes through a shared accessor, and expensive otherwise — so the first move is to make the accessor the only door, not to start editing call sites.

Done for the exception family (`_exc_value`, `_exc_handler_top`, `_exc_call_frame_top`), the one blocking M1 in .plans/sandbox-threads.md. 301 references across ~45 files, ~300 of which already went through four `abi::` symbol accessors. The routing itself is then: add the fields to `_rt_ctx`, give ctx.rs a name→offset table (`per_context_symbol_offset`), and have the four accessors consult it and emit a ctx-relative access instead of a symbol reference. Not one call site changed.

The tripwire that makes it safe: a ctx build stops declaring the legacy `.comm` words in data/fixed.rs, so any path that still names the symbol fails the LINK on the first build instead of silently sharing one cell between two contexts. Concat and heap already use it.

The catch, and the reason the preparation matters: the link tripwire only sees NAMES. A two-step access (`emit_symbol_address` into a scratch, then a bare `str x0, [x9]`) still names the symbol on the address line, so the symbol disappears from the data section AND the store keeps writing wherever the address resolved — it survives the tripwire completely. Twelve sites had that shape, plus three fully hand-rolled. All fifteen had to be routed through the accessors BEFORE the table could be trusted, and `exception_state_is_only_reached_through_the_abi_accessors` now forbids both shapes at the source level (it deliberately does not accept `emit_symbol_address` as an allowed accessor for these symbols, which is only possible because zero sites use it that way now).

Also: `emit_ctx_zero_fields` must reset every new field, because the M1 case it exists for is a POOLED context starting a new request — an exception cell is exactly the kind of state that would otherwise be inherited from the previous request.

Verification shape worth reusing for the remaining families (fibers/stack limit, GC counters, shared buffers): compile one fixture that exercises the family in both modes, then check three things — the ctx build contains ZERO references to the legacy symbol, it contains the expected number of ctx-relative accesses at the field's offset, and it LINKS (the tripwire reporting no missed path). Then run the suite in both modes with ELEPHC_RT_CTX.
Evidence: A ctx build of a fixture throwing and catching three ways contains zero `_exc_value` references and fourteen `[x28, #72]` accesses, links (the tripwire finding no missed path), and prints exactly what the legacy build prints. Exceptions slice 78 passed in both modes; errors+spl+objects 626 passed in ctx mode; bin suite 1936; both library ABI sentinels still report PRESERVED, since the boundary's exception accesses sit between the export prologue's emit_ctx_publish and emit_scalar_native_return's emit_ctx_restore_foreign.
Verified by: cargo test --bin elephc (1936); ELEPHC_RT_CTX=on cargo test --test codegen_tests -- exceptions (78), -- errors spl:: objects (626); cargo test --test cdylib_tests -- rt_ctx (2)
