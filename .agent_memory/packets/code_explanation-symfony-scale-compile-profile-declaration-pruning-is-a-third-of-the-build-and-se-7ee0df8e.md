# Symfony-scale compile profile: declaration pruning is a third of the build and seed_vtable_slot_families + class_is_or_descends_from alone are ~27 %; the assembler is another quarter

> Sampled on the REAL Symfony web keep symbols debug build 2026 09 03, 19 × 5 s windows at ~13 % duty cycle, 72,889 sam…

Sampled on the REAL Symfony `--web --keep-symbols` debug build (2026-09-03, 19 × 5 s windows at ~13 % duty cycle, 72,889 samples under `pipeline::compile`). Phase shares: `prune_unreachable_declarations` 31.95 % (five of twelve minutes); `emit_and_link` 44.97 % of which `linker::assemble` 24.24 % (the single blocking `as`, comparable to all of codegen); the rest is check, lower, EIR opt, codegen. Lever shares (inclusive): F3 `seed_vtable_slot_families` 13.69 % + `class_is_or_descends_from` 13.75 % ≈ 27 % of the whole compile (`seed_live_methods` 29 %, `fixed_point` 30 %) in `src/optimize/reachability/graph.rs` — this is THE compiler-side lever at Symfony scale (~2,000 classes), consistent with the synthetic exponent 1.90 in classes. F2: `validate_function` 12.97 %, `compute_dominators` 9.57 %, `dominator_bitsets_to_map` 5.30 % in `src/ir/validator.rs` — but every sampled frame comes from `ir_passes::driver` (the debug-only per-pass validation); `validate_lowered_module` (the release-side call) was never sampled, so the RELEASE win of F2 is well under 5.3 %; what carries over is the ratio: the HashMap materialization is 55 % of `compute_dominators`. F4: `Module::clone` 3.44 %, entirely under `emit_runtime_extern_wrapper_inline` (the EXTERN arm) — the builtin arm was sampled 0 times, so a fix limited to the builtin arm of `src/codegen/lower_inst/runtime_wrappers.rs` recovers nothing; the follow-up is one accumulating clone or pre-interned extern names, with the open question whether accumulated DataIds keep the assembly byte-identical. F7: `type_check_methods_until_stable` 4.34 %, `ClassInfo::clone` 1.15 % — much smaller than the probe suggested. Real ranking: F3 ≫ parallel assembly (B1) ≫ F2 (small in release) > F7 > F4 ≈ 0. Six draft patches (F2, F7 with a dirty flag verified against the old clone-and-compare under cfg!(test) or ELEPHC_VERIFY_CLASS_DIRTY=1, B0 cache-key bits exhaustive by construction, F3 lineage-root index with the old predicate kept verbatim as the test oracle, F4 builtin arm, and a temporary reachability-dump probe) pass `git apply --check` on 76a771f80b but are UNBUILT and UNVERIFIED; they live outside the repo with a RUNBOOK (apply --check, narrow cargo filters, two `--emit-asm` runs `cmp -s`, sorted dump of the four reachability sets, `--timings`).
Evidence: macOS `sample` windows on PID of the running elephc --web compile (14:51–15:03), aggregated by symbol prefix; window sequence mapped to phases; the probe-scale profile and synthetic exponents from the earlier read-only pass agree on F3's direction.
Verified by: sample-based profile of the real build; git apply --check of the six patches
