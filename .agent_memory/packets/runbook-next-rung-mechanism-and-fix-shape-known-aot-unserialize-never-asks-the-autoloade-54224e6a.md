# NEXT RUNG, mechanism and fix shape known: AOT unserialize never asks the AUTOLOADER, so a .meta class that is not compiled becomes an object with no resolvable class

> OPEN, but fully located, and the fix shape is settled. WHERE. Symfony web now runs 2545 trace lines and dies binding …

OPEN, but fully located, and the fix shape is settled.

WHERE. Symfony `--web` now runs 2545 trace lines and dies binding `ContainerParametersResourceChecker::supports(ResourceInterface $metadata)`. The opt-in `phase=dynamic_method_bind_error` trace prints tag, identity and class:
`arg_tags=["6:4468956496:<unresolved>"]` — an object whose class `runtime_object_class_name` cannot name. The parameter binding cannot decide `instanceof` for a class it cannot resolve, so it refuses with `RuntimeFatal` where PHP raises a TypeError.

MECHANISM. The object comes from `ResourceCheckerConfigCache::safelyUnserialize()` over `var/cache/dev/*.meta`. That method is COMPILED, so the AOT `unserialize` runs, not the interpreter's. In `src/codegen_support/runtime/system/unserialize/decoder_*.rs` the class is instantiated with `__rt_new_by_name`, which answers 0 for a class that is not in the compiled class table, and the decoder then takes `__rt_unser_obj_incomplete`. PHP does not stop there: it calls `unserialize_callback_func`, whose entire purpose is to give the AUTOLOADER a chance before the value degrades to `__PHP_Incomplete_Class` — and Symfony points that ini at its own autoloader, which is why its `.meta` files deserialize into real resources under `php -n`.

FIX SHAPE, already proven twice this session. `__elephc_eval_dynamic_class_exists(ctx, name_ptr, name_len, autoload)` already exists as an FFI export and already runs the SPL chain, but the unserialize runtime is emitted for EVERY program while that symbol exists only when the bridge is linked. So it needs the hook-slot pattern: a `.comm` function-pointer slot the interpreter installs at context creation, loaded and null-checked before use — exactly what `_elephc_eval_dynamic_object_destruct_fn` and this session's `_elephc_eval_generator_protocol_fn` do. Then, where `__rt_new_by_name` answers 0, call the hook with `autoload = 1` and retry once.

DONE ALREADY, and NOT sufficient on its own: the INTERPRETER's `unserialize` now runs the autoload chain before falling back to `__PHP_Incomplete_Class` (`eval_unserialize_hydrate_object`). That is correct PHP semantics and stands on its own, but Symfony's call site is compiled, so it does not move this rung.

SECOND, INDEPENDENT DEFECT worth fixing either way: an UNDECIDABLE nominal parameter check should answer "not an instance" (a TypeError PHP code can catch), not "cannot proceed" (a runtime fatal that kills the request).
Evidence: scratchpad/trace.log line 2542 after the interpreter-side autoload fix: still `arg_tags=["6:4468956496:<unresolved>"]`, which is what proved the failing call site is the COMPILED unserialize rather than the interpreter's. cargo test -p elephc-magician stayed at 1687/2 across that change.
Verified by: The Symfony --web trace before and after the interpreter-side fix; the magician suite at its pre-existing baseline.
