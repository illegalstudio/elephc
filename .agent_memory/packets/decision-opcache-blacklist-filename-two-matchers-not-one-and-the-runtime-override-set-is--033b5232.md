# opcache.blacklist_filename: two matchers, not one, and the runtime-override set is now 18

> opcache.blacklist filename now governs the runtime script cache: a matched path RUNS and is simply never stored. The …

`opcache.blacklist_filename` now governs the runtime script cache: a matched path RUNS and is simply never stored. The semantics were derived from reference PHP 8.5.10 probe by probe, and three of them contradict the obvious guess:

1. THE REFUSAL REPLACES THE MISS. php-src hands a blacklisted file back to the original compiler before any cache accounting, so `misses` does NOT move and nothing is written to `opcache.file_cache` either — only `blacklist_misses` moves. The check therefore belongs at the TOP of `fill_entry`, before the file-cache consult and before `misses += 1`.
2. `blacklist_misses` COUNTS REFUSALS, NOT FILES. Including a blacklisted script twice counts twice.
3. THE DIRECTIVE VALUE IS ITSELF A `glob()` naming the blacklist FILES, and php-src loads EVERY match and unions their entries — the word "matching" in its own `No blacklist file found matching:` message is literal.

TWO DIFFERENT MATCHERS ARE INVOLVED and conflating them is the easy mistake: the directive value is matched as a POSIX glob (must consume the whole filename), while each LINE inside the files matches as a PREFIX — anchored at the start, open at the end, so a bare directory blocks everything under it. Both use `*` and `?`, and in BOTH of them the wildcards STOP AT `/`. The only difference is the end anchoring. `blacklist_miss_ratio` is `blacklist_misses * 100 / (misses + blacklist_misses)` — hits are not in the denominator.

SCOPE-RULE COUNT UPDATE. The packet "A directive that starts baking behavior must leave the runtime-override set" records "16 excluded, 38 overridable" — accurate when written, now dated. `opcache.file_update_protection` and `opcache.blacklist_filename` have since joined, so it is 18 excluded and 36 overridable. Its LESSON is unchanged and still load-bearing: a directive that starts baking behaviour must leave the runtime-override set, the null arm must follow, and the test suites' exemplar directives have to move to a directive that is still reporting-only. All three bit again for the blacklist, exactly as that packet predicts — three tests used `blacklist_filename` as their example of a reporting-only STRING and had to migrate to `opcache.lockfile_path`.

The reported `opcache_get_configuration()['blacklist']` lists the resolved entries VERBATIM (wildcards unexpanded, keyed 0..n-1) on both surfaces: the eval interpreter reads the loaded patterns in-process, native code reads them back across the bridge with a count key plus an indexed accessor, mirroring how `scripts` is already reported.
Evidence: Reference PHP 8.5.10 probes for each rule, plus a differential corpus of 34 paths x 26 patterns (exact paths, bare prefixes, both wildcards, doubled and trailing stars, regexp-special characters, case variants, four directory depths) comparing the shipped matcher against reference's own caching decisions: zero disagreements. The ratio formula was derived from a run reporting 82.8571428571 for blacklist_misses=29 and misses=6, which no other candidate formula produces.
Verified by: 15 unit tests, 12 end-to-end tests, the differential corpus, and cross-compilation on both Linux targets.
