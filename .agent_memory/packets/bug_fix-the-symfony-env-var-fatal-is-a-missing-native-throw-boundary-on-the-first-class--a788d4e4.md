# The Symfony env-var fatal is a MISSING native-throw boundary on the first-class-callable invoker, and bounding the invoker itself is the wrong half of the fix

> LOCATED AND PROVEN BY EXPERIMENT, fix not landed because the obvious placement regresses a test. This is the mechanis…

LOCATED AND PROVEN BY EXPERIMENT, fix not landed because the obvious placement regresses a test. This is the mechanism behind `Fatal error: Uncaught EnvNotFoundException: Environment variable not found: "APP_RUNTIME_ENV"` that gated every `%env(default:...)%` resolution in the Symfony `--web` request.

THE SHAPE. The generated container calls
  $container->getEnv('string:default:kernel.environment:APP_RUNTIME_ENV')
(var/cache/dev/ContainerTvPT0Dp/getSecrets_VaultService.php). That unwraps to `EnvVarProcessor::getEnv`, whose `default:` branch is
  try { $env = $getEnv($next); } catch (EnvNotFoundException) { }
and `$getEnv` is `$container->getEnv(...)` -- a FIRST-CLASS CALLABLE created in AOT code. The interpreter calls it through the callable descriptor's `invoker` pointer. That invoker is emitted by `emit_runtime_callable_invoker_inline` (src/codegen/lower_inst/runtime_wrappers.rs) via `emit_runtime_callable_invoker`, i.e. with `catch_native_throws = false`. So a Throwable raised inside it goes to `__rt_throw_current` and unwinds natively past the interpreted `try`, which never gets to look at it. The sibling `emit_runtime_callable_invoker_with_exception_boundary` exists and does install the `setjmp` boundary; only the eval function-registration path used it.

PROOF IT IS THE RIGHT MECHANISM. Switching that one call site to the bounded form made the EnvNotFoundException fatal DISAPPEAR: the `default:` processor caught it, the fallback parameter resolved, and the request advanced past every env var it had been dying on -- straight to a new and unrelated blocker (three `filter_var(): array $options passed through a mixed value is not supported by elephc yet` warnings, then SIGSEGV, worker terminated by signal 11). That is several échelons of forward progress from one line.

WHY IT WAS REVERTED, and this is the part that matters for the real fix. Bounding the invoker converts a native throw into a returned status for EVERY caller of that invoker, not just the interpreter. AOT dispatch needs the throw to keep propagating natively. `cargo test --test codegen_tests exception` went from the 145/2 baseline to 144/3, the new red being
  codegen::runtime_reachability::test_shared_mixed_callable_dispatch_preserves_results_and_exceptions
  left: "not-reached|7|12|9|24|8|9:10|11"   right: "caught:boom:3|7|12|9|24|8|9:10|11"
-- a callable that throws stopped reaching its PHP `catch`. So the boundary must NOT live on the invoker.

WHERE THE FIX BELONGS. Bound the INTERPRETER'S ENTRY into the descriptor instead, so AOT dispatch keeps native propagation while a throw raised under an interpreter-initiated call comes back as a status: the eval callable-call helper (`__elephc_eval_value_callable_call_array`, emitted in src/codegen/lower_inst/builtins/eval/introspection.rs) is the natural place, mirroring what `eval_method_helpers.rs` and `eval_constructor_helpers.rs` already do for method and constructor calls -- both of those DO install a TRY_HANDLER and both work. An equivalent alternative is emitting two invokers per signature (bounded and unbounded) and having the interpreter use the bounded entry.

METHOD NOTE: `method_call_out` in crates/elephc-magician/src/runtime_hooks/ops/collection_calls.rs was bracketed with enter/leave prints and every enter had its leave, which correctly proved the METHOD path is bounded -- and misled me into concluding no path longjmps. The callable path was never bracketed and is the unbounded one. Bracket the specific extern you suspect, not a neighbouring one.
Evidence: One-line change at src/codegen/lower_inst/runtime_wrappers.rs:32 from `emit_runtime_callable_invoker` to `emit_runtime_callable_invoker_with_exception_boundary`, then a full `--web` rebuild (exit 0, 75 s) and cold request: before, `Fatal error: Uncaught Symfony\Component\DependencyInjection\Exception\EnvNotFoundException: Environment variable not found: "APP_RUNTIME_ENV".` with worker exit 255; after, that fatal is gone entirely and the worker instead prints three `filter_var(): array $options passed through a mixed value is not supported by elephc yet; flags ignored` lines and dies with `terminated by signal 11`. Regression slice: baseline 145 passed / 2 failed (both reproducing on an untouched tree); with the invoker bounded, 144 passed / 3 failed, the new red being test_shared_mixed_callable_dispatch_preserves_results_and_exceptions with the exact left/right quoted above. Tree restored to 145/2 after reverting. Oracle throughout: `php -n` 8.5.10 on the same app returns HTTP 404, 39,315 bytes, containing "Welcome to Symfony!".
Verified by: Compile-and-curl of examples/symfony-app with and without the one-line change, plus cargo test --test codegen_tests exception (RUST_MIN_STACK=33554432, --test-threads=4) before, during and after

## Verification

One-line change at src/codegen/lower_inst/runtime_wrappers.rs:32 from `emit_runtime_callable_invoker` to `emit_runtime_callable_invoker_with_exception_boundary`, then a full `--web` rebuild (exit 0, 75 s) and cold request: before, `Fatal error: Uncaught Symfony\Component\DependencyInjection\Exception\EnvNotFoundException: Environment variable not found: "APP_RUNTIME_ENV".` with worker exit 255; after, that fatal is gone entirely and the worker instead prints three `filter_var(): array $options passed through a mixed value is not supported by elephc yet; flags ignored` lines and dies with `terminated by signal 11`. Regression slice: baseline 145 passed / 2 failed (both reproducing on an untouched tree); with the invoker bounded, 144 passed / 3 failed, the new red being test_shared_mixed_callable_dispatch_preserves_results_and_exceptions with the exact left/right quoted above. Tree restored to 145/2 after reverting. Oracle throughout: `php -n` 8.5.10 on the same app returns HTTP 404, 39,315 bytes, containing "Welcome to Symfony!".
