# A directive with compiled behaviour needs THREE things wired, and two of them bite silently

> Making an opcache. directive act rather than only report touches three places, and two failures here were found only …

Making an `opcache.*` directive act (rather than only report) touches three places, and two failures here were found only by end-to-end probes, not by the type system.

1. ORDERING AGAINST THE EVAL-CONTEXT INSTALL. Generated code installs the compiled OPcache configuration inside `ensure_eval_context`, which runs at the program's FIRST eval — NOT at program start. Anything that writes the configuration before that (an `ini_set()` at the top of the script) is silently clobbered when the install finally runs. The fix is to keep runtime overrides in a SEPARATE thread-local table and apply them when the configuration is read, so write order stops mattering; `__elephc_eval_opcache_swap_directive` carries an `as_override` flag to tell the compiled install from a runtime `ini_set()`. Any future "runtime knob" for the script cache has to do the same, or it will work in a probe that evals first and fail in one that does not.

2. THE PRELUDE'S HELPERS ARE PAY-FOR-USE, SO A LITERAL MAY NOT REFERENCE ONE FREELY. `opcache_get_configuration()`'s directive literal is built by `directive_runtime_value_expr`, and making it consult the `ini_set()` override store made every program that called ONLY `opcache_get_configuration()` fail to compile with `Undefined function: __elephc_opcache_ini_override` — the store is injected with the `ini_get`/`ini_set`/`ini_get_all` surface, which such a program does not pull in. The rule that fixes it is also the precise one: consult the override store only when `ini_set` is actually injected, because without that wrapper no override can exist. `tests/opcache_manifest_tests.rs` caught this, not the opcache ini tests.

3. THE EMPTY STRING IS NOT A USABLE "UNSET" SENTINEL for an INI override store. `__elephc_ini_scan` rewrites the boolean barewords (`off`/`false`/`no`/`none`/`null`) to `''`, so `ini_set('opcache.validate_timestamps', 'off')` stores exactly that and a value-only read cannot distinguish it from absent. The store needs an explicit presence query.

Scope note that keeps the model honest: `ini_set()` succeeds for exactly the intersection of php-src's 18 `PHP_INI_ALL` directives and the ones elephc's cache reads — THREE (`revalidate_freq`, `validate_timestamps`, `file_update_protection`). `opcache.max_file_size` is NOT among them; it is `PHP_INI_SYSTEM` (access=4) and reference PHP's own `ini_set()` returns false for it, so elephc refusing it is exact. Succeeding for the other 15 `PHP_INI_ALL` directives would move a reported value while nothing changed, which is the contradiction the override-scope rule exists to prevent.
Evidence: The ordering bug showed as a probe where ini_get moved to '77' but the cache kept the compiled value (hits=1 where hits=0 was required). The pay-for-use bug showed as opcache_manifest_tests::enable_and_enable_cli_are_anded_on_cli failing to COMPILE with Undefined function: __elephc_opcache_ini_override. The sentinel bug was caught by reading __elephc_ini_scan before shipping. The PHP_INI_ALL intersection was computed against reference PHP 8.5.10's ini_get_all access bitmasks.
Verified by: cargo test --workspace --lib --no-fail-fast (3550 passed, 0 failed) plus the nine opcache integration suites; the ini_set sequence verified byte-identical to reference PHP 8.5.10
