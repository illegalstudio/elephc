# A diagnostic with the wrong shape is a new DIFF, not a PASS

> Adding a php warning the interpreter was missing does NOT move a differential sweep case unless the warning is FRAMED…

Adding a php warning the interpreter was missing does NOT move a differential-sweep case unless the warning is FRAMED the way php frames it. `php -n` 8.5.6 prints, for every non-fatal diagnostic, a leading blank line, the severity, the message, the position, and a newline:

    \nWarning: Undefined variable $missing in /path/probe.php on line 3\n

Measured for all three severities (`Warning`, `Notice`, `Deprecated`); only the word before the colon differs. elephc printed the bare message, so the undefined-variable warning added in 67fe685c1c could not turn a single one of its 18 sweep cases green -- the output differed from php either way. Fix the CONTRACT before adding emitters: everything downstream reads it (`error_reporting` decides emission, `set_error_handler` receives severity/file/line).

`crates/elephc-magician/src/interpreter/diagnostics.rs` owns the shape: `EvalDiagnostic::{Warning, Notice, Deprecated}` plus one framing function. The position is the one the USER wrote and is knowable only because `EvalStmt::SourceLine` markers move the call site as an included file executes -- before that work every diagnostic inside an include said line 1. Omit BOTH halves of the location when there is no call site rather than printing `in  on line 1`; that is php's own behaviour for a fragment.

CONFORMANCE CATCH found while migrating: ArrayIterator's "using an object as a backing array" message is a DEPRECATION in php, not a warning. Moving emitters onto a severity-typed API is what surfaced it -- a bare `warning()` API cannot express the difference and so hides it.

DO NOT bulk-migrate every `values.warning` caller. There are ~53; roughly fifteen sit in LEAF HELPERS that take no `context` and therefore have no position to report. A mechanical rewrite either fails to compile or invents a location. Threading a context through those helpers is a separate change. FOLLOW-UP still open: migrate the remaining ~49 sites, threading context where needed.

STILL BLOCKING THE CENSUS, compiler-side: `__rt_diag_warning` in `src/codegen_support/runtime/diagnostics.rs` writes to fd 2, while php CLI writes diagnostics to STDOUT (measured: stderr is empty for all three severities). Correct framing on the wrong stream still interleaves differently with `echo` output, so the sweep cases cannot turn PASS until that is changed on both architectures.
Evidence: php -n 8.5.6 measured for Warning/Notice/Deprecated, all on stdout with stderr empty. Four tests in interpreter/tests/undefined_variable_warning.rs, one through the include path asserting a real file and line 3. Sentinel: dropping the location from the framing fails exactly that test. The blanket migration of 53 call sites was attempted and reverted after the compiler named ~15 leaf helpers with no context in scope.
Verified by: cargo test -p elephc-magician --lib &lt; /dev/null -- 1501 passed, 0 failed, 0 filtered, in a second CARGO_TARGET_DIR. Commit b588969b48.
