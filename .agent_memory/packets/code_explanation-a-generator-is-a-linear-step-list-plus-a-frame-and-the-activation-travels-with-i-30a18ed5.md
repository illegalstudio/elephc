# A generator is a linear step list plus a frame, and the activation travels with it

> Each generator in the eval interpreter gets a flat STEP LIST plus a frame holding a program counter, its own boxed sc…

Each generator in the eval interpreter gets a flat STEP LIST plus a frame holding a program counter, its own boxed scope, the auto-key counter, foreach slots, delegation state, the open `try` regions and its ACTIVATION. Resuming is continuing at the stored index. Only constructs that CONTAIN a yield are flattened; everything else stays a statement subtree the ordinary evaluator runs atomically, so the generator module owns control flow and nothing else. The frame is taken OUT of the context while it runs, because the body needs the context mutably and the frame lives inside it.

Two designs were rejected and should stay rejected. A resumable tree walker must reify every loop's and every `try`'s position anyway and then re-descend the tree on each resume. OS threads cannot work because the runtime handles and scope pointers are not `Send`, and a generator outlives the scope that created it.

Two rules a re-implementation gets wrong. The activation -- function name, class scope, late-static-bound class, magic frame -- travels WITH the generator, because it is resumed from anywhere: without it `self::`, `static::`, `__CLASS__` and private-member access inside a generator method resolve against whoever happened to call `next()`. And `finally` is emitted once per EXIT EDGE (normal completion, each catch clause, the unhandled path, and every return/break/continue that crosses the region) plus a standalone destruction copy; a shared copy would need a return address the step list has nowhere to put.

The predecessor was not merely incomplete, it was wrong in kind: closures were lowered eagerly into an `ArrayIterator`, which evaluated every yielded expression at call time, so an infinite generator hung, `send()` had nowhere to land, and the body ran before php runs it.
Evidence: 29 tests whose every expected string is php -n 8.5.6 output, including auto-key numbering where an explicit key does NOT advance the counter, `yield from` preserving inner keys down a three-level chain, switch fall-through, a match arm that is the yield itself, a throw on the resumption after a suspension reaching the catch that covered it, and destruction unwinding nested finally blocks innermost first.
Verified by: Commits 7ece14702e, 47cb71ccdb, c7a4392588; suite 1311 passed / 16 pre-existing failed, zero new reds.
