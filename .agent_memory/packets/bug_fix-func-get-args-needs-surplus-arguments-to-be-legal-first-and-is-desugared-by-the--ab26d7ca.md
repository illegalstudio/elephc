# func_get_args needs surplus arguments to be legal first, and is desugared by the compiler not a builtin

> func num args , func get args and func get arg were missing from the eval interpreter 10 php src sweep cases . Two th…

`func_num_args()`, `func_get_args()` and `func_get_arg()` were missing from the eval interpreter (10 php-src sweep cases). Two things about them are easy to get wrong.

1. THEY ARE NOT CATALOG BUILTINS AND MUST NOT BECOME ANY. The compiler answers them by DESUGARING at compile time (`src/func_args/`, driven from `src/pipeline.rs`), rewriting each call into plain PHP before lowering. So there is no AOT registry binding, and adding a shared-catalog contract would demand one that cannot exist -- the exact trap that panicked the compiler on every input in 12ec45f0cf. Implement them as interpreter intrinsics, intercepted in `eval_call` (interpreter/expressions/calls.rs) BEFORE the function lookup.

2. IMPLEMENTING THEM IS NOT ENOUGH. `bind_dynamic_positional_arg` in interpreter/dynamic_functions/method_binding.rs refused any positional argument past the declared parameter list (`if param_index >= bound_args.len() { return Err(RuntimeFatal) }`). php ACCEPTS a surplus argument for a user function, method and closure alike -- it binds to nothing and is reachable only through this trio. So the trio was unreachable even once written: the call died before its own body ran. Both halves have to land together because neither is observable alone. Keep the fatal for the OTHER branch of that condition (the same parameter filled twice, positionally and by name), and note a builtin is different -- php raises ArgumentCountError there and that path does not go through this binder.

VALUES ARE NOT SIMPLY THE FRAME'S. `php -n` 8.5.6 prints `changed`, not `original`, for `function f($a) { $a = "changed"; $all = func_get_args(); echo $all[0]; } f("original");`. A DECLARED parameter must be read from the SCOPE (so a reassignment shows); an argument past the declared list has no variable and can only come from the call frame's recorded args. Parameter names resolve differently for a plain function (`context.function`), a closure (`context.closure(..).function()`) and a method (`context.class_method(current_class_scope, name)`) -- handling only plain functions passes most tests and fails methods/closures.

OPEN ODDITY, worth its own investigation: an array built with `values.array_new(n)` + `array_set` from the FRAME's argument cells carries the right keys and values (`var_dump` byte-identical to php) but `json_encode` renders it as an object `{"0":7}` rather than a list `[7,8]`, while the identical `array_new`+`array_set` sequence in the array-literal path yields a list. Neither the retain nor its position changes it; the difference is that a literal stores freshly evaluated cells and this stores the caller's. Passing the result through `eval_array_values_result` (what `array_values()` does) settles it -- measured, not reasoned: `json_encode(array_values($a))` printed `[7,8]` for the very array whose direct encoding printed `{"0":7,"1":8}`.
Evidence: Oracle php -n 8.5.6 over six shapes, byte-identical: `3:[1,2,3]:1,2,3|2:["x","y"]|1:["only"]|["changed"]|2-[7,8]|2-["a","b"]`. Five tests in interpreter/tests/func_args.rs. Sentinels: refusing surplus arguments again fails four of five (including the trio tests, showing the dependency); not reading declared parameters from the scope fails exactly the reassignment test with `original` against `changed`.
Verified by: cargo test -p elephc-magician --lib &lt; /dev/null -- 1497 passed, 0 failed, 0 filtered, in a second CARGO_TARGET_DIR. Commit on the worktree branch after b04b5f197b.
