# SipHash over String keys was the compiler's hottest leaf; swapping the reachability phase to FxHasher cut Symfony pruning 22.5% with a byte-identical binary

> A sampled profile of one Symfony web build release compiler, sample mayDie at 1 ms, four windows put core::hash::sip:…

A sampled profile of one Symfony `--web` build (release compiler, `sample -mayDie` at 1 ms, four windows) put `core::hash::sip::Hasher::write` at the TOP of the leaf frames in EVERY window — 4,164 leaf samples in the pruning/lowering window against 617 for `seed_live_methods`, the hottest elephc frame beside it, with `hash_one::<String>` at 682 and `String::clone` at 412. The compiler keys almost everything on `String` and `(String, String, bool)` — class names, method triples, symbol keys — and paid a cryptographic hash on every probe.

THE GATE IS SAFE FOR A REASON WORTH KNOWING, because changing a hasher changes ITERATION ORDER and that normally makes a byte-identical gate meaningless. It does not here: std's `HashMap` uses `RandomState`, which seeds itself per PROCESS, so two runs of today's compiler ALREADY iterate these maps in different orders. Two `--emit-asm` runs of one fixture nevertheless produce identical output — measured across six separate invocations, all sha256 76cf50e5…, 6,787,310 bytes — which PROVES the emitted assembly does not depend on map order. A deterministic hasher only replaces a random order with a fixed one; it cannot make an order-independent output order-dependent. So the `.s` gate holds unchanged, and the only outputs that can move are ones that were already nondeterministic — the known "Unused variable" stderr ordering — which is why gates here compare SORTED stderr.

WHAT IT BOUGHT, swapping only `optimize::reachability` (graph, usage, expressions, index) via a `crate::fast_hash` alias module:
- Symfony `--web` pruning 14.59 s to 11.30 s, −3.29 s, −22.5 %, with the linked binary BYTE-IDENTICAL at 108,317,352 bytes and 631 class-name symbols.
- On a 300-class magic-method fixture, pruning 207 ms to 161 ms on top of the magic-map inversion, so 249.68 ms to 161.26 ms combined, −35.4 %.
- The phases the change cannot touch moved slightly UP (type-check 15.56 to 16.08 s, codegen 26.90 to 27.22, lowering 7.39 to 7.90), which is what makes the pruning drop attributable rather than a machine-wide speedup.

WHERE THE RIPPLE STOPPED, and it is small: five files in the reachability tree, plus two signatures made generic over the HASHER (`reconcile::check_result` and `retain_function_keyed_map`) so one helper can serve a fast-hashed keep-set against a std-hashed `CheckResult` map without rebuilding either. `PruneOptions`'s two input sets stay std-hashed on purpose — they are read a handful of times, they are not in the fixed point, and it is a public signature. `rustc-hash` was already in `Cargo.lock` as a transitive dependency, so this pins no new version.

STILL SIPHASH, and this is where the remaining prize is: type-check (16.08 s), lowering (7.90 s) and codegen (27.22 s) all still key on `String` with std's hasher, and the profile puts the same frames at the top of those windows too.
Evidence: Sampled profile: `core::hash::sip::Hasher::write` 4,164 leaf samples in the pruning/lowering window (top elephc frame beside it, `seed_live_methods`, 617), 747 and 545 in the two type-check windows, with `hash_one::<String>` 682/758/547 alongside. Paired Symfony `--web --heap-size=1073741824` from the worktree root, cache off: pruning 14.59 s before, 11.30 s after; binary 108,317,352 bytes and 631 `_class_name_` symbols on BOTH sides. Paired three-run fixture measurement: 201.57/207.57/206.28 ms before the hasher, 164.97/161.26/159.25 after, with `--emit-asm` output 6,787,310 bytes and sha256 prefix 76cf50e59477a82e in every run on both sides. `cargo test -p elephc --lib` run on the parked and restored trees: 1648 passed / 19 failed on each, and `comm` of the two sorted failing-name lists is EMPTY in both directions.
Verified by: cargo test -p elephc --lib on both trees compared by name (1648/19 identical); paired Symfony --web builds; paired three-run fixture measurement with sha256 of the emitted assembly identical on both sides; sample -mayDie profile at 1 ms
