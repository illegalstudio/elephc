# FIXED: an interpreter-created Generator driven by native `__rt_gen_*` read fiber fields it never had; the probe belongs in the runtime helpers, not at each call site

> FIXED, and it is the fix that removed the Symfony web SIGSEGV. THE BUG. Generator is an AOT class, so a generator the…

FIXED, and it is the fix that removed the Symfony `--web` SIGSEGV.

THE BUG. `Generator` is an AOT class, so a generator the INTERPRETER created is indistinguishable from a native one at every native iteration site. The native `__rt_gen_current/key/valid/next/rewind/send/throw/get_return` helpers drive a generator through the Fiber fields a `Generator` object carries at offsets 184..224 (`FIBER_STATE_OFFSET`, `GEN_LAST_KEY_OFFSET`, `GEN_LAST_VALUE_OFFSET`, ...). An interpreted generator never filled them -- its state is an `EvalGeneratorFrame` in the eval context, keyed by object identity -- so those reads return whatever the object storage happens to hold. Measured twice: a `ret` into a two-byte address with `sp` inside `heap_buf`, and `__rt_mixed_unbox` on `0x100000020` during `foreach`.

WHERE TO PUT THE PROBE. NOT at the call sites. `iterator_to_array`, `iterator_apply`, `foreach` over a static class, `foreach` over an `iterable`, and a plain `$g->current()` reach the protocol through at least four different lowering paths (`spl.rs`'s `emit_to_array_loaded_iterator_object`, `iterators.rs`'s `emit_interface_dispatch_call`, `emit_object_iterator_method_call`, `emit_generator_interface_fast_path`), and `emit_interface_iterator_method_call` bypasses the interface table entirely for a Generator receiver. They all converge on the `__rt_gen_*` HELPERS, so one probe per helper covers every path present and future.

THE SHAPE. A hook slot `_elephc_eval_generator_protocol_fn` (`.comm` in `src/codegen_support/runtime/data/fixed.rs`), installed by the interpreter at `__elephc_eval_context_new` through `__elephc_eval_install_generator_protocol_hook` -- exactly the `_elephc_eval_dynamic_object_destruct_fn` pattern, and for the same reason: the runtime assembly is emitted for every program while the magician archive is linked only when `eval_bridge` is set. Each helper loads the slot, falls through to the fiber path when it is zero, and otherwise calls `hook(gen, op, arg, out) -> 0 | 1`. `arm64_eval_generator_probe` / `x86_eval_generator_probe` in `coro.rs` emit it; both reserve their own 16-byte out slot rather than touching the shared accessor prologues.

`__rt_gen_get_return` had NO frame (it tail-called `__rt_incref`); the probe needs one, so it now takes the shared accessor prologue on both architectures.

THE ANSWER CONVENTION matters: the hook writes the native representation each helper returns, not a uniform boxed cell -- a boxed Mixed for current/key/send/throw/getReturn, a plain 0/1 for valid, zero for next/rewind. Doing the conversion in Rust (`generator_protocol.rs`) keeps the emitted assembly to one load and one branch.
Evidence: scratchpad/red9 (AOT `Holder` with a promoted `iterable` property + `gen.php` included through `getenv('PROBE_INC')`) printed `AOT read-ok convert:2 foreach:2` then `EVAL read:read-ok` and CRASHED on convert / HUNG on foreach. After the fix it prints all six lines and `after`, matching `php -n` 8.5.10. scratchpad/red10 main/steps/survive/one all reach `after` with PHP's values. Symfony `--web` went from `worker terminated by signal 11` to a clean PHP-level error four rungs further on.
Verified by: codegen_tests slices against their verified pristine baselines: generator 96/0 (identical), iterable 120/13, instanceof 59/2, exception 145/2, callable 795/17 -- every failure count unchanged from the pristine tree.
