# ReflectionClass::hasMethod on a Mixed/Union receiver runs a synthesized body that never reaches the eval bridge, and it folded only the needle against a declared-case index; getMethods() is empty whenever the program has an eval context (open)

> Commit ee5fe20ab8. Mechanism proved with ELEPHC EVAL TRACE=1 and emit ir, not the four hypotheses about loading : bot…

Commit ee5fe20ab8. Mechanism (proved with ELEPHC_EVAL_TRACE=1 and --emit-ir, not the four hypotheses about loading): both Symfony Router classes load fine through the interpreter (`phase=class_decl_ok`); the failing `hasMethod` emitted no eval trace because it never reached the bridge — `lower_method_call` in `src/codegen/lower_inst/method_dispatch.rs` (~:21) returns early for Mixed/Union receivers BEFORE the eval-bridge routing for reflection classes (~:33), so a union-typed `ReflectionClass` receiver (e.g. `$c ? false : new ReflectionClass($cls)`, or a value narrowed by `!== false`) runs the SYNTHESIZED body `in_array(strtolower($name), $this->__method_names)`. That folds only the needle, while the two producers of `__method_names` disagree on case: the compile-time materializer stores folded php_symbol_keys (`names_constants.rs` ~:128), the eval bridge stores the declared spelling (`normalization.rs` ~:94, what b7ad5cb0d7 changed so getMethods()->getName() reports declared case). Result: false for every method not already lowercase; the sibling getMethod() already folded both sides. Fix: `builtin_reflection_class_has_name_method` in `src/types/checker/builtin_types/reflection/class_scalar_methods.rs` folds both sides for the case-insensitive variant, mirroring `builtin_reflection_class_get_member_method`; case-sensitive variants (hasProperty, hasConstant) keep a byte-identical AST and the test pins that direction too. Reduction: 9 lines of the container's exact sequence (ClassExistenceResource::isFresh + getReflectionClass shape) now match php -n; row 4 (a union holding the very same object as a typed receiver) proved the object was right and the call wrong. Filters: reflection 159 → 158 reds (the diff is the new test), eval_bridge 11, destructors 44, runtime_gc 35, references 2, objects:: 17, class_exists 12/0 at baseline; method_exists 5/1 and autoload 118/1 pre-existing. STILL OPEN (next step of the same container code, `AbstractRecursivePass::getReflectionMethod` driven standalone): `ReflectionClass::getMethods()` returns 0 entries and `getMethod()` throws `does not exist` — for interpreted and plain AOT classes, typed and union receivers — whenever the program HAS AN EVAL CONTEXT; without one the same reflection works. Unconfirmed lead: b7ad5cb0d7 changed the emitted AOT method-table row NAMES (`src/codegen_support/runtime/data/user.rs::emit_eval_reflection_method_lookup_data`) from the folded key to the declared spelling while rows are still emitted in sorted-lowercase-key order, and the consumer's matching rule was not verified. Also pre-existing: hasConstant() returns int 1/0 on a typed receiver and SEGFAULTS on a union receiver; get_parent_class($str) returns '' where php returns false; is_subclass_of() false for a runtime-autoloaded class.
Evidence: ELEPHC_EVAL_TRACE showing class_decl_ok for both Router classes and no trace for the failing hasMethod; --emit-ir receiver reprs; 7-row reduction table php -n vs elephc before/after; reflection filter name diff = one line; the standalone container probe now passing hasMethod and throwing at getMethod (agent report 2026-09-04).
Verified by: commit ee5fe20ab8; php -n; --emit-ir; ELEPHC_EVAL_TRACE; standalone ContainerBuilder probe
