# Runbook: building the Symfony `--web` fixture on this machine without running the disk out (swap grows faster than the build writes)

> Compiling examples/symfony app/public/index.php with web emits an ~855 MB .s and links a ~119 MB stripped binary ~168…

Compiling examples/symfony-app/public/index.php with `--web` emits an ~855 MB .s and links a ~119 MB stripped binary (~168 MB with --keep-symbols) in roughly 650-720 s, and the real cost is not the artifacts: the debug compiler holds ~784 MB of assembly in memory and `as` another 855 MB, so macOS SWAP under /private/var/vm grows FASTER than the build writes to disk. A run started with 3.7 GB free collapsed to 454 MiB and had to be killed with SIGTERM (exit 143) with the big .s only just beginning. Before starting: require at least 3.5 GB free (the practical gate used through the campaign was 4.5 GiB before any rebuild; the "2.5 GB" figure once used was WRONG), and require that no other compile is running — the volume is shared with the other worktrees and sessions on this machine. Check for a running build with a bracketed pattern, `pgrep -fl '[e]lephc --web'` or `pgrep -x elephc`: an unbracketed `pgrep -f 'elephc --web'` matches ITS OWN command line and waits forever. Watch `df` from a side shell every couple of minutes and kill the build below ~700 MB free rather than let ENOSPC corrupt the link. When an aborted run leaves index.s (850 MB) and index.o beside the entry file, delete them first. Free rebuildable things in this order: stale target/debug/deps generations, keeping only the newest hash per crate (2.85 GB recovered on 2026-09-03); target/release (1.5 GB); leftover probe directories under target/; then $TMPDIR/elephc_test_* directories whose PID is DEAD (227 of them were 2.95 GB; the suites leave ~31 MB per test) — select by live PID, never by age, or you delete a running suite's scratch. Two related traps: a prebuilt test binary needs RUST_MIN_STACK=33554432 just as `cargo test` does (without it, exit 134 on a pdo connect test whose name happens to match the `late` filter), and the `callable` filter is not hung at 1080 s — 112 eval tests account for ~1017 s of it, so chunk it with `xargs <test-binary> --exact --test-threads=2 < names.txt`. Finally: `--emit-asm` and `--web` are mutually exclusive in src/cli.rs, so no single run gives you both a timing oracle and an identity oracle; and before attributing a verdict to a fix, compare the binary's mtime against the compiler's — a binary linked before the compiler was rebuilt does not carry the diff.
Evidence: Measured across the Symfony --web campaign of 2026-09-02..04 (session notes of those dates): the aborted --keep-symbols run (3.7 GB free at start, 454 MiB at kill, SIGTERM/exit 143); disk recoveries of 2.85 GB from stale target/debug/deps generations, 1.5 GB from target/release, ~0.7 GB from probe directories, and 2.95 GB from 227 dead-PID elephc_test_* directories; build times of 647 s and 716 s for full --web rebuilds; binary sizes 119,090,648 bytes stripped and ~168 MB with --keep-symbols; the self-matching pgrep wait observed on 2026-09-03; the RUST_MIN_STACK=33554432 requirement on a prebuilt test binary and the 1080 s / 1017 s split of the `callable` filter both measured on 2026-09-04. The two purge helpers used (a stale-deps pruner keeping the newest hash per crate, and a dead-PID temp purger) lived in the session scratchpad, NOT in the repo — regenerate them if needed. The --emit-asm/--web exclusion is at src/cli.rs:593-594.
Verified by: Repeated builds and `df` monitoring during the campaign of 2026-09-02..04 (session notes of those dates); the CLI exclusion re-read at HEAD f7a17151de on 2026-09-04.
