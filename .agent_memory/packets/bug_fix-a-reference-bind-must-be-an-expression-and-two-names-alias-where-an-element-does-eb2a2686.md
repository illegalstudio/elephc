# A reference bind must be an expression, and two names alias where an element does not

> The eval parser had a deliberate hand off for a reference assignment: parse assignment returned the target UNCONSUMED…

The eval parser had a deliberate hand-off for a reference assignment: parse_assignment returned the target UNCONSUMED so the statement tail could build one of the dedicated binding statements. That works only where a statement tail is waiting. Inside a condition nothing was, and the ampersand was left for a parser with no rule for it, so a bind used as a condition was refused. The fix is the same fold-then-unfold shape the array append needed: build an expression node, and have the statement tails unfold it back into their dedicated statements, which resolve their source through the scope's reference target in a way an expression node does not.

Two rules the expression has to get right, each missable while the other passes. WHAT IT EVALUATES TO is the bound value as a COPY, not a second alias: after assigning the result of a bind to another variable and then writing the source, php reports the alias updated and the copy unchanged. A lowering that returned the alias binds correctly and still gives the wrong value. And PHP puts assignment BELOW comparison, so a comparison against a bind binds the rightmost writable child and compares the result -- which needs the same rebuild that an ordinary nested assignment already gets, not a new rule.

The distinction that costs the most time: TWO PLAIN NAMES alias SYMMETRICALLY through the scope's named-alias table, while an element or property binds one-way through a reference target. The statement world already draws that line between ReferenceAssign and ArrayReferenceBind, and the expression has to draw it too. Binding a name through the one-way path instead of the alias table makes the inner bind silently do nothing: a chained bind then prints the source's old value twice instead of following it. Test a chain, not a single bind, or the difference is invisible.

Also measured: binding a key that does not exist reads null through it, so a condition on such a bind takes the else branch. The condition tests the VALUE the expression yields, not whether the binding succeeded.
Evidence: php -n 8.5.6 prints 11, hit:11;miss, 1;5 and 1;9 on the four fragments and elephc now prints the same. Sentinels: disabling the nested rebuild fails exactly the two condition tests; removing the symmetric-alias case fails exactly the chained test. Symfony measurement: ProfilerListener.php moves from the ampersand to the semicolon after it, so all three remaining refused files now stop at the by-reference RETURN; the reducer corpus goes from 14 refusals of 37 to 12 with g17 and g36 accepting.
Verified by: cargo test -p elephc-magician --lib with no skips: 1421 passed, 0 failed, 0 filtered (commit 648f73e4e2)
