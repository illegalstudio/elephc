# The append-bind statement carried a bare name while the interpreter accepted any lvalue

> Binding a reference to a NEWLY APPENDED element worked only from a bare variable. The array write parser has two appe…

Binding a reference to a NEWLY APPENDED element worked only from a bare variable. The array-write parser has two append branches: the one for a bare name looks for an ampersand after the equals sign, the one reached after an index does not and goes straight to parse_expr, which cannot start with an ampersand. Those two branches exist TWICE, once in parse_array_set_stmt in parser/statements/loops.rs and once in parse_array_set_clause in parser/statements/assignments.rs, and both had the same hole, so fixing one changes nothing for the other position.

The IR shape was the tell: EvalStmt::ArrayAppendReferenceBind carried name as a String rather than an lvalue, which is what made the nested target look unimplementable. It was not. eval_array_append_reference_bind was already building an EvaluatedLocation::ArrayElement over evaluate_location of a LoadVar, and evaluate_location has always accepted a general lvalue, so the nested target was reachable all along. When a statement variant carries a NAME where its interpreter takes a location, suspect the variant rather than the runtime.

Testing rule for references, worth repeating because it is easy to satisfy weakly: a reference is SYMMETRIC, so every case must write through BOTH ends. A test that only checks the source reaching the appended element passes against a copy made at bind time. Pinning the shape that already worked in the same file is what makes a disabled-fix run tell you which shapes the change actually bought.

Also measured here: autovivification happens on the BINDING path, not only on the value path. Binding through two indexes where neither intermediate array exists creates both, which php does too.
Evidence: php -n 8.5.6 prints 2;3 for an append bind through one index read from both ends, 9 for an append bind through two indexes that must autovivify, and 7 for the bare form; elephc now prints the same. Sentinel: disabling the new ampersand branch in both append paths fails exactly the two nested tests and leaves the bare one green. Symfony measurement: PhpDumper.php moves from a refusal at line 460 to one at line 2002 on destructuring into properties.
