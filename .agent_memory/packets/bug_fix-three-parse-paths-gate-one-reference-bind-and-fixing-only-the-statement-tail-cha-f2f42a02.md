# Three parse paths gate one reference bind, and fixing only the statement tail changes nothing

> A reference bind whose LVALUE is an array element reached through a property or a static property was refused at the …

A reference bind whose LVALUE is an array element reached through a property or a static property was refused at the ampersand, while the interpreter could already perform it: EvalStmt::ArrayReferenceBind writes through a general lvalue and evaluate_plain_assignment_location in interpreter/expressions/null_coalesce_assign.rs accepts a property or static-property root. Nothing needed implementing; three PARSE paths each declined in a different way and all three had to change.

parse_static_property_set_stmt reads the bracketed index itself and then demands an assignment operator followed by a VALUE, never considering an ampersand. parse_property_like_stmt_tail handed its target to property_reference_bind_stmt, which knows property shapes only and rejects an element. And parse_assignment in parser/expressions/precedence.rs hands a target back UNCONSUMED when an ampersand follows the equals sign so the statement tail can build a binding instead of an assignment -- but is_property_reference_target listed only the four property shapes, so with an element target the expression parser marched past the equals sign and refused the ampersand as the start of a value. That third gate is the one that makes this worth writing down: fixing the statement tail alone produced no change at all, because the tail was never reached.

Testing rule for references: a reference is SYMMETRIC, so every case must write through BOTH ends. Asserting only that a write to the original shows up through the alias passes against a plain copy made at bind time; appending through the alias and reading the original back is what distinguishes a binding from a copy.

Constructs deliberately still refused after this, each different rather than a leftover: binding to a NEW appended element through a nested array, an APPEND used as the reference SOURCE, and binding to the result of a call, which needs the callee to hand a writable target back to the caller -- the by-reference RETURN.
Evidence: php -n 8.5.6 prints 2;3 for a property element bound to a by-reference parameter, 2;3 for two elements of one static array aliasing each other, and 2 for a nested local element; elephc now prints the same. Sentinels: disabling the static-property branch fails exactly the static test; disabling the property-tail branch fails exactly the property test; disabling the expression hand-off fails the property test too, which shows both halves of that path are load-bearing. Symfony measurement: 7 refused files become 6 with error-handler/DebugClassLoader.php parsing in full; the reducer corpus goes from 20 refusals of 37 to 19.
Verified by: cargo test -p elephc-magician --lib with no skips: 1398 passed, 0 failed, 0 filtered (commit 2f5f3e820c)
