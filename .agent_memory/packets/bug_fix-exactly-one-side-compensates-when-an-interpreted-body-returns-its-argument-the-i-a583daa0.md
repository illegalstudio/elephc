# Exactly one side compensates when an interpreted body returns its argument: the interpreter retains, the AOT bridge always releases

> function f $v { return $v; } declared in eval and called from compiled code has TWO frames that could account for the…

`function f($v) { return $v; }` declared in eval and called from compiled code has TWO frames that could account for the same reference, and for a while both did.

The interpreter side (`crates/elephc-magician/src/interpreter/statements/dispatch.rs`) retains a returned value whose activation scope owns nothing to transfer. A return normally transfers ownership by `release_activation_scope` SKIPPING the returned cell, which only hands the caller a reference when the scope actually owned one -- and a by-value parameter is bound `Borrowed` on purpose, so `return $param;` used to hand back a borrowed cell where every caller treats a call result as owned. A discarded `f($x);` then released the CALLER's `$x`.

The AOT side (`emit_release_eval_boxed_operands_keeping_result` in src/codegen/lower_inst/builtins/eval/argument_results.rs) compared the boxed operand cell with the published result cell AT RUNTIME and skipped the release when they matched, on the reasoning that the reference had moved to the result.

Both were right in isolation and wrong together: one reference, two compensations, so the object stayed one above zero and `$back = echo_back($local);` never ran `$local`'s destructor. The same trap is already avoided on the interpreter side for `$this` -- the comment there says retaining would "hand back two references and a discarded `$obj->fluent();` would never run the object's destructor" -- it just was not spelled for a parameter reaching the bridge from AOT code.

THE RULE: the interpreter now guarantees every result carries a reference of its own, so the AOT frame's box is ALWAYS still that frame's to drop. The alias skip is gone; `emit_release_eval_boxed_operands_keeping_result` releases unconditionally.

HOW IT WAS FOUND, and the method to reuse: the fixture passed at the session base and failed at HEAD, so the tree was reverted wholesale to the base and restored group by group -- src/types + src/ir_lower (innocent), src/codegen + src/codegen_support (innocent), crates/elephc-magician (guilty), then interpreter/statements/, then dispatch.rs. Note that checking out individual session commits does NOT work: they were split by FILE, so several reference symbols added by later commits and do not build in isolation.
Evidence: `codegen::destructors::test_eval_call_returning_its_argument_keeps_the_returned_cell` prints `back is local\nscope end\nend` where php -n 8.5.10 prints `back is local\nscope end\ndestruct local\nend`. A companion fixture pins the other half -- a discarded call whose result aliases its argument, a used call on the same cell, and a call whose result does not alias -- and matches php exactly. After the fix codegen::destructors is 44/47 with the three remaining failures pre-existing at baseline, and codegen::runtime_gc reports exactly the baseline's 53 failures, neither more nor fewer.
Verified by: php -n 8.5.10 differential plus the codegen::destructors and codegen::runtime_gc slices diffed against the 9667-test baseline
