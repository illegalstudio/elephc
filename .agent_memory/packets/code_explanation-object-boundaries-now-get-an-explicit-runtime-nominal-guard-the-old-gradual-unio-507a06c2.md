# Object boundaries now get an explicit runtime nominal guard; the old gradual_union_flows_into supertype hole is gone

> The July 2026 claim that a gradual union lets a SUPERTYPE member cross into a more derived object target with NO runt…

The July-2026 claim that a gradual union lets a SUPERTYPE member cross into a more-derived object target with NO runtime guard (SIGSEGV instead of TypeError) described gradual_union_flows_into in src/types/checker/type_compat/unions.rs. That function exists nowhere any more - not in the merged tree, not at the pre-merge branch tip 8da22fe141, not in origin/main. Object boundaries are now guarded explicitly at three points. (1) The predicates live in src/types/param_binding.rs: nominal_object_boundary_target (line 38) extracts the single named class or interface a target accepts, tolerating a nullable object union; object_requires_runtime_nominal_guard (line 62) fires when the SOURCE is statically an object; gradual_object_requires_runtime_nominal_guard (line 75) fires when the source is Mixed or Union - which is exactly the old repro shape, a nullable Base flowing into a Sub parameter. (2) ir_lower emits the guard as an Op::RuntimeCall carrying Immediate::NominalObject: at the parameter boundary in guard_nominal_object_param, src/ir_lower/expr/call_arg_coercion.rs:205-215, and at the return boundary in src/ir_lower/stmt/return_coercions.rs:173-176 (a property boundary exists too, src/ir_lower/stmt/typed_foreach.rs:88-90). (3) codegen lowers it in lower_generic_object_nominal_guard, src/codegen/lower_inst/array_access_runtime.rs:399, which accepts a source of Object, Mixed or Union, calls __rt_exception_matches against the target class or interface id, and falls through to exceptions::emit_type_error with "Argument must be of type X, object given" when the runtime object does not match. Note the neighbouring scalar guard, lower_gradual_union_param_guard (same file, line 323), deliberately EXCLUDES nominal objects, callables, iterables, resources and the false subtype - it only tag-checks Int/Str/Float/Bool/Void/array unions. So the object case is covered by the nominal guard above, not by that one; do not read the scalar guard comment as evidence that objects are unguarded. This is a static reading of the merged tree, not a run: the old repro (a nullable Base into a Sub parameter, Base|Sub into Sub, a nullable Base returned where Sub is declared, a nullable Animal holding a Cat into a Dog parameter) should now print a TypeError rather than exit 139, and re-running those four probes against php 8.5 is what would turn this into a measured fact.
Evidence: grep on the merged worktree 2026-09-02: gradual_union_flows_into has zero hits in src (and git grep finds it in neither HEAD 8da22fe141 nor origin/main). Read src/types/param_binding.rs:38-80, src/ir_lower/expr/call_arg_coercion.rs:150-220, src/codegen/lower_inst/array_access_runtime.rs:23,323-470 in full; the guard call chain and the emit_type_error fallthrough are present as described.
Verified by: grep + file reading on the merged worktree during the a7bb4cd92c merge, 2026-09-02; NOT executed
