# A test must assert the observed VALUE against `php -n`; `expect_no_error` counts only as a second assertion, never alone

> Maintainer rule, stated 2026 09 02 about a test that did nothing but expect no error inside ; expect no error strict …

Maintainer rule, stated 2026-09-02 about a test that did nothing but `expect_no_error(inside); expect_no_error_strict(inside);`: proving no error is raised is fine, proving the program returns what it should is better, and the second is required. "The checker accepts it" is not evidence that "the program does what PHP does" — the entire Symfony campaign of September 2026 chased SILENTLY WRONG outputs (a retyped local printing 0, a `$matches` array with its keys lost, PREG_OFFSET_CAPTURE ignored), which is precisely the class of defect a no-error test lets through. How to apply: for every accepted form, COMPILE AND RUN it and compare the output byte for byte with `php -n` — for example, after `foreach ($chunks as &$chunk) { $chunk = new C(); }`, assert the count, the get_class of the elements and a re-read through the array; and when the program allocates, use one of the heap-checking helpers in tests/codegen/support/compiler.rs (compile_and_run_with_heap_debug, compile_and_run_with_gc_stats, compile_and_run_with_counters) so a leak cannot pass as a green test. `expect_no_error` and `expect_no_error_strict` (tests/error_tests.rs) are DECISION pins: admitted beside a value assertion, never as the whole test. A test that asserts only a count, or only an absence of error, is to be rewritten before it is counted as coverage — and any brief given to an implementation agent must demand end-to-end value comparison against php explicitly.
Evidence: Maintainer instruction quoted in the session note dated 2026-09-02, given on test_by_ref_foreach_value_var_retype_inside_the_body_type_checks, which asserted nothing but the two no-error helpers. The pattern it guards against is documented by the same campaign's silent-output defects (branch-divergent local retype, lost preg named-group keys, ignored PREG_OFFSET_CAPTURE). Verified in the tree at HEAD f7a17151de on 2026-09-04: expect_no_error/expect_no_error_strict live in tests/error_tests.rs and its submodules, and tests/codegen/support/compiler.rs defines compile_and_run_with_heap_debug alongside compile_and_run_with_gc_stats, _with_counters and _capture; tests/codegen/locals_retype.rs is the worked example that follows the rule.
