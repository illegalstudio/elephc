# The gradual UNION parameter guard forwards its operand, so classifying it as an owning temporary double-released the caller's boxed cell — a `?string` property then read recycled memory

> Commit 283cd2fe4f branch reconcile/dirname symfony, on 99f98db775 closes the échelon 35 gotcha "the Symfony web Servi…

Commit 283cd2fe4f (branch reconcile/dirname-symfony, on 99f98db775) closes the échelon-35 gotcha "the Symfony --web ServiceClosureArgument string fatal is a ?string PROPERTY read back wrong".

REPRESENTATION, measured, not assumed. `?string` is `Union([Str, Void])` and `PhpType::codegen_repr()` maps it to `Mixed` — only `nullable_int_union_members` (Int + Void/Never) becomes `TaggedScalar` (src/types/model.rs:180). So a `?string` property slot is ONE word holding a boxed Mixed cell pointer at `offset`, with the uninitialized marker at `offset+8`. It is NOT the inline two-word TaggedScalar of the ?int fix 6683884da4, and no descriptor-tag work was needed. Writer and reader AGREE: aarch64 asm of `H::__construct` does `__rt_incref` on the cell, `__rt_decref_mixed` on the old slot content, `str x0,[x9,#8]`, `str xzr,[x9,#16]`; `H::get` does `ldr x0,[x9,#8]` + `__rt_incref`. Both correct. The defect is one step EARLIER, on the caller's side of the call.

MECHANISM. `guard_gradual_union_param` (src/ir_lower/expr/call_arg_coercion.rs:120) emits `Op::RuntimeCall` with `Immediate::TypeName` — the ONLY producer of that immediate in the tree — whenever a boxed union argument meets a declared scalar/null union parameter. Its codegen `lower_gradual_union_param_guard` (src/codegen/lower_inst/array_access_runtime.rs:323) compares the active Mixed tag against the declared members and on the accepted path does `ctx.load_value_to_result(value)`: it hands back THE SAME CELL, never acquires, never allocates. But the result's PHP type is a union, so `Ownership::for_php_type` marks it MaybeOwned and the generic `Op::RuntimeCall` arm at the tail of `value_is_owning_temporary` classified it as an owning temporary. `release_owned_call_arg_temporaries` then released a cell the guard had only borrowed. For `new H($n)` with `?string $name` and a branch-retyped `$n`: cell rc=1 from `__rt_mixed_from_value(tag 8)`, +1 from `prop_set`, -1 from the spurious argument release, then -1 from the frame's own epilogue release of `$n` => 0, FREED, while the object's property still pointed at it. The read afterwards saw recycled memory. The observed `int(9223372036854775806)` is the free list overwriting the TAG word with 0 while the NULL sentinel stays in the payload word; in the Symfony binary the same slot came back as a boxed object (class id 317 ServiceClosureArgument).

FIX. `value_is_owning_temporary` (src/ir_lower/context.rs) now recognises the guard via a new `gradual_union_param_guard_source()` and answers with its OPERAND's ownership, recursively: a pure forward owns exactly what it was given. A borrowed local load is no longer released after the call; an owning temporary (a `mixed` call result, `new H(src())`) still transfers through the guard and IS released. This is the union sibling of 76a771f80b / `value_is_borrowed_gradual_nominal_guard`, which could answer a flat "borrowed" only because a fresh box behind it is recovered separately by `owning_box_behind_borrowed_nominal_guard`; the union guard needs the operand-transparent answer instead.

READING IT IMMEDIATELY IS CORRECT, which is why échelon 35 could not see it from inside the frame: the cell is only freed at the producing frame's scope exit.

STILL OPEN, separate and pre-existing (untouched `if.else` arm, mixed_box path): a `?string` property built from a branch-retyped local on the NON-null path leaks 48 bytes per object (`--heap-debug` live_blocks=1). Reducer: `class H { private ?string $n; ... } function mk(bool $f): array { $n='aliasA'; if ($f) { $n=null; } return ['k'=>new H($n)]; } $b=mk(false); unset($b);`. `new H('zz')` directly is CLEAN, and the null arm is CLEAN, so it is specific to the mixed_box of a union-typed local.
Also observed and fixed by the same commit: `var_dump(mk(true)-&gt;get())` on that shape used to HANG.
Evidence: Reducers before/after against php -n 8.5.6. examples/symfony-app/p35r.php: php `key=aliasA -> 'aliasA'` / `key=TypeB -> NULL` / `key=aliasC -> 'aliasC'`; elephc BEFORE three EMPTY values, AFTER identical to php. p35s case m3: php NULL, elephc BEFORE `9223372036854775806`, AFTER NULL. Minimal 12-line reducer (`$n='x'; if($f){$n=null;} return ['k'=>new H($n)]`): BEFORE `int(9223372036854775806)` and `--heap-debug` "Fatal error: heap debug detected bad refcount", AFTER `NULL` and "leak summary: clean". Reading the property INSIDE the producing frame was correct before and after. Every reader (var_dump, print_r, var_export, json_encode, serialize, unserialize, get_object_vars, (array) cast, isset, ??) byte-identical to php for both the set and null states after the fix. Evidence for the representation claim: whole-function aarch64 disassembly of H::__construct (incref + str at [x9,#8] + xzr at [x9,#16]) and H::get (ldr [x9,#8] + incref), and the EIR showing `v8: Heap(Mixed) own=owned = runtime_call v7 type_name[2]` followed by `release v8` before the fix versus `own=maybe_owned` and NO release after. 6 new tests in tests/codegen/objects/property_access/nullable_string_properties.rs, all green.
