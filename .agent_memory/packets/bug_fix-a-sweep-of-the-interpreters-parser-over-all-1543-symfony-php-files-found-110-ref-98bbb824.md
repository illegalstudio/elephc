# A sweep of the interpreter's parser over all 1543 Symfony PHP files found 110 refusals in 18 constructs; fixing 85 moved the request onto the warm container path

> Running the interpreter's parser over EVERY PHP file of examples/symfony app, instead of reducing one blocker at a ti…

Running the interpreter's parser over EVERY PHP file of examples/symfony-app, instead of reducing one blocker at a time, turned a serial hunt into one batch: 110 of 1543 files refused, php -n -l accepted all 110, and they fell into only 18 constructs. The harness is committed as the ignored test parser::tests::source_tree_sweep, driven by an environment variable naming colon-separated roots, and it now goes through parser::parse_source_file so it exercises the real bridge entry.

THE SINGLE LARGEST WIN CAME FROM ASKING A DIFFERENT QUESTION. Four builders in parser/statements/property_builders.rs enumerated four property shapes and refused everything else, which cost 21 files for writes like a nested append through a property. Nothing was missing underneath: interpreter eval_array_append already appends through ANY writable lvalue, and Assign, CompoundAssign and PostfixIncDec already write through the general location machinery. Replacing the enumeration with is_assignment_target reached all of it. The refusal was also invisible where it happened: it surfaces after the whole statement is read, at the NEXT statement's first token, which is why one construct was reported as unexpected brace eight times and unexpected return four times.

A WHOLE PHP FILE IS ONE TOKEN STREAM. include_exec split an included file on its tags and parsed each block alone, so a brace one block opens and a later block closes could only ever be an unexpected end of file, which is how every error-page template is written. parser::parse_source_file now builds one stream: inline HTML is a token that parse_stmt turns into an echo, a short echo tag emits an echo token, a closing tag emits the implicit semicolon PHP inserts, and the single newline PHP swallows after a closing tag is dropped. Measured: php prints x for a file ending in the tag then one newline, and x plus a newline for two.

A DOC COMMENT IS TRIVIA WHEREVER NOTHING READS IT. PHP's zendlex skips it like whitespace and parks it for the next declaration; this lexer keeps the token so reflection can report it, and every rule that does not expect one refused the file. Dropping the doc comments no rule reads, decided by the same predicate the one consuming site uses, is the whole fix.

THE PARSER FIXES CHANGED WHICH PATH THE REQUEST TAKES, not just how far it gets. With the files parsing, Symfony's container freshness check stops throwing the TypeError an empty catch was swallowing, so the app trusts its cache and loads the DUMPED container instead of rebuilding it. The request went from 4.7 s to a parse error, to 15.4 s on the cold build path, to the warm path.
Evidence: Sweep before: 1543 files, 110 refused, 0 rejected by php -n -l 8.5.6. After: 25 refused, 12 of them yield from. A 37-file reducer corpus with php -n's value per construct went 24 refused to 5. cargo test -p elephc-magician fails 16 names where the branch point fails 25, the 11 parser::tests reds being the pre-existing Assign vs PropertySet set. Runtime-include value tests assert php's exact strings: 3;01:S1Bag:null;hit;tail[in][alt]done for the grammar groups, 74d;2;hit:11;miss;1,2,3,4/2,3,2,3;55;2 for the write and reference groups, 98;m1n2;AB;123;pq;56;13;781 for destructuring. Filters unchanged against their known reds: eval_bridge 13 of 13, destructors 44 of 44, class_exists 13 of 13, autoload 1 red, exception 8, runtime_gc 35, objects 17.
