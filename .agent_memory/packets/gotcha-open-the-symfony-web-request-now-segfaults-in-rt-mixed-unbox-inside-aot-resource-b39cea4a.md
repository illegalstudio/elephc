# OPEN: the Symfony --web request now segfaults in __rt_mixed_unbox inside AOT ResourceCheckerConfigCache::isFresh, and the macOS crash report gives the backtrace for free

> OPEN, measured and NOT fixed. This is the blocker the Symfony web request reached after the first class callable exce…

OPEN, measured and NOT fixed. This is the blocker the Symfony `--web` request reached after the first-class-callable exception-boundary fix removed the whole `EnvNotFoundException` family. The worker dies with `terminated by signal 11` after printing three `filter_var(): array $options passed through a mixed value is not supported by elephc yet; flags ignored` warnings.

DO NOT FIGHT LLDB FOR THIS. The runbook's echelon-35 recipe (attach lldb in batch to the single prefork worker) does NOT work here: the worker is respawned, so the pid found with `pgrep -P <listener>` is stale by the time lldb attaches and it reports `error: attach failed: no such process`. macOS already writes a fully symbolicated crash report for every SIGSEGV at `~/Library/Logs/DiagnosticReports/index-<timestamp>.ips`. It is JSON with a one-line metadata header followed by the body, so `json.loads` the second line, take `faultingThread`, and map each frame's `imageIndex` into `usedImages`. That is the whole recipe and it costs one python snippet.

THE BACKTRACE, innermost first:
  __rt_mixed_unbox
  method___Symfony_N_Component_N_Config_N_ResourceCheckerConfigCache___isfresh
  __elephc_eval_method___Symfony_N_Component_N_Config_N_ResourceCheckerConfigCache___...
  elephc_magician::runtime_hooks::ops::<impl ...>            (method_call_out)
  elephc_magician::interpreter::statements::native_method_execution::eval_native_method_with...
  elephc_magician::interpreter::statements::method_dispatch::eval_method_call_result_with_ev...
Exception: EXC_BAD_ACCESS (SIGSEGV), KERN_INVALID_ADDRESS at 0x0000000100000020.

So the interpreter calls the AOT-compiled `ResourceCheckerConfigCache::isFresh()` through the eval method bridge, and inside that compiled body `__rt_mixed_unbox` dereferences a bad pointer. The faulting address 0x100000020 is a small offset off a bogus base, i.e. an invalid boxed-Mixed cell rather than a null one.

THE SUSPECT MEMBER. `isFresh()` (vendor/symfony/config/ResourceCheckerConfigCache.php) reads the PROMOTED `private iterable $resourceCheckers = []` three times in a row: `instanceof \Traversable`, `instanceof \Countable`, then `iterator_to_array(...)` and `\count(...)`. `iterable` is a boxed Mixed, and this is the SAME property an earlier packet already caught misbehaving -- `is_array()` answered false on it while `get_debug_type()` said `array`, raising a TypeError at ResourceCheckerConfigCache.php:65 that the kernel's empty `catch (\Throwable)` swallowed. That half was claimed fixed by 54723228bd; the property is now crashing instead of lying, which is consistent with the same storage being wrong in a different way.

WHAT DOES NOT REPRODUCE IT, so start past this: an AOT class with a promoted `private iterable $items = []`, constructed from a runtime-included file and read back by an AOT method doing exactly the `instanceof \Traversable` / `instanceof \Countable` / `iterator_to_array` / `count` sequence, matches `php -n` 8.5.10 exactly (`empty:true / filled:false / after`, exit 0) for both an empty default and a `[1, 2]` argument. The real `$resourceCheckers` is not a plain array -- Symfony feeds it a `RewindableGenerator` of checker services -- so the next reducer should put a Traversable-but-not-Countable object in that property, which is precisely the branch that then calls `iterator_to_array`.
Evidence: examples/symfony-app compiled `--web --timings --keep-symbols --heap-size=1073741824`, exit 0, 74 s; cold request on 1 worker gives `curl: (52) Empty reply from server`, HTTP=000, and `elephc-web: worker <pid> terminated by signal 11`. Crash report ~/Library/Logs/DiagnosticReports/index-2026-09-12-192853.ips parsed for the frames quoted above. lldb attach attempted per the runbook and failed with `error: attach failed: no such process` because the worker is respawned. Negative reducer under scratchpad/red5 (main.php AOT `Checker` with promoted `private iterable`, gen.php included through `getenv('PROBE_INC')`) prints identically under `php -n` 8.5.10 and elephc, exit 0. Oracle for the goal: `php -n` on this app returns HTTP 404, 39,315 bytes, containing "Welcome to Symfony!".
Verified by: macOS DiagnosticReports crash report for the segfaulting worker, plus a non-reproducing php -n reducer
