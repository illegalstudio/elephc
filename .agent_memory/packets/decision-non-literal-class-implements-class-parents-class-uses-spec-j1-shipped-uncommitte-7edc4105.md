# Non-literal class_implements()/class_parents()/class_uses() (SPEC J1) shipped uncommitted

> Non literal class implements /class parents /class uses SPEC J1 shipped uncommitted on reconcile/dirname symfony: che…

Non-literal class_implements()/class_parents()/class_uses() (SPEC J1) shipped uncommitted on reconcile/dirname-symfony: checker (src/types/checker/builtins/callables.rs) now accepts Object|Str|Mixed|Union|StringLiteral for arg0. Runtime design: 3 new uniform 64-byte-row sorted tables (_class_relation_table/_interface_relation_table/_trait_relation_table, one row per class/interface/trait, fields {name_ptr,name_len,implements_ptr,implements_count,parents_ptr,parents_count,uses_ptr,uses_count}) computed by src/codegen/runtime/data/class_relation_registry.rs (a deliberate PARALLEL Rust implementation of the existing class_implements/class_parents/class_uses computation in src/codegen_ir/lower_inst/builtins/class_relations.rs — NOT a shared refactor — to keep the literal fast path byte-identical/untouched). 3 new runtime helpers: __rt_class_relation_probe (lowercase+search one table, entry_size=64, mirrors __rt_class_exists but returns the row pointer), __rt_class_relation_lookup (tries class/interface/trait tables in order with a caller-supplied payload byte offset 16/32/48, register-offset LDR on ARM), __rt_hash_from_name_list (runtime LOOP version of the existing emit_string_hash_entries_* unrolled hash builder — every register that must survive a nested `bl`/`call` needs an explicit stack spill since runtime helpers only preserve x29/x30/rbp). New RuntimeFeatures.class_relation_introspection flag detected in src/ir_lower/program.rs mirroring class_introspection's non-const-string detection. KEY CORRECTNESS FIX bundled in: OBJECT arguments now ALWAYS resolve via the object's RUNTIME class id (reusing emit_dynamic_object_class_name, the same mechanism get_class() uses) instead of the checker's static declared type — php -n confirmed a base-typed parameter holding a derived instance must report the derived class's interfaces; the old code used the static type and was silently wrong under polymorphism. Verified php-vs-elephc byte-identical via php -n probes for: transitive interface order, ancestor chain order, direct-only trait uses, case-insensitive needle, interface/trait target-kind matrix (unknown relation on a valid target = empty array, not false; only a genuinely unknown name = false, no warning emitted since elephc has no E_WARNING infra and class_exists sets the same precedent), anonymous-class object arg, trait-use method-alias adaptations (alias doesn't change class_uses() trait identity), enum class_implements (enums are dual-registered in class_infos so they work automatically, but elephc's literal path already omits UnitEnum from PHP's real result — pre-existing gap, not introduced/fixed here). Pre-existing, unrelated leak found and NOT fixed (out of scope): any function-returned Mixed array leaks ~4-6 blocks per unset() even for a plain array literal return — confirmed on the untouched literal class_implements() path too, so the non-literal path matches (doesn't regress) this baseline exactly.
Verified by: macOS aarch64: cargo test --test codegen_tests introspection (67/67), cargo test --test error_tests callables (43/43), cargo test --test ir_backend_smoke_test (256/256), manual php -n vs elephc parity smoke test byte-identical, cargo build/--tests zero warnings, git diff --check clean. Linux x86_64 via Docker (scripts/test-linux-x86_64.sh introspection): 67/67 + related error tests, completed before host disk hit 100% and killed the concurrent Linux ARM64 Docker run (coordinator directive: do not retry Docker locally, CI is authority for the Linux matrix). --web: manual --web compile + live TCP request against class_implements() with a non-literal name returned byte-identical output; the scripted web_tests suite was killed after ~1h hang (pre-existing prefork/socket harness issue in this sandbox, unrelated — reproduced independently of this change).
