# Compile-time hotspots per phase: pruning is O(methods × classes), lowering validates dominators in O(blocks²) even in release, codegen clones the whole Module per builtin wrapper

> Read only profile 2026 09 03, debug compiler sampled with sample , shares within 0.7 pt of timings , plus a synthetic…

Read-only profile (2026-09-03, debug compiler sampled with `sample`, shares within 0.7 pt of `--timings`, plus a synthetic 100/200/400/800-class and -function series with log-log exponents). Findings that are algorithmic, hence valid for release: (F3) declaration pruning scales with exponent 1.90 in CLASSES and 0.94 in functions: `seed_vtable_slot_families` in `src/optimize/reachability/graph.rs:423-450` iterates every kept method × every live class and calls `class_is_or_descends_from` (`:807-824`) which allocates a fresh `String` and a fresh `HashSet<String>` per call and clones a String per ancestor step, with both driving sets materialised by `.cloned().collect()`; this is most of the 15.1 s release pruning on Symfony (~2,000 classes). A control with declared-but-unused classes stays linear, so the quadratic is in the retained method × class product. (F2) `dominator_bitsets_to_map` in `src/ir/validator.rs:1328-1343` converts an already O(1) `Vec<u64>` bitset into a dense `HashMap<BlockId, HashSet<BlockId>>` in O(blocks²) SipHash insertions; it is the hottest self-frame of the whole compile and is reached UNCONDITIONALLY in release through `validate_lowered_module` from `src/ir_lower/program.rs:128` (43.6 % of the lowering phase, ≈2.5 s of the 164 s release build), besides the debug-only per-pass validation. (F4) `src/codegen/lower_inst/runtime_wrappers.rs:106` does `ctx.module.clone()` (seven `Vec<Function>`, the DataPool, ~30 class maps) per distinct builtin wrapper just to obtain a `&mut Module`, dropped right after: 20.7 % of codegen on the probe, O(wrappers × module size). (F7) the checker's `method_pass.rs:39-41` deep-clones `self.classes` (`HashMap<String, ClassInfo>`) at the top of every pass for change detection, cap O(C): 17.7 % of the check phase, exponent 1.18. (F8) constant propagation exponent 1.38 (`src/optimize.rs:106,231-248`, whole-program `CallableEffectAnalysis` + `ExceptionFlowAnalysis`), not diagnosed. DEBUG-ONLY costs, do not size levers from them: (F1) `src/ir_passes/driver.rs:199-200` runs `validate_function` after every pass under `#[cfg(debug_assertions)]` = 67.5 % of the EIR-opt phase and ~43 % of a debug compile (release EIR opt is 956 ms); (F5) `relax_conditional_branches` `aarch64_relax.rs:30-71` is linear but calls Unicode `trim()` on all 1.15 M lines including data; (F6) the ir-opt driver has no worklist at three levels (`driver.rs:135,190`; `liveness.rs:80-103` allocates a HashSet per block per sweep; `dead_inst.rs:52`/`dead_store.rs:311` recompute dataflow from scratch), a dev/test-loop lever only. None of these change the emitted assembly: the identity gate is two `--emit-asm` runs `cmp -s` identical (verified byte-identical on a 34.9 MB probe), or a stderr diagnostics diff for the checker.
Evidence: `--timings` on examples/symfony-app/freshprobe2.php (min of 2: 16.06 s; `--no-ir-opt` 5.72 s); 13,541 self samples over 10 × 2 s windows; synthetic series exponents pruning 1.90/0.94, lowering 1.64/0.96, const-prop 1.38/0.84, check 1.18/0.92, codegen 1.15/1.06, EIR opt 1.01/0.88 (classes/functions); two --emit-asm runs cmp-identical at 34,933,741 bytes. Load average 7–12.5 during measurement; shares and exponents, not absolute times, carry the findings.
Verified by: macOS sample + --timings on the debug compiler; synthetic scaling series; code reading at the cited lines
