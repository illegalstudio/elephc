# Closure::bind on x86_64 now retains $this: the object-capture arm loads the receiver into rax, the register __rt_incref actually reads

> On x86 64 the runtime's single argument helpers read their input in rax, not in the System V first argument register …

On x86_64 the runtime's single-argument helpers read their input in rax, not in the System V first-argument register rdi (`__rt_incref` tests and increments through rax at src/codegen_support/runtime/arrays/incref.rs:70-74). `__rt_closure_bind`'s object-capture arm (src/codegen_support/runtime/callables/closure_bind.rs, around lines 172-177) loaded the receiver into rdi before `call __rt_incref`, so the increment landed on whatever rax held — the freshly allocated descriptor block reloaded three instructions earlier. Two defects from that one line: the bound Closure took a reference it never gave back, and `$this` took none, so the caller's last release freed a live object. Commit e2c59d58cf changes the load to `mov rax, rdx`. Because only the linux-x86_64 CI shard executes this emission, the fix is pinned from the emitted assembly on both targets by two unit tests in that file's test module: `the_object_capture_arm_passes_this_in_the_incref_input_register` and its control `the_retained_receiver_is_the_one_stored_into_the_capture_slot` (a bare `mov rax, …` of the descriptor would satisfy the first alone). Reverting the one-line fix makes the first test fail with `got mov rdi, rdx`. The change sits inside `emit_closure_bind_x86_64`, reached only for Arch::X86_64, so no assembly emitted on macOS-aarch64 changes. General rule for anyone adding x86_64 runtime calls: check the callee's input register in its emitter before choosing rdi; the aarch64 convention (x0) does not carry over.
Evidence: Commit e2c59d58cf on reconcile/dirname-symfony ("fix: retain $this, not the descriptor, when Closure::bind copies an object capture"). `cargo test -p elephc --lib closure` 11 passed / 0 failed after the fix; with the fix reverted, `the_object_capture_arm_passes_this_in_the_incref_input_register` fails with `got mov rdi, rdx`. `--test codegen_tests closures` failing set unchanged (4 pre-existing codegen::eval_closures failures) because the host emits the aarch64 variant.
Verified by: Opus 5 implementation agent, 2026-09-02, unit tests on the emitted x86_64 assembly + revert check; commit e2c59d58cf
