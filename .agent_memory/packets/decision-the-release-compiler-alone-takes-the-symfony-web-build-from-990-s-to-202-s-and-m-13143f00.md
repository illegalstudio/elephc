# The release compiler alone takes the Symfony --web build from 990 s to 202 s, and moves the assembler from a quarter of the build to 60 %

> Measured 2026 09 05 at HEAD 283cd2fe4f. cargo build release j 2 stock release profile; Cargo.toml has no profile.rele…

Measured 2026-09-05 at HEAD 283cd2fe4f. `cargo build --release -j 2` (stock release profile; Cargo.toml has no [profile.release] override) takes 10m01s from scratch, produces a 37,125,776-byte elephc against the debug build's 73,774,032, and 1.4 GB of target/release. Compiling examples/symfony-app/public/index.php with `--web --timings --keep-symbols --heap-size=1073741824` then takes 202.49 s where the DEBUG compiler took 990 s — a 4.9x cut for one cargo invocation and no code change.

The release phase profile is NOT a scaled copy of the debug one, and using debug shares to prioritise compile-time work is wrong. Release, one run, runtime cache miss: Assembling object file 122.29 s (60.4 %), Generating native code 26.93 s (13.3 %), Pruning unreachable declarations 24.34 s (12.0 %), Checking types 16.65 s (8.2 %), Lowering program to EIR 6.60 s (3.3 %), Optimizing EIR 1.21 s (0.6 %), Linking native output 1.17 s (0.6 %). The emitted .s is 861,640,960 bytes. freshprobe2.php is a good cheap proxy: 9.30 s total of which assemble 6.27 s (67.5 %).

The reason the shape changes is that `as` is a separate single-threaded process that a faster compiler cannot speed up, so its SHARE grows as everything Rust shrinks. The 2026-09-03 debug profile put the assembler at ~24 % and declaration pruning at ~32 %; on release the assembler is 60.4 % and pruning is 12.0 %.

Consequence for the compile-time patch set: anything gated on `#[cfg(debug_assertions)]` is worth exactly zero on release. `src/ir_passes/driver.rs:199` (the per-pass EIR validation, 67.5 % of the EIR-opt phase in debug) does not exist in a release build, so a gate on it buys nothing there — while `validate_lowered_module` at src/ir_lower/program.rs:128 carries no cfg gate and does run in release. Check the cfg of a hot call before costing a patch against it.
Evidence: Two `--timings` runs at HEAD 283cd2fe4f: debug 990 s (prior sessions) vs release 202.49 s, per-phase tables captured. `cargo build --release -j 2` timed at 10m01s (996.51 s user, 170 % CPU). Binary sizes from ls; target/release size from du. freshprobe2 --timings table captured in the same session. cfg gates read directly in src/ir_passes/driver.rs and src/ir_lower/program.rs.
Verified by: elephc --web --timings --keep-symbols --heap-size=1073741824 on examples/symfony-app/public/index.php, release and debug compilers, HEAD 283cd2fe4f
