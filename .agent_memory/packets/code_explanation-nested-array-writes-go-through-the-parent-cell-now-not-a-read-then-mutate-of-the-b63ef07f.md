# Nested array writes go through the parent cell now, not a read-then-mutate of the whole target

> The old claim was that lower nested array assign's general fallback lowered a nested write target e.g. $x $i $j = v b…

The old claim was that lower_nested_array_assign's general fallback lowered a nested write target (e.g. $x[$i][$j] = v) by reading the WHOLE ArrayAccess chain as an rvalue and emitting a 2-operand Op::RuntimeCall that mutated whatever cell the read returned - which silently no-ops whenever __rt_mixed_array_get had to allocate a fresh detached Mixed cell (a miss or a scalar leaf, i.e. exactly the auto-vivify case). That fallback is no longer the path taken. lower_nested_array_assign now lives at src/ir_lower/stmt/nested_array_writes.rs:13 and its own comment names the two issues that fixed it: #529 (the detached-box write was silently lost) and #555 (missing or null intermediate elements dropped the write). For an ArrayAccess target it now splits off the INNERMOST key and emits a THREE-operand Op::RuntimeCall of (parent, key, value) - lowering the parent chain with fetch-for-write semantics via lower_nested_assign_parent so intermediates autovivify as arrays - which writes through __rt_mixed_array_set for Mixed parents or offsetSet for ArrayAccess objects, mutating the aliased container for every slot representation. It also releases the parent when it is an owning temporary, and preserves PHP's store-time index evaluation order by only deferring a target whose indexes are all bare variables (nested_target_is_all_bare_variables). The old two-operand read-then-mutate shape survives only as the non-ArrayAccess tail of the function (lines 70-77). The consumer side moved too: lower_mixed_cell_runtime_assign is now at src/codegen/lower_inst/mixed_property_runtime.rs:160 (with aarch64/x86_64 variants at 202 and 252) and __rt_mixed_array_get is emitted from src/codegen_support/runtime/objects/mixed_array_get.rs. This is a static reading, not a run: the old repro $x = json_decode('[false]', true); $x[0]["k"] = 1; var_dump($x[0]); is what would confirm it now matches php instead of printing bool(false).
