# Runbook: probing a framework application compiled with --web, from the first crash to the page (the Symfony ladder, to be replayed on Laravel)

> The procedure that took the Symfony web request from a SIGSEGV to a served page over échelons 19 39 2026 09 02 to 202…

The procedure that took the Symfony --web request from a SIGSEGV to a served page over échelons 19-39 (2026-09-02 to 2026-09-05), written so the Laravel campaign replays it. Build and serve: compile the app with the RELEASE compiler (cargo build --release, 4.9x faster than debug on the Symfony build) as one backgrounded invocation with a disk gate of 4.5 GiB and a watchdog (the 861 MB assembly plus swap can empty a 16 GiB machine's disk); delete index.s, index.o and index.slice*.{s,o} right after linking; start the produced binary as its own background command with --listen and --workers 1 (the cold request then reproduces in ~200 s instead of ~650 s with ten workers); curl from a separate script with an 1800 s budget for the cold request and 600 s for the warm one, recording status, size, time and the marker in the body, plus the first server stdout/stderr lines (fatals from the eval bridge go to stderr with exit 1, uncaught php reports to stdout with exit 255). Naming the site, cheapest first: the message itself (since échelons 37-38 a parse or runtime failure of the bridge names file, line, token or cause); the eval trace variable set to 1 (tens of thousands of lines per request, read with grep -a, never tailed raw: include parse errors, object_is_a decisions with the deciding table, autoload callbacks, allocation errors); for a fatal raised by an AOT runtime helper that the trace cannot see, rebuild with --keep-symbols and attach lldb in batch mode to the single worker with a breakpoint set by regex on the helper symbol (a breakpoint by exact name does not resolve on macOS), then the backtrace names the compiled PHP method; then a reducer run from the app directory with a ./ prefix (a bare filename disables autoload), including through a variable path or __DIR__ (a literal include of a file created at run time is a silent no-op), forcing an eval context with a new of an eval-declared class or compiling the probe with --web (a lone eval of a seed assignment is folded), measured against php -n before and after, remembering that reading a value immediately can be right while reading it after the producing frame returned is wrong. When the failure is a parser refusal, sweep first: the ignored test source_tree_sweep in the interpreter crate parses every PHP file under the roots given by the sweep-roots variable and filters through php -n -l, giving a table by construct (Symfony: 110 of 1543 files, 18 groups) and a reducer corpus that gates the fixes by group instead of by ten-minute rebuild. Fixing: kage_context before the brief and as the agent's first instruction; kage_risk on the touched files before the commit (co-change partners are the twins to check, x86_64 against aarch64, sprintf against printf); failing-name sets compared against a pristine tree (git archive of HEAD with its own target directory, deleted afterwards) with the known pre-existing reds listed; commits by path without trailers; kage_learn of the mechanism with the reducer values as evidence; one échelon stops at the second different mechanism after its fix, characterised with the verbatim message, the named site and a reducer. Perf gates when touching the compiler: compare the emitted .s file (not stdout), the linked binary, program stdout, nm on a --keep-symbols build and SORTED stderr (diagnostic order is nondeterministic), with bridge archives frozen through the per-bridge lib-dir variables because the compiler otherwise spawns cargo by itself mid-compile; test bin-only modules (linker, pipeline, runtime_cache) with --bins, never --lib. Laravel specifics: freeze the fixture (vendor committed, a fixed application key), take the php baseline and an xdebug trace, compile with the current compiler untouched, treat the feat/laravel-compilation branch as a source of reducers only, and run the parser sweep before the first request.
Evidence: Échelons 19-39 of the Symfony --web campaign, 2026-09-02 to 2026-09-05: commits 4c645c3838, 99f98db775, 283cd2fe4f, b5b322b264, 50cfc339de and the perf commits adc11fa115..a6bbed59b8, each with its reducer and both HTTP verdicts recorded in the agents' reports; the sweep of 2026-09-05 17:45 (110/1543 refused, php -l accepting all 110); the lldb recipe of échelon 35 (four identical captures); the memory-pressure and archive-rebuild findings of the perf executor.
