# php_rel_cmp chosen before constant folding can reach the backend with two static ints

> php rel cmp is selected while lowering the expression from the operand types at that moment. A class constant whose i…

`php_rel_cmp` is selected while lowering the expression from the operand types at that moment. A class constant whose initializer is a NESTED expression (`const MAX = 16 * 1024 * 1024;`, two multiplications are required; a single level folds earlier) lowers as a runtime-tagged value, so `strlen($buffer) > self::MAX` picks the runtime relational opcode; constant folding then rewrites that operand to `const_i64 16777216`, and the instruction reaching the backend has two statically `Int` operands and no runtime tag to dispatch on. The backend called that an invalid module and aborted the WHOLE compile (Symfony `FileInputHelper::readWithPasteDetection`). Fix (commit 5766393b6c, `src/codegen/lower_inst/comparisons.rs` `lower_int_compare`): two statically integer operands take the ordinary signed integer predicate, PHP's rule for int against int. The fast path is deliberately NOT extended to other static shapes: PHP compares `true > 24` as booleans, `"10" > "9"` numerically, and answers false for every NaN predicate; those still box into Mixed cells and use the comparison table.
Evidence: Reduced 12-line program (`$buffer .= fread($s, 8192)` in `while (true)`, then `strlen($buffer) > self::MAX` with a two-level constant initializer) refused with `EIR backend error: php_rel_cmp requires a runtime-tagged operand, got Int and Int`; after the fix it prints what `php -n` prints; ELEPHC_BACKEND_INVENTORY=1 on the stock Symfony fixture went from 5 refusing bodies to 4.
Verified by: commit 5766393b6c; value tests in tests/codegen/operators.rs; php -n oracle
