# array_merge's element gate unifies two object element types instead of demanding identity

> array merge 's element type gate in src/codegen/lower inst/builtins/arrays/helper validation.rs demanded IDENTICAL el…

`array_merge`'s element-type gate in `src/codegen/lower_inst/builtins/arrays/helper_validation.rs` demanded IDENTICAL element types on both operands. All that type decides is which runtime helper copies the slots and which `value_type` byte is stamped in the result header, and every object slot is one refcounted pointer stamped `object` whatever class it names, so `Object("")` against `Object("Foo")` produces byte-for-byte the same code and was refused anyway. `array_merge([$this], $this->getAllPrevious())` is exactly that pair (the literal types its element as the unspecified object `$this` is; the accessor's declared `array` return names the class); `FlattenException::toArray()` and `getAsString()` are written that way and each refusal aborted the whole Symfony compile. Fix (commit 2c662c5e0c): `Object(_)` x `Object(_)` unify to the unspecified-class object. No other pair is widened: a class name is the only element distinction this gate can discard without changing the emitted slots. Note for future work: a `?Node $previous` chain leaves a heap residual at exit that is NOT caused by array_merge (removing the call leaves the identical residual).
Evidence: Backend inventory on the stock Symfony fixture listed two `array_merge` refusals at FlattenException.php:118 and :422 with element types Object("") vs Object(FlattenException); after the fix both bodies lower and the reduced programs print what php -n prints.
Verified by: commit 2c662c5e0c; value tests in tests/codegen/arrays/indexed/search_merge_union.rs; php -n oracle
