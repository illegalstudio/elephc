# A user-defined __toString() that throws is NOT catchable when invoked implicitly through `

> A user defined toString that throws is NOT catchable when invoked implicitly through echo $obj; or an explicit string…

A user-defined __toString() that throws is NOT catchable when invoked implicitly through `echo $obj;` or an explicit `(string)$obj` cast: the exception escapes as an uncaught fatal instead of propagating through an enclosing try/catch. Calling `$obj->__toString()` directly throws and IS caught normally by try/catch — only the implicit echo/cast-to-string coercion path has this gap. This is a general, pre-existing bug (not scoped to any one class), discovered while adding Reflector-interface __toString() throw bodies to the Reflection* shells (moonlit reflection-expansion session). Repro: `class A implements Stringable { function __toString(): string { throw new \Error('x'); } } try { echo new A(); } catch (\Error $e) { echo 'caught'; }` prints nothing and exits with an uncaught-exception fatal instead of printing 'caught'. Root cause not yet investigated — likely the implicit string-coercion codegen path (echo/cast-to-string) doesn't route through the normal call-with-exception-unwind machinery the way an explicit method call does. Documented as a known incompatibility in docs/php/types.md.
Evidence: Reproduced directly: echo $a; and (string)$a; both produced 'Fatal error: uncaught exception' bypassing an enclosing try/catch(\Error), while $a->__toString(); inside the same try/catch printed 'caught' as expected. Confirmed unrelated to Reflection (reproduces on a plain user class implementing Stringable).
