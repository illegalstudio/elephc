# A callback is validated at registration and matched by value, not at first use and by identity

> spl autoload register accepted any callback and discovered the problem at the first autoload. PHP refuses AT REGISTRA…

`spl_autoload_register()` accepted any callback and discovered the problem at the first autoload. PHP refuses AT REGISTRATION and names what is wrong: `TypeError: spl_autoload_register(): Argument #1 ($callback) must be a valid callback or null, class "NotYetDeclared" not found`, plus four more wordings for a missing function, a missing method, a private method and an instance method called statically. Deferring the check moves the failure to a line the program never wrote, and hides it completely for a program that happens never to autoload anything.

The whole validation matrix `call_user_func()` already uses is reusable as-is: measured with `php -n` 8.5.6, the REASON is byte-identical and only the prefix differs, because this parameter accepts null. `spl_autoload_unregister()` takes the same contract with the non-nullable prefix, because PHP distinguishes "not a callback" (a TypeError) from "not registered" (`false`).

Two defects sat underneath. First, that matrix accepted a static-method callback naming a class that DOES NOT EXIST -- an escape returning Ok for an unknown class. PHP words that refusal differently from a missing method: `class "X" not found` with the name quoted, against `class X does not have a method "m"` with the method quoted. The class now gets one autoload attempt, as PHP gives it, and is refused by name if nothing produces it. Second, autoload callbacks were matched by CELL IDENTITY, while PHP matches by value: the same `'name'` written at registration and unregistration is two cells and one callback, so unregistration answered false for a callback plainly registered and the same loader could register twice.

The test that covered this area was pinning the first defect: it registered `"missing_loader"` and asserted that it SUCCEEDED.
Evidence: php -n 8.5.6: registering 'NotYetDeclared::m', 'not_a_function', 'Reg::hidden' and 'Reg::inst' throws TypeError with those four reasons at the registration call; spl_autoload_unregister('not_a_function') throws with the prefix that has no `or null`; registering 'a_loader' twice reports success and leaves count(spl_autoload_functions()) === 1; spl_autoload_unregister('a_loader') then reports true and leaves 0.
Verified by: Commit 316f8257ad. Three tests measured against php -n 8.5.6. cargo test -p elephc-magician --lib with NO skips: 1339 passed / 14 failed, down from 15.
