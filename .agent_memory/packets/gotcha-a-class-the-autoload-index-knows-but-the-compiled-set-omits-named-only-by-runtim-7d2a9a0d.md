# A class the autoload index knows but the compiled set omits (named only by runtime strings) gets a TRUTHY reflector with an EMPTY member table: method_exists/ReflectionClass answer "no method" instead of loading the class like `new $cls` does

> OPEN, localized on 2026 09 04 échelon 29/30 of the Symfony web campaign . After the secrets.local vault root cause wa…

OPEN, localized on 2026-09-04 (échelon 29/30 of the Symfony --web campaign). After the secrets.local_vault root cause was fixed and confirmed (configurator ladder 6 → 222 of 632 reaching refcount 1), the cold container build dies with `RuntimeException: Invalid service "router.default": method "Symfony\Bundle\FrameworkBundle\Routing\Router::setConfigCacheFactory()" does not exist` (method on the parent `Symfony\Component\Routing\Router`). `strings` on the 119 MB --web binary finds neither Router class (0 occurrences of the FrameworkBundle one and of `setConfigCacheFactory`; the component one appears once as a bare string): Symfony names these classes ONLY as runtime strings in its configuration, so nothing reaches them statically and they are not in the compiled program — yet the runtime hands Symfony a truthy reflector whose member table is empty, while a genuinely unknown class throws `ReflectionException` exactly like php. PHP's rule is that a class-name string is autoloaded at the moment it is needed, identically for `new`, static calls, `class_exists(..., true)`, `method_exists` and reflection. Two acceptable generic shapes: (A) the compiled set includes every class the autoload index knows (the reachability hazards already claim to retain everything on an unresolvable include — verify what retention means for emission and checking), with a LOUD diagnostic for any index file that fails to parse or type-check instead of a silent drop; (B) reflection/method_exists/class_exists on a class absent from the compiled set defers to the interpreter (magician) exactly as `new $cls` does, so the runtime never answers from an empty member table. Related: the parse failure of `vendor/symfony/routing/Router.php` was itself silent (fixed by 369c234027 for the parser; the silence is not fixed), and now that it parses the checker rejects it with 6 errors that would drop it again silently. `ReflectionMethod::getName()` also returns the lowercased name.
Evidence: Server stdout verbatim after the rebuild from 369c234027; `strings` counts on examples/symfony-app/public/index; probe showing ReflectionException for an unknown class vs an empty reflector for an index-known uncompiled class (agent report 2026-09-04).
Verified by: Symfony --web rebuild + curl; strings; reflection probes vs php -n
