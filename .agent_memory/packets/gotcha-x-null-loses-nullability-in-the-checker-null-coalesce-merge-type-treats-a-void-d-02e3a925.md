# `$x ?? null` loses nullability in the checker (null_coalesce_merge_type treats a Void default as "value type"), and `include "literal.php"` of a runtime-created file is a silent no-op

> Two located, unfixed divergences 2026 09 03 , both with reproducers. 1 null coalesce merge type in src/types/checker/…

Two located, unfixed divergences (2026-09-03), both with reproducers. (1) `null_coalesce_merge_type` in `src/types/checker/inference/syntactic.rs` (~:178) returns the VALUE type when the default operand is `Void` (a `null` literal), so `self::MAGIC[$method] ?? null` on a MISSING key is typed `string`, materializes `""`, and `null !== ($x ??= self::MAGIC[$m] ?? null)` folds to true: php prints `none(NULL)`, elephc `type=` (probe `coalesce_assign_in_cond.php` from the assignment-in-condition corpus). Executed by the Symfony request in `DebugClassLoader::checkAnnotations` (:636) and `EnvVarProcessor::getEnv` (:173). A correct fix makes every `?? null` nullable, so it needs wide filter measurement (`coalesce`, `nullable`, `error_tests`, `types`, `arrays`). (2) `file_put_contents("p.php", '<?php echo "INCLUDED"; $x = 9;'); $x = 1; include "p.php";` prints `INCLUDED;x=9` under php and `;x=1` under elephc: a LITERAL include path is resolved at compile time and, when the file does not exist yet, the include silently disappears; a variable path (`__DIR__ . "/p.php"`) goes through the runtime include and works. PHP semantics are a runtime include with a warning when missing, never a silent skip. Practical consequence: eval-bridge tests that create the included file at runtime must use a computed path or they pass vacuously. Also noted in the same pass: a module linking the eval bridge without any `callable` AOT parameter or `NormalizeCallable` op references `__elephc_eval_dynamic_callable_entry`/`_invoker` without defining them (`ld: symbol(s) not found`) because the emission ladder gates on `required_runtime_features.eval_bridge` (`src/codegen/lower_inst/callables.rs` ~:499) while the definition gates on the narrower `module_needs_eval_callable_descriptor_support`; `var_dump` of an AOT object from inside the interpreter prints `object(Foo)#<raw pointer> (0) {}`; `unset($obj->arr[0])` from interpreted code does not shrink the array; `gettype()` of a closed resource answers `resource` where php answers `resource (closed)`.
Evidence: Standalone reproducers diffed against php -n by the agent on 2026-09-03; the ?? null case matches the frozen .expected of the reconnaissance probe corpus; the include case was found when a first draft of eval-bridge tests passed vacuously.
Verified by: php -n vs ./target/debug/elephc on the reproducers (agent report)
