# Eval class METADATA is process-global but static property VALUES are per-context, so a class declared by one context reads its defaulted statics as uninitialized in another

FIXED for the default case; the wider divergence is still OPEN and documented here.

THE ASYMMETRY. `define_class` publishes to a process-global registry and `sync_global_eval_classes` (`context/classes_aliases.rs:55`) imports class, interface, trait and enum DECLARATIONS into any other eval context that needs them. Static property VALUES live in `ElephcEvalContext::static_properties`, a per-context `HashMap<(String, String), RuntimeCellHandle>`, and nothing syncs them. `initialize_eval_static_properties` seeds declaration defaults once, in the context that ran the declaration.

THE SYMPTOM. Any other context finds the declaration through `class_property`, finds no cell, and -- because the property is TYPED -- reports `Typed static property X::$y must not be accessed before initialization` for a property that plainly has `= []` in the source. Symfony: `LinkStub` is declared by the autoloader's context and `getComposerRoot()` runs in another, so `self::$vendorRoots = []` (a WRITE, which creates the entry in the reading context) worked and `self::$composerRoots` (a DEFAULT, seeded only in the declaring context) threw.

HOW IT WAS PROVEN, because five reducers all passed and none of them reproduced it: two opt-in traces, `phase=static_property_seed` in `initialize_eval_static_properties` and `phase=static_property_uninitialized` at the throw. They showed the SAME class name seeding `composerRoots` successfully at trace line 3850 and the SAME class name reporting `statics=["vendorRoots:stored", "composerRoots=default:absent"]` at line 5257. Nothing removes entries from `static_properties`, so the only reading left is two different maps -- i.e. two contexts. No reducer reproduces it because a single-file reducer only ever has one context.

THE FIX: `eval_static_property_value_or_default` in `static_property_access.rs` materializes the declaration default on first access in whatever context asks, used by both the read and the `isset` path. A declaration default is a constant expression, so the value is what the declaring context stored, just computed later.

STILL OPEN: a value one context has WRITTEN is still invisible to the other. Two contexts running `self::$counter++` keep two counters. The real fix is process-global static storage, which needs cell ownership to cross contexts.
Evidence: Trace from the Symfony --web request: `phase=static_property_seed class="Symfony\\Component\\VarDumper\\Caster\\LinkStub" property="composerRoots" has_default=true seeded=true` at line 3850, then `phase=static_property_uninitialized ... statics=["vendorRoots:stored", "composerRoots=default:absent"]` at line 5257. After the fix the request advances past LinkStub into HttpKernel::filterResponse.
Verified by: The Symfony --web request; scratchpad/red15 gen.php/gen2.php/gen3.php/gen4.php all pass both before and after, which is itself the evidence that a single-context reducer cannot reproduce this.

## Verification

Trace from the Symfony --web request: `phase=static_property_seed class="Symfony\\Component\\VarDumper\\Caster\\LinkStub" property="composerRoots" has_default=true seeded=true` at line 3850, then `phase=static_property_uninitialized ... statics=["vendorRoots:stored", "composerRoots=default:absent"]` at line 5257. After the fix the request advances past LinkStub into HttpKernel::filterResponse.
