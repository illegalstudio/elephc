# Calling a closure through a captured callable variable in a loop leaks ~4 heap blocks per

> Calling a closure through a captured callable variable in a loop leaks ~4 heap blocks per call, independent of argume…

Calling a closure through a captured callable variable in a loop leaks ~4 heap blocks per call, independent of argument count/extra-arg support. Repro: `$cb = function ($i) { return "got:" . $i; }; for ($k=0;$k<50;$k++) { echo $cb("A"), "\n"; }` compiled with --heap-debug shows allocs=500 frees=300 live_blocks=200 (4/iteration). The EXACT same loop calling a plain top-level function instead (`function cb($i) {...} ... echo cb("A"), "\n";`) is perfectly clean (0 leaks). This isolates the leak to the `StaticCallableBinding::Closure` direct-call specialization path in `lower_static_callable_call` (src/ir_lower/expr/mod.rs) or its surrounding call-result/concat handling — NOT to argument count (verified identical leak count with 0 args, 1 literal extra arg, and 1 freshly-concatenated extra arg, ruling out any relationship to caller-side argument release). Pre-existing, confirmed independent of the H1 gradual-typing campaign (reproduces via code paths untouched by that work — the release-surplus-operands helper added for H1 PART A is a no-op for equal-arity calls and was proven not to worsen or fix this number). Worth investigating: something in the closure-call return path or the loop-body concat's temp-string cleanup isn't fully balanced when routed through the direct-closure-call ABI.
Evidence: Three isolated --heap-debug runs on branch reconcile/dirname-symfony HEAD 3a2bb667a+: closure-var call loop (0/1-literal/1-concat extra arg) all show live_blocks=200 for 50 iterations; the same loop via a direct top-level function call shows live_blocks=0 (clean).
Verified by: cargo run -- --heap-debug probe scripts, 3 isolated variants plus a direct-function-call control

## Verification

Three isolated --heap-debug runs on branch reconcile/dirname-symfony HEAD 3a2bb667a+: closure-var call loop (0/1-literal/1-concat extra arg) all show live_blocks=200 for 50 iterations; the same loop via a direct top-level function call shows live_blocks=0 (clean).
