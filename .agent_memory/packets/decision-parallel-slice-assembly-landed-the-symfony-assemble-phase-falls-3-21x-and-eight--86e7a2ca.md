# Parallel slice assembly landed: the Symfony assemble phase falls 3.21x and eight objects cost the linker nothing

> Commit 5da90f33d5 perf linker , based on 283cd2fe4f; src/linker/asm split.rs is NEW in that commit and only exists in…

Commit 5da90f33d5 (perf(linker), based on 283cd2fe4f; src/linker/asm_split.rs is NEW in that commit and only exists in a worktree that has it). `linker::assemble` was ONE single-threaded `as` over one ~861 MB `.s` and was 62.1 % of a release Symfony `--web` build. `linker::asm_split` now cuts the FINISHED assembly text into N contiguous slices (never bin-packed: an emitted `__data` record depends on the record beside it), assembles them concurrently, and hands the objects to the link line in slice order.

MEASURED, release compiler, paired A/B on ONE compiler minutes apart so only the split differs (this pairing is the method that matters — a before/after across two different tree states is worthless on this machine, whose load moved 10 to 22 between runs and shifted every unrelated phase by 20-30 %): assemble 173.94 s -> 54.22 s = 3.21x, total 280.14 s -> 162.50 s = 1.72x. The phases the split CANNOT touch agree within noise across the pair (prune 30.11/29.23, codegen 36.76/35.92, lower 10.06/10.53), which is what makes the pair trustworthy. Split note: 8 slices, 5831 temporaries promoted, 46843 locals published.

THE LINK DOES NOT PAY FOR THE EXTRA OBJECTS: 1.46 s at N=1 against 1.39 s at N=8. Do not assume more objects cost link time — measure it.

IDENTITY, all byte-for-byte with frozen bridge archives: at ELEPHC_ASM_JOBS=1 the assembly, the LINKED BINARY, stdout, stderr and `nm -n` all reproduce the unpatched compiler exactly. At N=8 vs N=1: behaviour identical, `Section __text` 8,277,024 B and `Section __data` 1,114,040 B in both, 315 nm additions ALL prefixed `_elephc_xslice_`, zero losses. That __text equality is also the proof that eight `-dead_strip` atoms collect what one atom did — the patch header's own stated worry, answered by measurement rather than argument.

Tests: `--bins linker::` 49/49. NOTE `cargo test -p elephc --lib` does NOT compile one line of this code — `mod linker` and `mod pipeline` are declared in src/main.rs only, so `--lib` reports "0 passed; N filtered out" and passes the patch vacuously. Use `--bins` for anything under src/linker, src/pipeline, src/cli, src/link_plan.
Evidence: Release compiler, frozen bridge archives (ELEPHC_*_LIB_DIR), Symfony --web --timings --keep-symbols --heap-size=1073741824. N=1 vs N=8 paired run phase tables; cmp exit 0 on .s, binary, stdout, stderr and nm for the ELEPHC_ASM_JOBS=1 identity gate against a HEAD reference built in the same worktree; nm diff showing 315 additions all _elephc_xslice_-prefixed and 0 losses; size -m showing equal __text and __data.
Verified by: cargo test -j 2 -p elephc --bins linker:: (49/49 pass, 0 warnings); crate-wide --bins 1838 passed/19 failed and --lib 1636 passed/19 failed, both failing sets exactly the 19 pre-existing reds at this base
