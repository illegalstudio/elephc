# An array filled from a retyped local is boxed, and the checker must tell its callers (a narrowed type is not a representation)

> Seventh root cause of the local retype campaign commit ab1c5436e5 . $out = ; $e = $this; while $e = $e getP { $out = …

Seventh root cause of the local-retype campaign (commit ab1c5436e5). `$out = []; $e = $this; while ($e = $e->getP()) { $out[] = $e; } return $out;` (verbatim `FlattenException::getAllPrevious()`): the loop header retypes `$e` from `N` to `N|null`, which boxes its frame slot into a Mixed cell; the checker then flow-narrows `$e` back to `N` for the body, which is RIGHT as a PHP type (still reports `$e->noSuchMethod()`) and WRONG as a REPRESENTATION (the slot holds a cell). Typing the pushed element from the narrowed view made EIR lowering run `__rt_array_to_mixed` on `$out`, so the callee returned `array<mixed>` (`--emit-ir`: `return v14: Heap(Array) php=array<mixed>`) while every call site was compiled against `array<N>`. The invariant is stated in `src/types/array_storage.rs`: checker and lowering MUST agree on when an array's representation changes. Fix: `Checker::stored_element_type` answers from the SLOT's representation (`codegen_repr`, not the type: `?int` retyping an `int` stays tagged-scalar) at the two statement forms storing into a local array (`check_array_push`, `check_array_assign`); it only ever widens, only to Mixed; `retyped_boxed_storage_locals` is set-or-CLEARED at the rebinding/widening arms (rebinding abandons the old slot so `$a = 1; $a = "s"; $a = 2;` ends raw), per body (`SavedLocalBindingScope`). NOT applied to the acceptance checks (string-offset, `buffer<T>`, `ArrayAccess`) which judge a value against a declared element type. LEVEL CHOSEN BY MEASUREMENT: 22 readers of the returned array vs `php -n` on the tree with the previous agent's per-reader `foreach` stamp dispatch (`src/codegen/lower_inst/iterators.rs`) in place: 14 right, 7 SILENTLY WRONG (by-ref foreach, array_pop, array_shift, array_map, array_filter, `array_merge([$this], $r)` = `FlattenException::toArray()`, append-then-read: six printed EMPTY labels, array_filter answered 2 for 1), 1 refused (`in_array` object needle over boxed elements, refused identically by the honest `array<mixed>` control). Control corpus (same 22 readers over an honestly-typed `array<mixed>`): 21 identical + same refusal, proving the Mixed-element path is fully supported so honesty costs no coverage. After the fix: 21/21 identical. The per-reader dispatch was DROPPED after measuring that no shape still exercises it (array_values over a hash of objects, in-place widening at a mixed argument boundary, array literal from a narrowed retyped local all answer identically without it). Lesson: a crash fixed per reader hides a whole class of silent wrongs; fix the representation at the boundary that produces it. Not covered: values passed as call arguments or stored into properties (own coercion), `in_array` with an object needle over boxed elements (still refused).
