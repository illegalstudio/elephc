# A first-class-callable descriptor invoked from interpreted code needs the native-throw boundary; the shared builtin/extern descriptors must NOT have it

> FIXED. Every %env default:... % resolution in the Symfony web request died with Fatal error: Uncaught EnvNotFoundExce…

FIXED. Every `%env(default:...)%` resolution in the Symfony `--web` request died with `Fatal error: Uncaught EnvNotFoundException: Environment variable not found: "APP_RUNTIME_ENV"` (and, once that name was supplied, `SYMFONY_TRUSTED_HOSTS`, and so on -- one mechanism, every variable).

THE MECHANISM. The generated container calls `$container->getEnv('string:default:kernel.environment:APP_RUNTIME_ENV')`, which unwraps to `EnvVarProcessor::getEnv`, whose `default:` branch is `try { $env = $getEnv($next); } catch (EnvNotFoundException) { }` -- and `$getEnv` is the FIRST-CLASS CALLABLE `$container->getEnv(...)`, created in AOT code and called by the interpreter through the descriptor's invoker. That invoker was emitted by `emit_runtime_callable_invoker_inline` with `catch_native_throws = false`, so a Throwable raised inside reached `__rt_throw_current` and unwound NATIVELY past the interpreted `try`, which never got to look at it. The bounded sibling `emit_runtime_callable_invoker_with_exception_boundary` (a `setjmp` boundary that returns the throw as a status) already existed; only the eval function-registration path used it.

THE FIX, and the partition is the whole point. `emit_runtime_callable_invoker_inline_with_boundary(..., catch_native_throws)` in src/codegen/lower_inst/runtime_wrappers.rs, with `true` passed ONLY from the first-class-callable sites: all four invokers in src/codegen/lower_inst/callable_descriptors.rs plus the instance-method first-class callable in src/codegen/lower_inst/callables.rs (the `emit_instance_method_descriptor_entry_wrapper` site). The shared builtin/extern descriptors in callables.rs stay UNBOUNDED.

WHY NOT JUST BOUND THEM ALL. That was tried first and it regresses
`codegen::runtime_reachability::test_shared_mixed_callable_dispatch_preserves_results_and_exceptions`
(left "not-reached|7|12|9|24|8|9:10|11" vs right "caught:boom:3|7|12|9|24|8|9:10|11"): the boundary turns the native throw into a returned status for EVERY caller, and AOT dispatch needs it to keep propagating natively, so a callable that throws stopped reaching its PHP `catch`. Bounding ONLY the instance-method site in callables.rs is the opposite error -- it keeps the tests green but does NOT fix Symfony, because the descriptors that matter are the ones in callable_descriptors.rs. Both halves were measured.

CACHE NOTE. `ctx.shared.runtime_callable_invoker(sig, captures)` caches one label per (sig, captures), which is not enough once the same signature can be emitted both bounded and unbounded. The bounded form takes a fresh label and does not read or write that cache.

WHAT IT UNBLOCKS, and what is next. With the fix the EnvNotFoundException family is gone entirely and the request advances several echelons to a new, unrelated blocker: three `filter_var(): array $options passed through a mixed value is not supported by elephc yet; flags ignored` warnings, then SIGSEGV (`worker terminated by signal 11`). That segfault is the next thing to chase; the `filter_var` limitation is a known unimplemented surface and may or may not be related to it.
Evidence: Compile-and-curl of examples/symfony-app (`--web --timings --keep-symbols --heap-size=1073741824`, exit 0, 74 s) across four states: (1) unbounded baseline -> `Uncaught EnvNotFoundException ... "APP_RUNTIME_ENV"`, worker exit 255; (2) ALL invoker sites bounded -> fatal gone, advances to the filter_var warnings and SIGSEGV, but `cargo test --test codegen_tests exception` drops from 145/2 to 144/3 with test_shared_mixed_callable_dispatch_preserves_results_and_exceptions as the new red; (3) only callables.rs:1655 bounded -> tests back to 145/2 but the EnvNotFoundException fatal RETURNS; (4) all four callable_descriptors.rs sites plus callables.rs:1655 bounded -> fatal gone AND `RUST_MIN_STACK=33554432 cargo test --test codegen_tests exception -- --test-threads=4` = 145 passed / 2 failed, the same two pre-existing reds that reproduce on an untouched tree. test_shared_mixed_callable_dispatch_preserves_results_and_exceptions ok; test_runtime_included_code_constructs_an_aot_class_inheriting_a_builtin_throwable_constructor ok. Oracle: `php -n` 8.5.10 on the same app returns HTTP 404, 39,315 bytes, containing "Welcome to Symfony!".
Verified by: Four compile-and-curl states of the Symfony --web fixture plus cargo test --test codegen_tests exception at each, with the two pre-existing reds confirmed against a pristine tree
