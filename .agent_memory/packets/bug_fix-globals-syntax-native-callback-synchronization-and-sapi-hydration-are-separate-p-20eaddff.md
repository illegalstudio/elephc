# GLOBALS syntax, native callback synchronization and SAPI hydration are separate parity gates

> GLOBALS element accesses must address the context global symbol scope, not create a local array or shadow a same name…

GLOBALS element accesses must address the context global symbol scope, not create a local array or shadow a same-named local. The interpreter now routes direct reads, writes, nested writable locations, quiet checks and direct unset through that scope. This does not close native callback synchronization: explicit eval imports and exports globals, but later eval-backed callable invokers omit that barrier. The global-keyword control still exposes stale scalar native storage even when an array mutation is visible. Hydration is a third gate: CLI seeding currently produces empty ENV rather than importing the configured process environment, and GLOBALS argv/argc aliases expect Mixed while process startup stores raw argv-array/argc representations. Preserve PHP lazy auto-global rules; a GLOBALS-only ENV lookup is not equivalent to directly mentioning ENV. Whole-array views, references, byte-name coverage and error-path ownership remain open, not certified by these focused tests.
Evidence: Three globals_array unit regressions pass; 36 control_flow and seven null_coalesce_assign tests pass. Native explicit eval scalar set/unset returns 7:absent. Native callback global-keyword control still returns 0:seen:0 instead of 1:seen:2. PHP 8.5.6 direct ENV probe sees the supplied fixture sentinel; Elephc sees missing. PHP argv alias probe returns 3:3 for two arguments, while Elephc reports count with true given. Frozen php-src php_variables.c and php_cli.c confirm distinct SAPI initialization and auto-global activation rules.
Verified by: Native focused regressions, Magician unit tests, PHP 8.5.6 probes and bounded read-only Luna audit challenged against the control test.
