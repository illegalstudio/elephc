# array_unique over boxed elements compares string renderings, not cell addresses

> A BOXED Mixed array element's slot holds a CELL POINTER, so rt array to hash unique 's raw word duplicate scan compar…

A BOXED (`Mixed`) array element's slot holds a CELL POINTER, so `__rt_array_to_hash_unique`'s raw-word duplicate scan compared cell ADDRESSES: two separately boxed `1`s never matched. The lowering refused the call rather than answer wrongly, and that refusal aborted the Symfony compile at `Command::__construct` (`array_unique([...$this->aliases, ...$aliases])`, a spread whose element type is boxed). Fix (commit 549a7798bf, `src/codegen_support/runtime/arrays/array_to_hash_unique.rs`, both arches): the helper recognizes the boxed value_type next to the string one and compares such slots through a new `__rt_mixed_string_eq` (`__rt_mixed_cast_string` on each cell, then `__rt_str_eq`) which is PHP's own SORT_STRING default; `[0, false, null, "0", ""]` proves it is a string-rendering comparison (PHP keeps 0 AND false) and not loose `==`. Ownership contract of `__rt_mixed_cast_string`: a string payload comes back as a fresh heap copy the caller owns, every other scalar tag borrows the shared concat scratch; both go to `__rt_heap_free` (ignores non-live blocks) and the concat cursor is restored to its entry value, otherwise an n-element array_unique burns 21 bytes of scratch per rendering across its O(n^2) scan. GAP still open: `array_diff` and `array_intersect` still REFUSE boxed elements (different helpers, not covered).
Evidence: `array_unique([1,"b",1,4])` on boxed elements answered `1,b,1,4` before (address comparison) and `1,b,4` after, identical to php -n; the `[0, false, null, "0", ""]` fixture keeps 0 and false as php does; --heap-debug clean.
Verified by: commit 549a7798bf; value tests in tests/codegen/arrays/indexed/set_ops.rs; php -n oracle

## Verification

`array_unique([1,"b",1,4])` on boxed elements answered `1,b,1,4` before (address comparison) and `1,b,4` after, identical to php -n; the `[0, false, null, "0", ""]` fixture keeps 0 and false as php does; --heap-debug clean.
