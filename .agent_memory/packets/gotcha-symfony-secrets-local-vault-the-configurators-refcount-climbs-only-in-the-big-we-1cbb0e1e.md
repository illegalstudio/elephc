# Symfony secrets.local_vault: the configurator's refcount climbs only in the big --web build (set 2 / args 4 / tag 6 vs 1 / 2 / 2), and the excess comes from the AOT body of ServiceConfigurator::args where static::processValue() expands into a large late-bound ladder

> OPEN localized, not fixed, 2026 09 03 . The cold path fatal ServiceNotFoundException "secrets.local vault" is the sym…

OPEN (localized, not fixed, 2026-09-03). The cold-path fatal `ServiceNotFoundException "secrets.local_vault"` is the symptom of "the last `->set()` of a configurator chain never registers": `AbstractServiceConfigurator::set()` calls the previous configurator's `__destruct()` explicitly, so only the TRAILING `ServiceConfigurator` of `vendor/symfony/framework-bundle/Resources/config/secrets.php` depends on refcount-driven destruction, and `ServiceConfigurator::__destruct()` is what calls `setDefinition`. Decisive A/B on the identical `secrets.php` through the identical real `PhpFileLoader` (runtime include, interpreted by the eval bridge calling the AOT methods): refcount of the configurator object after `set`/`args`/`tag` is 1/2/2 in a small AOT probe build (all 4 ids registered) and 2/4/6 in the `--web` kernel build (final release leaves 2 refs, never destructed, id missing). Same PHP, same dispatch owners; the difference is BUILD-dependent, not shape-dependent. Disassembly of the shipped binary shows the eval-bridge slot for `ServiceConfigurator::args` is balanced (`__rt_mixed_from_value` then `__rt_decref_object`), so the extra references come from the AOT METHOD BODY of `args` in the big build: 3,452 bytes there versus ~100 in the small build, because `static::processValue($arguments, true)` (a late-bound static call on `AbstractConfigurator`) expands into a large multi-candidate dispatch ladder when many subclasses are reachable, and into a direct call otherwise. Working hypothesis for the fix: the late-bound ladder retains its receiver/class context or arguments per probe and releases only on the taken path (or boxes `$this` for the dispatch without releasing the box), leaking +1/+2 per call. The `--web` build cannot `--emit-ir`; `--emit-asm --web` needs ~1 GB transient disk. Three destructor-timing fixes that landed the same day (76a771f80b, 8b7878aafe, 8600e6af6b, 4d96033129) were real but did not change this verdict.
Evidence: A/B refcount table from the eval release trace on the same secrets.php under both builds; nm/disassembly of examples/symfony-app/public/index (--keep-symbols) for the args slot and method body sizes; four rebuild+curl verdicts unchanged.
Verified by: agent report 2026-09-03 (Opus), eval release trace and disassembly

## Verification

A/B refcount table from the eval release trace on the same secrets.php under both builds; nm/disassembly of examples/symfony-app/public/index (--keep-symbols) for the args slot and method body sizes; four rebuild+curl verdicts unchanged.
